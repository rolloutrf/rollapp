# Компоненты shadcn — проверка 9 сентября 2026

Проверены все 34 файла в src/components/ui и все 29 JSX-файлов приложения за пределами этой папки. Основа — настроенный Base Nova, официальные registry-исходники, [Select](https://ui.shadcn.com/docs/components/base/select), [Native Select](https://ui.shadcn.com/docs/components/base/native-select), [Dialog](https://ui.shadcn.com/docs/components/base/dialog) и [Accordion](https://ui.shadcn.com/docs/components/base/accordion).

## Причина замечания

Направление контакта использовало официальный NativeSelect. Его список рисует операционная система, поэтому меню выглядело иначе. Прежняя проверка разрешала этот компонент и проверяла запрет нативных контролов главным образом в App.jsx. Наличие shadcn-импорта само по себе не обеспечивало одинаковый вид всех меню.

Для Rollapp принято единое правило: выбор из списка использует Select. NativeSelect остался среди установленных upstream-файлов, но нигде не импортируется в приложение; аудит запрещает его повторное использование, включая импорт под другим именем.

## Исправления

| Область | Результат |
| --- | --- |
| Направление контакта | Select → Trigger/Value → Content/Item, явная связь FieldLabel с полем; сохранены «Без направления» и пользовательские категории |
| Поля редактора контакта | Общие Field/FieldLabel/Input/Textarea вместо отдельной композиции подписей |
| Карточка контакта | Кнопка закрытия вынесена в отдельную панель, содержимое прокручивается ниже неё |
| Исходный текст CV | Accordion вместо details/summary; сохранено начальное раскрытие CV без структурированных данных |
| Группа желаний | FullscreenDialog на основе shadcn Dialog вместо section с вручную заданным role=dialog |
| Редактирование желания | FullscreenDialog с управлением фокусом, закрытием и вложенными окнами; создание по-прежнему использует Drawer |
| Escape | Удалены обработчики document/window, которые могли закрывать редактор одновременно с его меню |
| Действия редактора | Footer находится в потоке, форма прокручивается отдельно, кнопки не перекрывают поля |
| Фото желания на мобильном | Подпись компактной кнопки скрывается через sr-only вместо font-size: 0, который конфликтовал с размером Large |
| Состояния фокуса | Восстановлены актуальные registry-классы FieldLabel, Checkbox, RadioGroupItem и Switch для вложенных полей |

| Окна и меню | dialog, alert-dialog, drawer, sheet, dropdown-menu, popover, tooltip |
| Содержимое и контейнеры | accordion, alert, avatar, badge, card, empty, scroll-area, separator, sidebar, skeleton, sonner, spinner |

Сверены происхождение, слоты и классы всех примитивов с Base Nova. Продуктовый размер Large (48 px) и общий Geist остаются в слое Rollapp. Сохранены функциональные расширения: pill-вариант Button, семантические заголовки и отдельное действие Accordion, компоновка ScrollArea, позиционирование портальных меню. Эти компоненты используют исходные механизмы Base UI; новые самодельные механизмы модальности и выбора не добавлены.

Допустимые нативные элементы: два невидимых file input, обслуживаемых видимыми shadcn-кнопками, и неизменяемые маркеры задач в Markdown согласно Typeset. Системный выбор файла, ввод дат/времени через официальный Input и семантические HTML-элементы документов сохраняются.

## Проверки

- npm run test:ui проходит и сканирует все JSX-композиции, включая отдельные редакторы и страницы. Добавлены запреты NativeSelect, сырых интерактивных тегов и вручную заданных ролей диалога/меню.
- Сборка npm run build и целевые тесты проходят; остаётся прежнее предупреждение о размере JS-бандла.
- Четыре регрессии проверяют импорт NativeSelect под псевдонимом, нативное раскрытие, условный role=dialog и узкие исключения для input.
- В существующем контакте проверены открытие, выбор, возврат к «Без направления», отмена и Escape; после Escape фокус возвращается в Trigger, редактор остаётся открыт. Меню на 320 и 1440 px помещается в окно, строки имеют высоту 48 px, длинный список прокручивается.
- После изменения панели закрытия контакт повторно проверен на 320×740 и 1440×900: область прокрутки начинается на 8 px ниже кнопки закрытия, горизонтального переполнения нет.
- Группа Wishlist и редактор проверены на существующих данных. Проверена цепочка группа → карточка → редактор → Select / создание списка / подтверждение удаления с отменой; закрытие возвращает фокус в предыдущий интерфейс.
- Геометрия редактора после прокрутки проверена на 320×740, 390×844, 768×1024, 1440×900 и 740×320. Нижняя граница содержимого совпадает с верхней границей Footer; закрытие и действия остаются в окне.
- Подтверждение удаления проверено и отменено на 740×320. Удаление не выполнялось.
- CV раскрывается и сворачивается через Accordion; проверено отсутствие горизонтального переполнения на 320 и 1440 px.
- В scripts/layout-checks.mjs добавлена проверка геометрии полноэкранного редактора: действия внутри viewport, отсутствие пересечения Footer и прокручиваемого содержимого. Для контактов проверяется отделение кнопки закрытия от области прокрутки.

Проверка использует авторизованную пользовательскую сессию и production-данные. Значения менялись только в несохранённом черновике контакта; формы, создание списков, загрузки и удаление не отправлялись. Проверка исходников не заменяет сквозные проверки всех бизнес-операций и внешних интеграций.
