# Импорт публичных вишлистов 19 ноября 2026

База проверки — `fe20732cf70fa675a6206a8dd3a9f7d92ffe7810`. Исходная
рабочая копия была чистой. Проверки выполнены с незакоммиченными изменениями
ветки `codex/public-wishlist-import`.

- `npm test` — 1091 тест пройден, 2 пропущены.
- `npm run test:profile-wishlists` — 9 размеров от 320 до 1920 px, включая
  390×400 и переход 767/768. После сохранения и при обновлении запросы к
  публичным источникам идут через API Rollapp. Проверено, что ошибка Ozon
  не останавливает другие источники, черновик сохраняется и повтор WB не
  добавляет дубли. Просмотрены снимки на 320 и 1440 px.
- `npm run test:ui`, `npm run test:controls`, `npm run test:form-actions` и
  `npm run build` прошли.
  Сборка сообщает о крупных чанках.
- `npm run check:comprehensive` остановился в `test:gifts` на 390×844.
  Сценарий не нашёл кнопку сертификата с нулевым остатком. Полная матрица
  в этом прогоне не завершилась.
- `npm audit` вернул 9 замечаний, `npm audit --omit=dev` — 2.
  В отчётах нет добавленных `parse5` и `entities`. Рабочие замечания относятся
  к `@ton/ton` и транзитивному `zod`, для которых аудит не предложил исправлений.

Публичный источник WB со скриншота прочитан серверным адаптером без
авторизации. Он вернул один товар. В первой проверке короткий код Ozon
был прочитан со строчной `l` вместо заглавной `I`, поэтому запрос попал на
главную. Правильный код перенаправляет на `/my/favorites/shared?list=…`.

Повторная проверка правильной ссылки в чистом Chrome без входа дошла до
HTTP 200. Ozon показал приглашение подписаться и ноль товарных ссылок.
Данные страницы содержали состояние `applyWishlist` для приглашения,
действие «Подписаться» перенаправило на `/ozonid/mobile/`. Попыток входа
и записи в Ozon не было. Для сравнения, отдельная публичная «Подборка»
Ozon в той же гостевой сессии показала товары. Живой импорт подарочного
вишлиста по ссылке без входа не подтверждён. В этой повторной проверке код
импорта не менялся, тестовые наборы и новый выпуск не запускались.
[Справка Ozon о доступе к вишлисту](https://docs.ozon.ru/common/tovary/izbrannye-tovary/)

Локальный preview работает с настроенным production PostgreSQL по прямому TLS,
режим `verify` подтвердил существующую схему. Анонимный вызов маршрута импорта
получил 401. Публичный профиль отрисовался без горизонтального переполнения
на 320 и 1440 px. Источники проверены без вставки карточек. Импорт в реальный
аккаунт не выполнялся. Для выпуска по запросу пользователя выбран
ручной режим `verification=none`.

Яндекс Диск уже экспортирует `users.wishlist_links` и карточки нужного
владельца из `wishes`. Дополнительных полей, связей, миграций, записей
данных автора и сведений о сборах WB в хранилище нет.

## Чтение открытого списка Ozon после входа

Кандидат проверен с незакоммиченными изменениями на базе
`951c29e5eafd9a4581703db8eb1f054e56ee8f7d`. Приложение принимает
товарные карточки через нативную вставку или через закладку, запущенную
на странице конкретного списка. Существующий защищённый маршрут импорта
сохраняет позиции приватно и сравнивает артикулы. Схема и состав резервного
копирования не меняются.

- `npm run build` и `git diff --check` прошли. Тестовые наборы не запускались.
- Chromium подтвердил сквозное копирование закладкой с двумя страницами
  товаров в контрольной разметке списка и исключение блока рекомендаций.
- Из открытой гостевой «Подборки» Ozon нативно скопирована реальная
  карточка. Вставка этой карточки в форму Rollapp дала один нормализованный
  элемент для API на 320, 390×400, 768, 820×450, 1024, 1440 и 1920 px.
  Проверены границы формы и просмотрены снимки на 320 и 1440 px.
- Вкладка пользователя с авторизованным списком недоступна для
  автоматизации в этой сессии. Вставка проверена на реальной карточке,
  чтение всех элементов именно этого списка и запись в настоящий аккаунт
  не проверялись. Куки, данные входа и целый снимок браузерной вкладки
  в Rollapp не передаются.
