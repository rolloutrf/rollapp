# 02 Идентификация

[Клиент](../../src/modules/identification/) · [Сервер](../../server/modules/identification/)

**В коде.** Сопоставление учётной записи со способом входа. Yandex ID подтверждается через OAuth, Telegram — через проверенные данные Mini App. Телефон подтверждается SMS-кодом. Телефон и Telegram можно привязать из настроек через `/api/me/phone/*` и `/api/me/telegram/link`. Это касается способов входа в продукт. Сфера с личными документами описана в [«Идентичности»](22-identity.md).

**Владение.** Храните уникальную связь способа входа с аккаунтом, статус подтверждения и правила конфликтов в серверном адаптере провайдера. Различайте назначение SMS-проверки для входа и привязки. Привязка принимает текущего пользователя из сессии. Потребителю передавайте подтверждённый идентификатор или безопасную сводку о привязке.

**Подключение.** Подключайте адаптер провайдера к авторизации и настройкам профиля через общую форму проверки с явно заданным назначением. Платежам отдавайте только сведения о подтверждённой привязке, необходимые для выбранного способа оплаты. Держите TTL, лимиты и повторное использование проверок внутри интеграции.

**Приёмка.** Покройте первое и повторное подтверждение, занятую привязку, просроченный код, несовпадение назначения и отключённый провайдер. Проверьте, что профиль и платёжный экран получают только опубликованный минимум. Используйте `npm test` и профильные проверки интеграций по [регламенту](../verification.md).
