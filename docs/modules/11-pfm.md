# 11 PFM

[Клиент](../../src/modules/pfm/) · [Сервер](../../server/modules/pfm/) · [Общий код](../../shared/modules/pfm/)

**В коде.** «Сводка по роллам» открывается из кошелька и из «Финансов» профиля.
Она показывает зачисления, списания и изменение доступного баланса за 7, 30
или 90 календарных дней, включая сегодня. Период начинается в 00:00 по
Москве. Пользователь может раскрыть операции отдельной группы или все
операции периода.

**Владение.** PFM владеет календарными периодами, группами, итогами и
фильтрованной выпиской. [Платежи](08-payments.md) публикуют сверяемый
реестр изменений кошелька. [История](10-history.md) публикует проекцию записи
и общий компонент списка. Сводка использует обычный кошелёк как единицу
учёта. Остатки карт, заложенные роллы и ожидаемые выплаты видны рядом
в кошельке. Полные журналы карт и заказов доступны в своих разделах.

**Правила.** Возврат учитывается в день поступления. Пополнение карты
показывается как движение в группу карт, списание в резерв — в группу
резервов. Персональный счёт и его возврат относятся к покупкам и продажам
по сохранившейся записи счёта и исходному переводу. Обычные переводы
остаются переводами. Stars и TON учитываются в сумме успешно зачисленных
роллов. Валюта внешних оплат видна в исходной операции. Десятичные
строки в ответе API сохраняют точность совокупных сумм.

**Подключение.** `GET /api/rolls/activity?days=30` возвращает период, серверный
момент отсечения и итоги. `GET /api/rolls/activity/entries` принимает тот же
`days` и `asOf`, при раскрытии группы — её ключ в `group`. Продолжение
использует пару `before` и `beforeId`, выданную сервером, с исходной
точностью PostgreSQL. Каждый запрос читает снимок в READ ONLY по владельцу
сессии. Якорь ограничивает дату проводки. Поздняя фиксация проводки с более
ранней датой учитывается при обновлении сводки. Настройки периода принадлежат
текущей открытой сводке. Бюджеты и настраиваемые категории — отдельный этап.

**Приёмка.** Проверяйте разницу на границе московского дня, точность крупных
сумм, возврат по исходному счёту, чужую выписку, пустоту, повтор после ошибки,
запоздалый ответ для прежнего периода, а также страницы с близкими
метками времени. Используйте `npm test`, `npm run test:roll-activity:production`
и `npm run test:purchase-history` по [регламенту](../verification.md).
