# 15 Вишлист

**Импорт по публичной ссылке.** `POST /api/me/wishlist-import/:provider` читает
сохранённый источник владельца без cookies магазина. [Серверные адаптеры](../../server/modules/wishlist/external-wishlist-import.js)
обрабатывают OhMyWishes, Яндекс Маркет, ссылки WB `/wlg/` и поддерживаемые
веб-страницы списков Ozon. Перенаправление на другую страницу, закрытый список,
антибот и неизвестный формат дают сообщение об ошибке источника.
Сервер перед вставкой сверяет сохранённую ссылку под блокировкой.
Карточки добавляются в «Товары» с приватностью владельца. Дедупликация по
артикулу Ozon и WB учитывает ранее добавленные карточки. У WB берём только
название и ссылку товара, сведения о сборах и авторе остаются за пределами
хранилища. Выгрузка на Яндекс Диск использует существующие
`users.wishlist_links` и принадлежащие владельцу `wishes`.

Списки Ozon, доступные после входа, можно импортировать через буфер
обмена в настройках профиля. Сборщик запускается пользователем на странице
`/my/favorites/list?list=…`. При ручной вставке Rollapp извлекает только
ссылки и названия товарных карточек Ozon и допустимые адреса изображений.
Сессия Ozon остаётся в браузере. API использует действующую привязку к
аккаунту Rollapp и общую дедупликацию по артикулу.

[Клиент](../../src/modules/wishlist/) · [Сервер](../../server/modules/wishlist/)

**В коде.** Мои списки и публичный вишлист, желания в нескольких списках, группы, порядок, перенос, ссылки, заметки к медиа, приоритеты, цена и валюта, даты и повтор, ссылка на сбор, бронирование, исполнение, архив и копирование. Серверные операции живут в `/api/dashboard`, `/api/lists*` и `/api/wishes*`. Публичные профили и ссылки используют те же данные с фильтрацией по правам.

**Владение.** Здесь находятся модель желания, принадлежность, порядок групп, состояние исполнения и резервы. Резерв может быть анонимным и не раскрывает дарителя владельцу. При переносе и группировке проверяйте исходное пространство и владение. Ссылка на сбор — поле желания. Проведение средств обслуживает платёжный модуль.

**Подключение.** Используйте один набор операций желания и адаптер карточки в личном, публичном и общем по ссылке списке. Контекст передаёт режим, список, права и действия. Добавление из каталога возвращает новое желание в коллекцию. Привязка к задаче передаёт тип и ID. При подтверждённом создании вызывайте политику награды на сервере.

[Раздел «Предложения»](../../src/modules/wishlist/wishlist-offers.jsx) показывает
позиции, предложенные аккаунту или отправленные им, и прежние рекомендации
выбранного пространства. Карточка активной входящей позиции показывает цену
и срок исполнения и открывает [чекаут](09-checkout.md). Возврат и проверка
сохранённой операции доступны на соответствующей карточке.

[Витрина продавца](../wishlist-business.md) публикует новую карточку через
`POST /api/wishlist-business/:space/items`. Редактор существующей позиции
отправляет `PATCH`: «Опубликовать» открывает выбранную скрытую позицию,
а «Сохранить» обновляет уже опубликованную.
Первая публикация на ранее скрытой витрине сохраняет прежнюю видимость
остальных карточек.

**Приёмка.** Владелец, гость, ссылка, смешанное членство, устаревшие записи, анонимность, конфликт резерва, отмена перетаскивания и длинное имя группы. Используйте `npm test`, `npm run test:wish-groups`, `npm run test:drag-drop` и `npm run test:details`.

**Доступность формы.** Область загрузки изображения открывается отдельной кнопкой shadcn; скрытый file input находится рядом с ней и исключён из Tab-порядка. Проверяйте Enter/Space, фокус, ошибки загрузки и drag-and-drop без вложенных интерактивных элементов.

Во время движения от края к центральной области Wishlist откладывает краевую перестановку при накопленном продвижении внутрь более 2 CSS px. Движение вдоль края, мелкое дрожание и неподвижное удержание сохраняют таймер 120ms; группировка по-прежнему требует подтверждения центра и подсветки. Расстояние измеряется до той же центральной области, что используется для определения режима. Полная матрица сохраняет исходные 24-шаговые жесты, а товарные сценарии на 320 и 1440px дополнительно замедляют каждый шаг до 35ms. Проверяются точный запрос группы без побочной записи порядка, обычная краевая перестановка и отмена.

Отдельная вкладка «Покупки» в «Финансах» ставит историю и импорт перед бюджетом, чтобы действия были доступны и при длинном списке планов. Бюджет, предстоящие пересмотры, подписки и общие покупки остаются в своих блоках. Вкладка использует приватные маршруты [плана покупок](../../server/modules/wishlist/wish-purchase-plan-routes.js) для бюджета, предложений с доставкой, истории, подписок и сопровождения покупки. Сквозной сценарий: владелец ставит дату и бюджет в карточке, затем пересматривает покупку через панель или основной To Do. Создание потребности и подписки остаётся в меню добавления Вишлиста. `GET /api/dashboard/purchases` возвращает планы, подписки, общие покупки и карточки для выбора вариантов только в контексте владельца сессии. Отдельные сценарии совместных покупок показывают только данные, положенные роли участника, и не проводят платежи. Проверки: `npm run test:purchase-plan` и `npm run test:planning:production`.
