# 10 История операций

[Клиент](../../src/modules/history/) · [Сервер](../../server/modules/history/)

**В коде.** `GET /api/rolls` отдаёт текущий кошелёк и страницы истории роллов. `GET /api/rolls/orders` отдаёт заказы пользователя с доставкой и отметкой возврата. Движения обычного кошелька видны в одной ленте вместе с покупками и возвратами. Персональный счёт и его возврат представлены переводами. Оплаты подарочной картой остаются в истории заказов и журнале карты. Обе стороны защищённой покупки видят срок проверки, закрытие, события и доступные им действия. В строке движения и в заказе можно раскрыть квитанцию и сохранить её как текст.

**Владение.** Модуль владеет чтением, пагинацией, отображением типа, статуса, даты и суммы. Источник проводок принадлежит платежам, запись заказа и команда возврата — чекауту. [PFM](11-pfm.md) подаёт выписку за период в общий компонент ленты. Снимки товара, продавца и ПВЗ используются для исторического отображения по мере доступности.

**Подключение.** Давайте кошельку ленту проводок, маршруту заказов — ленту заказов. Для общего виджета явно передавайте вид истории, страницу, состояние загрузки и разрешённое действие. После возврата перечитайте серверный результат. Карточка защищённого заказа открывает проверку сохранённого действия из чекаута. В кэше разделяйте владельцев и источники.

**Действия по заказам.** Кошелёк и «Заказы» используют одну проекцию
роли, состояния и серверного срока. Сводка кошелька содержит только
счётчики, ближайший срок и сумму выплат. Параметр `attention` выбирает
подборку в заказах. Просроченные действия исчезают при обновлении.
Сохранённая проверка остаётся доступной в прежней подборке.
[Правила защищённых покупок](../marketplace-settlements.md)

**Квитанции.** `GET /api/rolls/receipts/:kind/:id` читает подтверждённую
операцию или текущее состояние заказа по сессии с `private, no-store`.
Номер перевода совпадает у обеих сторон. Для оплаты и возврата персонального
счёта проводка связана с исходным заказом и сохранённым предметом счёта.
Для новых заказов квитанция сверяет идентификатор исходного дебета.
Эту же связь использует сводка роллов для группировки оплат.
Квитанция существующей покупки показывает источник, дату оформления, итоговый
статус и дату расчёта. Способ оплаты картой доступен покупателю. Адрес
доставки, номер карты, комментарии, служебные данные и остаток в квитанцию
не входят. Сумма передаётся десятичной строкой. Для пополнения отображается
также уплаченная сумма в Stars или TON. Интерфейс и TXT используют
одни поля и московское время.

**Приёмка.** Проверяйте стабильный порядок, следующую страницу без дублей, пустое состояние, заказ с прежним снимком, возврат и отсутствие чужих операций в API и DOM. Для квитанций используйте `npm run test:roll-receipts:production`, `npm run test:purchase-history` и `npm run test:orders`. Используйте `npm test` и `npm run test:rolls:production` по [регламенту](../verification.md).
