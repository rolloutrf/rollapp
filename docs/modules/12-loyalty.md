# 12 Лояльность

[Клиент](../../src/modules/loyalty/) · [Сервер](../../server/modules/loyalty/)

**В коде.** Одно приветственное начисление. Программа для подходящих аккаунтов начисляет роллы за первые десять новых желаний, включая ручное создание, копирование и добавление из каталога. Выдача происходит через серверные операции роллов. Редактирование, удаление или восстановление желания повторной награды не создаёт. Политика применимости хранится на сервере.

**В актуальном выпуске.** Модуль также обслуживает подарочные карты, награды за потребности, их ручной и плановый расчёт и проверку квитанций. [Условия наград и расписание расчёта](../need-rewards.md)

**Владение.** В этом модуле держите условие участия, лимит, причину бонуса и связь с уникальным событием. [Платежи](08-payments.md) проводят начисление, [история](10-history.md) показывает его результат. Административный ручной грант и бэкфилл относятся к явным операционным сценариям с отдельным запуском.

**Подарочные карты.** Проверка выпуска, пополнения и отправки читает
исходное действие по аккаунту, в том числе после передачи карты. Только
явный повтор после проверки использует исходный POST. [Подарочные карты и восстановление](../business-gift-cards.md)

**Подключение.** Вызывайте начисление при серверном создании аккаунта или нового желания в той же транзакции. Экран получает подтверждённый результат для уведомления. Владелец магазина или списка подключается к общей политике через событие создания и его устойчивый идентификатор.

**Приёмка.** Проверьте первый и повторный вход, все три пути добавления, аккаунт вне программы, исчерпанный лимит, конкурентный запрос и откат транзакции. Используйте `npm test` и `npm run test:rolls:production` по [регламенту](../verification.md).
