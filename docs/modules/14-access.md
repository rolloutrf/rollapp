# 14 Доступ и выдача прав

[Клиент](../../src/modules/access/) · [Сервер](../../server/modules/access/) · [Общий код](../../shared/modules/access/)

**В коде.** Публичные, для подписчиков, по ссылке и приватные списки. Приватные сферы с чтением владельцем или бизнесом по ранее выданному праву. Точки входа `/api/sphere-shares/*` и `/api/shared/:token`. Прежние команды создания и одобрения доступа отвечают HTTP 410.

**Владение.** Единое решение на сервере получает субъекта из сессии, объект, владельца, секцию, операцию и применимый токен. Различайте доступ для чтения и изменение. Контакты доступны по маршруту карьеры, историческое хранение прав остаётся в scope `contacts`.

**Подключение.** Передавайте странице выданный сервером контекст владельца и режим чтения, чтобы она не предлагала недоступные действия. API проверяет каждый запрос, включая детали и файлы. Вишлист отвечает за принадлежность к списку и передаёт факты для решения доступа и публичной проекции.

Меню бренда использует область и точный раздел права из `SphereSharingProvider`
для отзыва ранее выданного права. Кнопка «Открыть потребности» на карточке
даёт только право читать активные потребности и присылать
[предложения](../personal-offers.md). Приватные области используют свой контракт доступа.

«Клиенты» открываются под [шапкой бизнес-профиля](03-profile.md).
На странице можно отправить предложение и открыть ранее выданный раздел.
Снимок прежних прав читается через `GET /api/sphere-shares/incoming`.
Повтор загрузки и карточки проверяет `node scripts/business-accounts-smoke.mjs --clients-only`.

**Приёмка.** Матрица владельца, гостя, подписчика и гостя по ссылке. Для сфер проверьте бизнес-аккаунт с выданным и отозванным правом, соседний раздел, прямой URL, файлы и попытку записи. Используйте `npm test`, `npm run test:navigation` и закрытые интеграционные сценарии по [регламенту](../verification.md).
