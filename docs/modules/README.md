# Карта модулей РОЛЛАПП

Первые 13 инструкций следуют списку модулей РОЛЛАУТ. Следующие 17 покрывают сценарии РОЛЛАПП, общие компоненты и эксплуатацию. «Идентификация» относится к подтверждению способов входа, а «Идентичность» — к личным документам и психологическим тестам. «Карточка» относится к объектам вишлиста, каталога и магазина. 2FA зарезервирован. PFM показывает сводку движений кошелька за период. В «Доставке» уже работает выбор ПВЗ, а в «Ассистенте» — рекомендации подарков и поиск предложений.

Каждая инструкция описывает текущие точки входа, владение данными, способ подключения и приёмку. Пять приложений сфер используют эту структуру совместно и выбирают собственные HTTP и браузерные точки входа. [Приложения сфер](../sphere-applications.md)

Клиентская часть модуля лежит в `src/modules/<модуль>`, серверная — в `server/modules/<модуль>`, код для обоих слоёв — в `shared/modules/<модуль>`. `src/App.jsx` собирает страницы и контексты, а `server/index.js` регистрирует модули сфер, общие HTTP-маршруты и запускает нужное приложение. Текущие маршруты и вкладки перечислены в [карте покрытия](coverage.md).

## Работа с модулем

1. Найдите сценарий в карте покрытия и откройте инструкцию его владельца. Проверьте используемые проекции, операции и режимы доступа у соседних модулей.
2. Держите данные и правила записи у одного владельца. Другие модули получают опубликованную проекцию данных, серверную команду либо компонент с явными входами и действиями. Сценарий собирает эти части в маршруте или форме. Общие компоненты получают данные и callbacks от вызывающего сценария.
3. При разделении текущего кода сначала выделите одно рабочее поведение за узкой точкой входа. Сохраните действующий URL, форму ответа, права, совместимость старых записей и транзакционность. Подключите тот же вход во второй реальной поверхности, когда у неё тот же контракт. Для общего действия используйте одну серверную операцию, а для UI — один компонент с разными входными данными.
4. Проверьте штатную работу каждого потребителя и границы доступа. Для повторяемых операций проверьте ошибку, повтор и устаревший ответ. Обновите инструкцию и карту при изменении точки входа, владения или проверок. Оформляйте проверку по [регламенту](../verification.md) и [AGENTS.md](../../AGENTS.md).

Сценарий покупки кота собирает товар из [каталога](16-catalog-marketplace.md), ПВЗ из [доставки](06-delivery.md) и проведение из [платежей](08-payments.md) внутри [чекаута](09-checkout.md). После подтверждения [история](10-history.md) читает заказ с сохранённым снимком доставки. Второй пример — [планирование](18-planning.md) сохраняет задачу один раз через общий редактор, а [To Do](19-daily-todo.md), [календарь](20-calendar.md) и [Kanban](21-kanban.md) строят разные представления той же модели.
