# Приложения сфер Rollapp

| Сфера | Публичный адрес | Контейнер | Основные API |
| --- | --- | --- | --- |
| Идентичность | идентичность.роллапп.рф | `rollapp-identity` | `/api/identity` |
| Здоровье | здоровье.роллапп.рф | `rollapp-health` | `/api/health` |
| Карьера | карьера.роллапп.рф | `rollapp-career` | `/api/career`, `/api/contacts` |
| Образование | образование.роллапп.рф | `rollapp-education` | `/api/education` |
| Вишлист | вишлист.роллапп.рф | `rollapp-wishlist` | Желания, списки, группы, каталог, рекомендации, бизнес-вишлист и импорт |

Реестр `shared/applications.js` хранит IDNA-имена, начальные страницы и
границы API. Из него при сборке образа формируется конфигурация Caddy.
DNS-записи CNAME указывают на `роллапп.рф`, сохраняя публичный вход через
существующий балансировщик. TLS завершается в Caddy, а порты контейнеров сфер
доступны во внутренней сети Compose. Caddy отправляет запросы к API по
владельцу пути, в том числе со старых клиентов на основном домене.

Для каждой сферы есть отдельный HTML-вход, браузерный вход в
`src/applications/<сфера>/main.jsx` и регистрация своих обработчиков в
`server/applications/<сфера>.js`. Контейнер получает роль через
`ROLLAPP_APPLICATION`, обслуживает вход своей сферы и принимает только её
API. Обычный выпуск использует один immutable SHA для всех образов.
Контейнеры стартуют независимо. Разделы «Идентичность», «Здоровье», «Карьера»
и «Образование» загружают содержимое вкладок отдельными модулями.
Общая оболочка сохраняет компоненты навигации, доступность и редактирование.

На основном домене работают вход через Яндекс ID, профиль, планирование,
доступы, общие API и фоновые воркеры. Telegram Mini App продолжает
открывать страницы на основном домене. В обычном браузере старые ссылки на
сферы открывают нужный поддомен с исходными query-параметрами и якорем.
Ссылки на публичные профили остаются на основном домене.

## Адреса в браузере

Словарь `shared/modules/shell/page-urls.js` задаёт русские пути, имена параметров и
значения известных разделов. Например, `/app/spheres/health?tab=sleep`
открывается как `/приложение/сферы/здоровье?раздел=сон`. В ссылке на публичный
календарь используется кириллический адрес профиля, например
`/петрова-анна/календарь/запись`. Старый ник ведёт на новый адрес. Идентификаторы
записей, ключи доступа, часовые пояса и произвольные якоря сохраняются в
исходном виде. API и зарегистрированные OAuth callback продолжают использовать
свои технические адреса.

Production-сервер направляет старые адреса на русские с HTTP 308. Каждый
браузерный вход переводит URL при чтении и записи истории, включая переходы
через Back и Forward. Переключение сфер, копирование ссылок и возврат после
входа используют этот же словарь. Обновление словаря проверяется в
`npm test`, `npm run test:applications` и проверке пяти публичных HTTPS-хостов.

## Общий вход и данные

Обычный вход выдаёт Secure/HttpOnly cookies для управляемой зоны
`роллапп.рф`. При переходе на поддомен с прежней host-only сессией основной
домен проверяет прежнюю сессию и срок действия сохранённых аккаунтов, затем
выдаёт общие cookies и возвращает браузер на проверенный маршрут сферы.
Коды OAuth Яндекса возвращаются на зарегистрированный callback основного
домена. Команды с авторизацией сохраняют проверку origin и ожидаемого
аккаунта. Все хосты в этой зоне должны оставаться под управлением Rollapp.

Данные остаются в настроенном production PostgreSQL. Доменные обработчики
владеют своими запросами и сохраняют существующие правила доступа к записям.
Общие операции с профилем, доступами и медиа продолжают использовать
существующие транзакции. Каждый контейнер запускает проверку схемы
`ROLLAPP_DATABASE_INITIALIZATION=verify` и использует пул максимум в два
соединения. Для выпуска не нужны DDL, миграции или перенос записей.

## Выпуск

Перед выпуском проверить состояние основного домена, адрес балансировщика,
бюджет подключений и доступные ресурсы VM. Использовать обычный
`check:release` и процедуру проверки из [регламента](verification.md).
Штатный workflow проверяет пять HTTPS-хостов командой
`node scripts/check-sphere-production.mjs <SHA>`: health конкретной сферы,
точный SHA, её HTML на корневом и вложенном маршрутах и общий API аккаунта.
После него проверить вход один раз, переходы между поддоменами, Back,
старые ссылки и возврат из Яндекс ID в существующей браузерной сессии.
При откате до версии с host-only cookies пользователю может потребоваться
повторный вход.
