# Шкалы из загруженных PDF

`server/identity-report-source-layout.js` восстанавливает полосы и сегменты из
реальных графических операций PDF. `identity-report-layout.js` связывает их с
подписями и числами исходного документа. `IdentityGeneratedDocuments` отображает
эти блоки на странице Hogan/Gallup рядом с извлечённым текстом.

Над содержимым расположен навигационный блок «Графики отчёта» с переходами
«Шкалы» и «Субшкалы» только для реально извлечённой графики. Каждый переход
ведёт к первой соответствующей группе в конкретном файле, не открывает PDF
и не переставляет исходный текст. При нескольких графических файлах ссылки
сгруппированы под полными переносимыми именами файлов. Используется общий
`PageActionButton` 48px/24px, семантика ссылки и нативный fragment-переход;
фокус получает группа графиков. Обычный click/Enter сначала фокусирует цель с
`preventScroll` и мгновенно приводит её к rail; нативный href сохраняет fragment
history. Это исключает конфликт незавершённой focus-scroll с переходом к другому
файлу. Modified clicks остаются нативными. `scroll-margin-block-start` учитывает общий
chrome token и page gap, чтобы цель оставалась ниже верхней навигации.
PDF только с текстом не получает пустую навигацию или вымышленные графики.

- `score-chart`: `rows` содержат исходные `label`, `value` и `color`. Длина полосы
  соответствует числу в диапазоне 0–100. Число остаётся видимым; доступное имя
  графики содержит подпись и значение.
- `subscale-charts`: `columns` содержат код профиля, заголовок и секции со строками
  `label`/`cells`. Каждый элемент `cells` соответствует одному нарисованному
  сегменту исходного PDF. Число и цвет активных сегментов не выводятся из
  процентиля основной шкалы и не заменяются интерпретацией результата.
- Цветные сегменты сохраняют цвет источника; неактивные сегменты используют
  нейтральную поверхность текущей темы. Состояние доступно текстовым именем
  вида «Подшкала: 2 / 4», поэтому цвет не является единственным носителем данных.
- На узком экране профили идут последовательно; выше 820px — в трёх колонках.
  Страницы с подшкалами используют доступную ширину документа, обычный текст
  сохраняет общий текстовый rail. Geist 18/28 и масштаб заголовков не меняются.
- Чтение устаревшей версии layout повторно разбирает сохранённый оригинал для
  ответа API, не требует повторной загрузки файла и не записывает изменения в БД.
  Нераспознанная графика не заменяется вымышленными данными.

`npm run test:identity-reports` проверяет исходный текст, таблицы и графические
блоки, затем запускает `scripts/hogan-scales-smoke.mjs`: восемь размеров, включая
390×400, значения 0/37/100, 4/5 сегментов, пустое/полное заполнение, длинные
подписи, доступные имена и реальную геометрию полос. Fixtures отклоняют API.

Для локальной проверки уже извлечённого реального layout можно передать
`HOGAN_SCALES_REVIEW_LAYOUT=/absolute/path/layout.json` при запуске
`node scripts/hogan-scales-smoke.mjs`. Источник хранится вне репозитория;
проверка сравнивает все значения и цветные сегменты, не выполняя запросов к API
или записей в production. Такой прогон не заменяет live-проверку страницы.

Проверка текущего renderer в `src/components/identity-reports.test.js` адресует
общие source-chart tracks, rank ribbon из 34 shrinkable cells и одну колонку
профилей до 820px. Не привязывать её к удалённым DNA labels/domain cards старого
Gallup renderer. Browser fixture проверяет всю 34-ячеечную шкалу и длинную
неразрывную подпись без ellipsis/clipping; все прежние проверки точных полос и
сегментов сохраняются.


## Произвольные личностные тесты

Владелец может создать тест с названием до 80 символов, переименовать его и
переключаться между тестами через существующие плитки. Выбор сохраняется в `report`
URL. Тесты хранятся отдельно по `custom-<UUID v4>`; Gallup и Hogan сохраняют свои ключи.
Свои тесты пока приватны: существующие разрешения на Gallup/Hogan не открывают их.

У каждого теста до 8 PDF, каждый до 12 МБ и 50 страниц. Загрузка использует
существующий аутентифицированный endpoint, MIME/signature validation, rate limit,
хеш для запрета повторного файла и лимит общего JSON в 2 МБ. Исходный PDF можно
открыть; извлечённое содержимое отображает общий reader с заголовками, текстом и
распознанной структурой. Парсер не приписывает неизвестным тестам шкалы Hogan или
таланты Gallup и не генерирует психологическую интерпретацию. OCR не реализован:
скан без текстового слоя, повреждённый или защищённый PDF получает явную ошибку.
Удаление одного/всех PDF сохраняет название теста. Отдельное подтверждённое удаление
теста удаляет и его файлы. Создание/переименование на телефоне используют нативную
страницу формы; выбор созданного теста применяется после закрытия её history entry.

Схема новых установок допускает custom-ID. Для существующей production-базы нужна
отдельно разрешённая миграция `server/migrations/2026-10-24-custom-identity-tests.sql`.
Она расширяет только два section CHECK; не запускается при старте или UI-релизе,
не изменяет и не удаляет строки. `node scripts/identity-tests-schema.mjs` проверяет
точную настроенную production-базу/роль и ограничения в READ ONLY; `--apply` выполняет
миграцию в отдельной транзакции с короткими таймаутами, только после разрешения.
Пока схема не обновлена, создание возвращает явную 503 без fallback.

`node scripts/identity-tests-smoke.mjs` проверяет реальный компонент и форму на
320/390/768/820/1024/1440/1920 и коротких экранах 390×400/1024×400: создание, ошибка и повтор, переименование,
выбор/URL, отображение PDF и подтверждение/отмена удаления. Используются только
UI callbacks; любые API-запросы запрещены. Проверка не доказывает сохранение в БД
или распознавание всех форматов PDF. Включена в `test:identity-reports`.

Длинные названия тестов и имена PDF переносятся внутри пустого состояния и
подтверждений удаления. Подтверждения используют общую границу VisualViewport
и собственную вертикальную прокрутку. Регрессия проверяет 80 символов без
пробелов и длинное имя PDF по реальным границам дочерних элементов и scrollWidth
диалога; одного отсутствия root overflow недостаточно.

Новые тесты создаются только кнопкой «+» (доступное имя «Новый тест») после плиток в том же горизонтальном viewport. Это обычная кнопка вне tablist, а не ещё одна вкладка; выбор отчёта и клавиатурная навигация Tabs сохраняются. Плитки используют ListTileContent с detail и data-list-tile, описание — общий caption. Загрузка выполняется видимым полем PDF выбранного отчёта (multiple, до8 файлов по12МБ), поле остаётся видимым и отключённым при лимите/загрузке. Во время загрузки «+» отключён. Три прежних page actions «Добавить тест», «Загрузить», «Удалить все» удалены; индивидуальное удаление PDF и настройки custom-теста сохранены. Read-only не показывает «+» и поле. test:identity-reports проверяет полный reader и девятиразмерную матрицу создания/отмены, URL/mobile history, поля, ошибок/retry, multi-PDF, individual delete, лимита и read-only без API/БД.

Настройки custom-теста открываются одной outline-кнопкой `PageActionButton` «Настройки теста», по композиции настроек списка Wishlist. Форма содержит название, отдельный раздел destructive-удаления с пояснением и общий footer «Сохранить изменения». Удаление требует подтверждения; отмена и ошибка сохраняют форму и её черновик. На телефоне успешное сохранение/удаление сначала закрывает native form history, затем меняет выбранный отчёт; удаление возвращает Gallup. Создание остаётся через +, загрузка — через PDF-поле. Встроенные Gallup/Hogan не имеют настроек каталога. Полная девятиразмерная custom matrix проверяет nested confirmation, cancel/error/retry, блокировку во время удаления и отсутствие formScreen после успеха.

Вся сфера identity исключена из shared business marketplace availability: бизнес-кнопок нет во всех разделах, у встроенных отчётов нет пустого action rail; custom-тест сохраняет только «Настройки теста». Legacy business/store route возвращает в приложение, list/purchase API identity отвечает404 до доступа к прежним offers. Записи/схема не удаляются.

Загрузка PDF на странице отчёта открывается круглой кнопкой «+» (48px),
с полным доступным именем «Загрузить PDF для …». Она запускает общий native file
picker; скрытый input сохраняет multiple, PDF validation, лимит8, busy/readonly
и retry. Настройки своего теста и отдельное удаление PDF остаются доступны;
кнопки каталога и «Удалить все» на страницу не возвращаются.
