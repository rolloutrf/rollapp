# Проверка совместных желаний · 9 ноября 2026

Базовый коммит `f55cce47e5718bc411f39cfc9436930deb152f23`. Рабочее дерево на старте чистое. Проверки выполнены с незакоммиченными изменениями этой задачи.

При создании или редактировании желания владелец выбирает участников Rollapp по имени или имени пользователя. Состав участников сохраняется в транзакции записи желания. Изменение состава отправляет явные добавления и удаления, поэтому сохранение других полей из старой формы не возвращает вышедшего участника. Участник видит исходную карточку в блоке «Совместные со мной» нужного пространства и может убрать её со своей доски. Состав участников доступен владельцу. Блок получателя доступен только в его авторизованном представлении.

## Production

Первичная проверка через настроенный TLS и Yandex Lockbox прошла существующие проверки auth, planning и документов, затем остановилась на отсутствующей таблице `wish_participants`.

После отдельного согласования применён DDL из `server/wish-participants.js` в одной транзакции на настроенном production PostgreSQL. Сверены база и роль, схема `public`, сертификат TLS, существующие таблицы `users` и `wishes`, составной ключ, оба внешних ключа с каскадным удалением и индекс по участнику. Реальный startup verify в транзакции READ ONLY прошёл после коммита миграции.

Локальный сервер с изменённым кодом обслуживал реальные HTTP-маршруты на loopback с production PostgreSQL. В одной откатываемой транзакции с тремя временными аккаунтами проверены поиск, создание совместного желания, добавление к уже существующему, выбор пространства старого желания по списку, синхронизация полей и пространства, ограничения редактирования и чтения, повторное добавление, исключение владельцем, выход участника и каскад при удалении карточки. После `ROLLBACK` отдельный запрос подтвердил отсутствие тестовых аккаунтов. Живой браузерный сценарий с этими аккаунтами не запускался.
