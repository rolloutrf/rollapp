# Восстановление сайтов после остановки Yandex Cloud — 18 ноября 2026

Проверки начаты в 23:17 МСК. Локальный исходный коммит Rollapp
`f55cce47e5718bc411f39cfc9436930deb152f23`, рабочее дерево до отчёта чистое.
На публичном Rollapp проверена версия
`d465b22781731db6097d66fdcf328541e8a7a810`, которая была активна до остановки.
Новый релиз Rollapp в этой операции не выполнялся. Итоговое рабочее
дерево содержит только этот отчёт.

## Восстановление

- Биллинг Yandex Cloud активен. Через `yc serverless api-gateway resume`
  запущены семь существующих шлюзов трёх облаков.
- Через `yc compute instance start` запущены действующие ВМ Rollapp и студии.
  Через `yc load-balancer network-load-balancer start` запущен публичный
  балансировщик Rollapp, его действующая цель `HEALTHY`. PostgreSQL
  восстановился до `RUNNING / ALIVE`. Схема проверена через конфигурацию
  production, TLS и штатный `initializeRuntimeDatabase` в режиме `verify`
  с транзакцией `READ ONLY`. Постоянный dev-сервис проверен через
  `npm run dev:keepalive:status`.
- CDN `cdn.роллаут.рф` включён, действующий сертификат перепривязан.
  Для origin задан Host `logos-cdn.storage.yandexcloud.net`. CNAME указывает
  на `87819b770635b524.topology.gslb.yccdn.ru.`, адрес из
  `yc cdn resource get-provider-cname`. Три публичных HTTPS-запроса
  за `/banks.json` получили 200, размер ответа 38 268 байт.
- Для `контакты.роллаут.рф` и `лого.роллаут.рф` выпущен сертификат
  `fpqmdqb1tl77fa1f03lm`. Добавлены записи ACME, сертификат назначен
  существующим бакетам. CNAME каждого домена указывает на веб-адрес
  соответствующего бакета Object Storage.
- `хкпк.финтехника.рф` уже был DNS-псевдонимом главной, но возвращал 404.
  Создан пустой бакет с HTTPS-перенаправлением на главный адрес. Для
  `www.финтехника.рф` создано такое же перенаправление с существующим
  сертификатом. Для обоих адресов настроены CNAME на веб-адреса бакетов.
  Привязку `www` к API Gateway провайдер отклонил из-за квоты
  `serverless.apiGatewaysDomains.count`.
- Запуск исходного PostgreSQL для фильтров, `pg-pilot` (`c9q11j9k294u5dmlk127`),
  завершился ошибкой провайдера `No live hosts left in group`. Последняя
  доступная резервная копия завершена 7 октября в 02:18 МСК. Из неё ранее
  восстановлен действующий production-кластер `c9q73m0flac0ai0kj468`.
  Теми же учётными данными по TLS и в `READ ONLY` подтверждены непустые
  `categories` и `filters` во всех семи базах этого кластера. Ревизия
  фильтров `bbaej664rkq79ecvcuut` использует новую закреплённую версию
  секрета, прежний digest образа и прежние настройки выполнения.
  Предыдущая ревизия `bbafvl7n5m76i6c3fltb` доступна для отката.

## Публичная проверка

- Chrome на ширинах 390 и 1440 px отрисовал страницы и получил 200 для
  колосков.рф, финтехника.рф, роллаут.рф, роллапп.рф, студии, курса,
  демо, витрины, фильтров и Storybook Rollapp.
- Через `curl` с проверкой TLS получены 200 от `www.колосков.рф` и пяти
  разделов Rollapp (образование, карьера, здоровье, вишлист, идентичность).
  `www.роллапп.рф` перенаправляет на основной домен. `/api/healthz`
  подтвердил активную версию Rollapp. Студия вернула `ok` на `/health`,
  а курс отдал PNG `/assets/Avatar1.png`.
- Публичный `/api/health?db=…` вернул `ok: true` и `catalogReady: true`
  для всех семи баз фильтров. `/api/catalog?db=avito` вернул 624 элемента.
- Две внешние точки в России получили 200 от [контактов](https://check-host.net/check-report/58d657c7kb94)
  и [лого](https://check-host.net/check-report/58d657d6kcb4), 301 от
  [хкпк](https://check-host.net/check-report/58d657dek427) и
  [www.финтехника.рф](https://check-host.net/check-report/58d657e2kc2f).
  В 23:39 МСК на Mac ещё наблюдались ошибки TLS при части запросов к
  контактам, лого и хкпк, а системный резолвер сохранял отрицательный
  ответ для `www.финтехника.рф`. Прямой HTTPS-запрос к Object Storage
  с именем `www.финтехника.рф` подтвердил 301 на основной сайт.
- Проверка публичных страниц выполнена без входа в пользовательские
  аккаунты. Production-записи, миграции и очистка не выполнялись.

## Блокировки

- `опенклоу.колосков.рф` указывает на зарезервированный, но не привязанный
  IPv4 Yandex Cloud. В облаке Koloskof нет ВМ и дисков этого сервиса.
  Нужен прежний сервер или резервная копия OpenClaw.
  [Внешняя проверка](https://check-host.net/check-report/58d657c1ka7f)

  для диагностики и запуска VPS нужна авторизованная сессия Cloud4box.
  [Внешняя проверка](https://check-host.net/check-report/58d657cfkf82)
