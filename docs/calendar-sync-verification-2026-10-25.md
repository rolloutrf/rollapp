Новая UI-матрица охватывает 320/390/767/768/820/1024/1440/1920 × 900/400, DPR 3 для 390. Fixture использует явный UI transport и запрещает все настоящие API-запросы. Никакая fixture не подменяет development/production БД. Визуально просмотрены настоящий скриншот компонента на 320px и 1440px и короткая мобильная страница подключения. Полная подпись даты доступна assistive technology; на 320px навигация остаётся в одной строке без столкновения пяти контролов.

Backend-проверка подтвердила: отдельные владельцы и календари не смешиваются, Kanban calendar-subscription не подключается, неподписанный/подменённый токен не читается, capability не подходит для browser login, повторное подключение сохраняет ссылку, замена отзывает старую, отключение не удаляет другие подписки и текущую login session, общий отзыв сессий закрывает и календарные ссылки. SELECT ленты сохраняет авторские 10:17/43 минуты, DATE-only задачи и исключает архив/задачи без даты. Таблицы/схема не создавались и не изменялись.

Во время разработки исправлены обнаруженные проверки: доступное имя кнопки при Spinner, семантическая роль ссылки, невидимая подпись footer из-за роли обычного non-submit действия на mobile. Оба footer действия используют подходящий outline variant и общий ControlBar без изменения shared primitives или глобальной темы. Поздний результат операции игнорирует размонтированное окно; busy не позволяет уйти в середине изменения подписки.

Постоянная production development connection оставлена включённой: `http://127.0.0.1:5177`, API 8097, keepalive PID 21483 при проверке. Сервер загружает существующий credentials secret из Lockbox; новый endpoint без авторизации возвращает 401. При перезапуске keepalive первый stop обнаружил завершающийся старый PID и безопасно сохранил PID-file; после фактического выхода повторное включение прошло. PID-file вручную не удалялся. Схема при старте остаётся в `verify`, прямое TLS-соединение сохраняется.

Ограничения: системный диалог установки Apple Calendar, реальные фоновые обновления подписки, SSL-настройки native webcal handler, физическое iOS-устройство и синхронизация через iCloud не проверялись. В открытом пользовательском браузере шла другая работа, поэтому read-only live проход не доведён до окна подключения; новых личных ссылок или событий в аккаунте не создавалось. Нативные обновления и TLS проверяются отдельно перед заявлением о полном end-to-end прохождении. Локальная HTTP loopback-ссылка не подходит для другого устройства. На публичном домене feature появится только после отдельного deployment.

Полный `check:comprehensive` для этой новой версии не повторялся: предыдущий полный календарный аудит относится к состоянию до добавления синхронизации. Здесь пройдены перечисленные затронутые проверки; это не утверждение о новом comprehensive или release прогоне.
