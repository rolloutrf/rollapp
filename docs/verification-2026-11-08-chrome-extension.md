# Публикация расширения Rollapp для Chrome 8 ноября 2026 года

Проверена версия расширения `1.2.0` из чистого checkout
`1588896abfcb0d181638f36f5d60dfd271d66a08`. Production health на момент
проверки сообщал тот же SHA. Рабочий checkout `f55cce47` был чистым до
добавления этого отчёта.

- ZIP с роллапп.рф скачался с HTTP 200 и типом `application/zip`.
  `unzip -t` проверил все восемь файлов. Распакованные файлы совпали с
  `git archive` каталога `browser-extension` проверенного коммита.
- Хук `rollapp-browser-extension-download` из `vite.config.js` с `TZ=UTC`
  собрал идентичный ZIP. `node --check` прошёл для всех скриптов расширения.
- `node --test scripts/marketplace-wishlist-routing.test.js` прошёл 2 из 2
  проверок маршрутов и запроса входа в Ozon.
- Изолированный профиль Chromium загрузил распакованное Manifest V3
  расширение. На production URL `/app/wishes` оба обработчика вернули
  ожидаемые ответы. Фоновый процесс отклонил неизвестный магазин без
  открытия вкладки магазина. Проверка не записывала данные в Rollapp.
- `npm audit` сообщил 8 предупреждений приложения, `npm audit --omit=dev`
  сообщил 2 высоких (`@ton/ton`, `zod`). ZIP состоит из собственных
  скриптов, манифеста и инструкции и не содержит npm-зависимостей.

[Релиз GitHub chrome-extension-v1.2.0](https://github.com/rolloutrf/rollapp/releases/tag/chrome-extension-v1.2.0).
Архив скачался без авторизации с HTTP 200 и побайтно совпал со сборкой.
SHA-256 архива `aa43038e28293d3923537d046516cd89be7f7ebe74d92fff7ed9f68473aa79eb`.

Проверка ограничена сборкой и распространением расширения. Полный импорт с
авторизацией в магазинах и записью товаров, Comet и общий релизный прогон
Rollapp не проверялись. Повторный rollout приложения не запускался.

## Подтверждение выкладки без тестов

По запросу «Деплой без теста» сверены GitHub Actions и production HTTP.
[Ручной прогон 42416360873](https://github.com/rolloutrf/rollapp/actions/runs/42416360873)
пропустил тестовый этап, опубликовал образ
`486286cc9ba694157af9a3307b061130f2a5d2c4` и обновил конфигурацию VM.
Проверка в CI завершилась по таймауту ожидания смены версии. После
завершения согласования `/api/healthz` подтвердил `ok: true`,
`service: rollapp` и точный SHA этого образа. `/app/wishes` вернул
HTTP 200, а скачанный с production ZIP сохранил SHA-256, указанный выше.
Другой rollout уже обрабатывался очередью. Для расширения отдельный
повторный запуск и тесты не понадобились.
