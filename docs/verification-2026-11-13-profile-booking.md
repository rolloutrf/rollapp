# Календарь записи на встречи, 13 ноября 2026

База проверки — коммит `6b02ea31d7a5d66d4e87091f1f6555d0d112e59c`.
Рабочее дерево ветки `codex/calendly-profile-booking` содержит изменения календаря,
маршрута записи, API и проверок. Node 22.22.3, Chromium на macOS.

Ориентиры — [разовая встреча Calendly](https://calendly.com/help/how-to-create-a-one-off-meeting)
и [страница записи Calendly](https://calendly.com/blog/how-to-send-a-calendar-invite).
Организатор выбирает длительность, часовой пояс, даты и несколько интервалов,
затем вводит название. Участник видит доступные дни и время в выбранном поясе,
проверяет данные аккаунта и подтверждает запись. Прямая ссылка открывает
`/:username/calendar/book`. При необходимости вход сохраняет слот и пояс.
Слоты с одинаковым названием и длительностью показываются как одна встреча.

- `node scripts/profile-publications-schema.mjs` проверил роль, базу и
  существующие таблицы в транзакции READ ONLY по прямому TLS. Dev-сервис
  `http://127.0.0.1:5467` запущен в режиме `verify` и оставлен под launchd.
  Временные сбои Lockbox при запуске восстановились повторным запуском сервиса.
- `npm run test:profile-publications:production` прошёл с откатом. Проверены
  существующие одиночные запросы, пакетная публикация, повтор без дублей,
  отклонение пересечений без частичной записи и правила бронирования и отмены.
- `npm run test:ui`, `npm run build` и шесть целевых тестов серверного
  представления и маршрутов прошли. Повтор полного набора
  `ROLLAPP_TEST_CONCURRENCY=3 npm run test:unit` дал 996 успешных, 0 ошибок
  и 1 пропуск.
- Прямая ссылка реального профиля прошла в Chromium на 390 и 1440 px без
  ошибок страницы, горизонтального переполнения и API-записей. У профиля
  пустое расписание, поэтому заполненные сценарии проверены в fixture,
  а их запись — в тесте PostgreSQL с откатом.
- `npm run test:profile-publications` прошёл 8 размеров: 320×844, 390×844,
  390×400, 768×844, 820×844, 1024×844, 1440×900 и 1920×900. Проверены
  обе роли, часовые пояса, прямая ссылка, конфликт, повтор после потери
  ответа, отмена и открытие публикаций из Вишлиста.
- В браузере исправлены приоритет CSS-слоёв, минимальная ширина календарных
  панелей и переполнение длинной кнопки на 320 px. Просмотрены скриншоты
  выбора слота и редактора на 390 и 1440 px.
- Полный `npm run test:controls` прошёл, включая проверку видимых границ
  48 px и мобильную плотность пикселей. Отдельный общий `test:form-actions`
  на момент отчёта ещё выполнялся. Доска и её форма прошли все размеры
  в `test:profile-publications`.
- Общий `test:dates` остановился на 8-секундных тайм-аутах загрузки
  фикстуры и снимка. Прямой выбор даты в календаре записи проверяется
  отдельным `test:profile-publications`.
- `npm audit` показал 8 предупреждений, `npm audit --omit=dev` — 2 высоких
  в существующих `@ton/ton` и `zod` без предлагаемого исправления.
  Зависимости в этой ветке не менялись.

Полный релиз не запускался. Внешний OAuth до возврата из Яндекса, нативные
мобильные браузеры и конкуренция двух независимых SQL-сессий отдельно не
проверялись. Видеоинтеграции, календарные приглашения и автоматические
письма не входят в реализацию этого интерфейса.
