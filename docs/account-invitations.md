# Лимит участников и инвайты

Rollapp допускает не больше 30 000 аккаунтов. Новый аккаунт создаётся через Яндекс ID по одноразовому приглашению. Email в Яндекс ID должен совпадать с адресом приглашения. При регистрации можно выбрать личный или бизнес-аккаунт, а для бизнеса — категорию и, если требуется, раздел Вишлиста. В существующий аккаунт можно войти через Яндекс ID, Telegram, телефон или email и пароль. Отправлять приглашения может только пользователь с `users.can_invite`; отдельная миграция назначает это право проверенному профилю `@koloskof`.

`account_invites` хранит только SHA-256 токена. Ссылка уходит на email через настроенный Yandex Postbox. Срок — ровно 10 суток с создания; база и API отклоняют истёкшие, неотправленные и использованные инвайты. Одновременную регистрацию сериализует advisory lock, затем транзакция проверяет общее число пользователей и атомарно расходует инвайт. Ошибка доставки оставляет инвайт непригодным. Консольная почта недоступна с production-БД.

После регистрации участник сразу попадает в приложение. Номер участника можно получить отдельно в настройках профиля. При нажатии «Крутить барабан» сервер выбирает криптографически случайный свободный номер от `00001` до `30000`, защищает выбор уникальным индексом и записывает его один раз. Повторный запрос возвращает тот же результат. Форматированный номер показывается в собственном и публичном профиле как ID участника. Исходный UUID служит внутренним ключом для ссылок и внешних связей.

Для каждого выбора сохраняется `SHA-256("rollapp-member-v1:" + user_id + ":" + number + ":" + nonce)`. `nonce`, номер и хеш возвращаются владельцу. Только проверенная входящая self-transfer транзакция TON с комментарием `rollapp-member-v1:<hash>` переводит статус в `confirmed`; хеш отправки сам по себе подтверждением не считается. Подписанный BOC сохраняется до отправки и при сетевом сбое повторяется без нового `seqno`. Если `seqno` изменился без найденного подтверждения, запись переходит в `failed` для ручной проверки, без повторного списания. Рабочая очередь берёт один отпечаток за раз и использует advisory lock между процессами.

## Отдельная подготовка production

Обычный dev/release старт использует `ROLLAPP_DATABASE_INITIALIZATION=verify` и не меняет схему. `npm run db:migrate-account-invites` только проверяет точную production-БД, роль, число аккаунтов, наличие `@koloskof` и состояние схемы. После отдельного явного разрешения оператор выполняет `npm run db:migrate-account-invites -- --apply`. Миграция только добавляет таблицы/колонки/ограничения и выдаёт право инвайтов этому профилю. До выполнения миграции `verify` показывает ошибку отсутствующей схемы; приложение нельзя выпускать в состоянии, где регистрация обходит новую проверку.

Для автоматической записи в TON нужен **отдельный уже развёрнутый и пополненный кошелёк V4**, не используемый другими отправителями. Поместите его 24 слова в Yandex Lockbox, задайте `YC_TON_MEMBERSHIP_LOCKBOX_SECRET_ID`, при необходимости `YC_TON_MEMBERSHIP_MNEMONIC_KEY`, обязательный `TONCENTER_API_KEY` и после проверки кошелька `TON_MEMBERSHIP_ENABLED=true`. `server/start.js` загружает секрет в память перед запуском API. Отправляется 0.01 TON на тот же кошелёк на каждый номер; сеть удерживает комиссию. При 30 000 номеров это до 300 TON оборота плюс комиссии, поэтому баланс и стоимость нужно согласовать перед включением. Без настройки сеть не вызывается, а номер остаётся закреплённым со статусом `pending`.

## Проверка

`npm test` проверяет токены, срок, диапазон, формат и распознавание TON-подтверждения. `npm run check:comprehensive` проверяет существующие UI-контракты без БД. Живые проверка писем, регистрация, миграция и TON-транзакция требуют настроенного production-доступа и отдельного разрешения на мутации; не заменять его демо-БД. Проверить экраны регистрации, барабана и профиля на 320, 390, 768, 820, 1024, 1440 и 1920 px, а также при высоте менее 500 px.
