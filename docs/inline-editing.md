# Редактирование текста в странице

Текстовые документы «О себе», «4 вопроса», «Тезисы», «Принципы», «Миссия»,
«Домен», «Жизненная стратегия», «Идеальное состояние», «План развития» редактируются на месте.
Для начала достаточно поставить курсор в текст; отдельного режима, drawer,
мобильного formScreen и кнопки сохранения нет. План развития — один свободный
Markdown-документ в `InlineDocument`, без переключателей категорий и постоянных
кнопок добавления. Заголовки, описания и списки редактируются в общем потоке;
Enter создаёт следующую строку, `/` открывает выбор блока. Существующий Markdown
загружается без структурного разбора и пересборки; автосохранение использует
прежний раздел `career/development`, очередь и черновик `career:development`.
Прежний объектный черновик в sessionStorage преобразуется в Markdown до
монтирования редактора; открытие не записывает преобразование на сервер.
При загрузке или ошибке документа редактор не монтируется; общий доступ сохраняет
режим чтения.

Форматирование появляется только при выделении текста: одна контекстная панель
с действиями блока, выбором типа, жирным, курсивом и ссылкой. От 768px в этой же
панели доступны underline, strike, inline code и палитра. На телефонах эти действия
доступны в меню «Тип блока»; сброс всех стилей находится в палитре. Курсор без выделения
не показывает панель; снятие выделения скрывает её. Постоянной панели и пустого
места под неё нет. Undo/Redo доступны через обычные сочетания клавиш, символы
и slash-команды работают без открытия панели. Открытый выбор типа, действия
блока или ввод ссылки скрывают панель выделения: она не перекрывает второе меню.
Отмена возвращает выделение и его панель без изменения текста.

Панель привязана к нативному DOM Range своего редактора, включая выделение
через несколько строк и в обратном направлении. Она располагается над подсветкой
с зазором 8px, при нехватке места — ниже; сохраняет поля 16px у границ viewport.
Меню вынесены в отдельные body-порталы, чтобы координаты не зависели от положения
статьи и соседних редакторов. У каждого документа свой portal host; четыре ответа
используют один редактор и одну панель. Прокрутка обновляет положение без
debounce; уход подсветки за экран скрывает меню, возврат показывает его снова.
VisualViewport resize/scroll перепривязывают панель при клавиатуре/panning.
Если выделение выше viewport, приоритет — доступность панели внутри видимой области.
Ввод ссылки и slash-меню используют тот же контракт координат body-портала.

## Текстовые стили и хранение

Смена типа выбранной группы сохраняет индивидуальный цвет/фон каждого блока,
включая обычный цвет, вместо применения цвета активного блока ко всему диапазону.
Текст, заголовки, маркированные/нумерованные списки, чек-листы и цитаты проходят
общий снимок цветов с mapping от начала конкретной команды. При оборачивании
единственного абзаца в пункт списка цвет принадлежит пункту, включая маркер.
Пустые и одинаковые блоки отслеживаются позициями, не сравнением их текста.
Для выделения ячеек используются отдельные selection.ranges, без промежуточных
невыделенных ячеек.

Преобразование группы в toggle создаёт отдельный блок для каждого заголовка,
сохраняет marks/цвет и вложенные пункты. Существующий toggle и его тело остаются
нетронутыми. Простая группа сохраняет направление выбора, а преобразование
столбца сохраняет CellSelection. Одиночное преобразование сохраняет offset
курсора в заголовке toggle, включая slash-команду и следующий ввод. Вся операция
делит один Undo с командой.
Код сохраняет цвет блока; переход к нему и Undo проверяются отдельно от marks
обычного текста. Полный аудит произвольных вложенных композиций остаётся в
`docs/notion-text-experience.md`.


Доступны bold, italic, underline, strike, inline code, ссылка, девять цветов текста
и девять цветов подсветки с возвратом к обычному оформлению. Смешанный диапазон
не показывает ложный единый активный цвет; замена цвета сохраняет разные фоны
его фрагментов. Снятие цвета оставляет фон и другие marks. «Сбросить стили» снимает
marks выбранного текста, сохраняя буквы и структуру; действие отменяется Undo.
Активные кнопки сохраняют индикатор, когда фокус с текста переходит в панель.

Ctrl/Cmd+U, Ctrl/Cmd+Shift+S и Ctrl/Cmd+E переключают underline/strike/code;
Ctrl/Cmd+Shift+H повторяет последний цвет между редакторами и после reload.
Это browser preference `rollapp.inline.last-color.v1`, содержащая только enum
цвета и scope, без текста. LocalStorage недоступен — используется память текущей
страницы. Серверной синхронизации этой настройки между устройствами нет. При
выделении текста применяется inline mark; для выбранных блоков/ячеек — атрибут
блока. При курсоре повторяется последний inline или block scope. Сохранение
Ctrl/Cmd+S не перехватывает Shift+S.
Палитра одна, укладывается в viewport, прокручивается внутри при малой высоте;
radio-группы поддерживают стрелки, Home/End, Enter и доступные имена цветов.

Хранилище остаётся Markdown. Underline использует поддерживаемые Tiptap `++…++`,
цвет/фон — безопасные enum-атрибуты `<span data-inline-color="red"
data-inline-background="yellow">…</span>`. Обычные code spans сохраняют backticks.
Для непрерывного code с разными styles внутри Markdown не может выразить вложенное
оформление. Code с буквальными переносами, табами, повторными или крайними пробелами
также нельзя отдавать обычному codespan serializer: он нормализует whitespace
или переносит его за границы marks. Эти случаи сериализуются как inline HTML под
`<span data-inline-rich>`, с экранированными текстом/атрибутами. Закрывающие теги,
кавычки, pipe, табы, переносы и повторные пробелы остаются буквами. Разбор ограничен
известными text marks/атрибутами, не исполняет HTML и работает без браузерного DOM.
HTML `<br>` имеет одинаковую семантику hard break в editor/public/server parser.
Тот же fallback применяется к обычной прозе с крайними/повторными пробелами,
табами, буквальными CR/LF и marks на hard break, ведущими/конечными/повторными soft breaks и переносами
в heading/semantic roles. Он сохраняет символы и
оформление без добавления code mark, в том числе после slash-преобразования.

`InlineMarkdown` использует те же marks для чтения опубликованной прозы, вместо
прежнего inline-regex, распознававшего только bold/links. Ссылки проходят проверку
схемы URI. Парсер использует отдельный экземпляр `Marked` и inline-контейнер:
`1.`, `#`, fence и отступы внутри переданной строки не становятся другим блоком
и не исчезают. Marks нормализуются схемой редактора, чтобы цвет/фон одинаково
наследовались при чтении. Для обычных документов с таблицами или fenced code
`MarkdownDocument` использует тот же редактор в read-only: вложения и буквальный
код читаются одинаково после сохранения. Неинтерактивные source groups внутри возрастных/стратегических accordion также
передают rich-блоки общему read-only renderer: canonical images и колонки не
превращаются в alt/plain text. Прежний parser сохранён у документов с внешним
обработчиком интерактивных чек-листов; полный аудит сложных составов остаётся открытым. Несколько абзацев
ячейки сохраняются отдельными блоками через канонический HTML.

## Цвет целого блока

Меню блока → «Цвет блока» и slash-команды `/red`, `/blue background`,
`/default` поддерживают девять цветов текста или фона. У блока один enum
`blockColor`: цвет и фон — альтернативные режимы. Сброс снимает только этот
атрибут; независимые inline marks сохраняются. Обычное оформление не меняется
при отсутствии атрибута, plain Markdown остаётся прежним.

Цвет работает и у пустого блока, сохраняется при вводе, переносе/дублировании,
смене типа и Undo. Текущий контракт Enter: следующий абзац наследует цвет;
прямое соответствие этого перехода Notion ещё требует отдельной сверки в R6.
Блоковые группы и диапазоны текста, включая обратное выделение через ответы,
применяют цвет одной транзакцией. Фиксированные вопросы не окрашиваются.
Вложенный пункт списка относится к своему item, toggle summary — к toggle;
родительский цвет наследуется, явные inline/child цвета остаются независимыми.

В меню таблицы «Цвет ячеек» меняет всю поверхность выбранных ячеек, включая
header cells; текстовая палитра продолжает менять только содержимое. Геометрия,
Geist 18/28 и общий typeset rhythm не переопределяются. Цветовые токены находятся
в `src/typeset.css`; фоны не вводят border, outline, ring или shadow.

Для хранения используется читаемый canonical HTML внутри Markdown API:
`<div data-inline-block="true"><p data-block-color="red">…</p></div>`.
Адаптер снимает wrapper при загрузке: он не добавляет узел/отступ в документ.
Окрашенные вложенные списки/toggle/таблицы сериализуются целиком, сохраняя
структуру, spans, marks, whitespace и пустые блоки. Кодек использует общий
DOM-free vocabulary с table storage, проверяет безопасные enum/теги/структуру;
повреждённый HTML остаётся буквальным текстом. Для image sizes различаются
числовые и строковые атрибуты. Метаданные image/divider сохраняются, но их
цветовые действия не предлагаются: эти узлы не имеют текстовой поверхности.

Обычное публичное чтение новых блоков использует тот же read-only renderer.
HTML clipboard собственного редактора сохраняет literal whitespace (`full`);
обычный внешний HTML сохраняет стандартные правила ProseMirror. Черновики и
retry содержат полный Markdown с атрибутами; восстановление не записывает его
самостоятельно. Read-only запрещает и palette, и повтор последнего цвета.

`text-block-color-checks.mjs` входит в полную матрицу; диагностика:
`npm run test:text-edit -- --block-colors-only`. Проверяются slash/default,
пустые блоки, ввод/Enter/смена типа, Undo, смешанные marks, группы/ячейки,
обратный диапазон через ответы, clipboard, reload/public read, draft/retry,
два независимых редактора, preference reload/storage failure, read-only и
VisualViewport 220px / offset 96px. Реальные iOS/Telegram IME этим не заменяются.

## Таблицы

Из ячейки Ctrl/Cmd+/ открывает существующее меню блока с группой «Действия
таблицы». Оно доступно и через ручку блока или «Действия блока» в панели
текстового выделения. Меню добавляет строки выше/ниже и столбцы слева/справа,
выбирает строку/столбец/таблицу, переключает первую строку и первый столбец
заголовков, очищает ячейки, удаляет строку/столбец/таблицу. Удаление и очистка
используют destructive. Каждое изменение меню — отдельный шаг Undo; открытие,
отмена и выбор ячеек не меняют содержимое.

CellSelection обозначает прямоугольник целых ячеек, поддерживает Shift+клик и
не вызывает текстовую панель поверх соседней строки. Bold/italic и общие
стили/палитра доступны в меню выбранных ячеек. Палитра рассматривает каждый
выбранный диапазон отдельно, не захватывая находящиеся между ними соседние
ячейки. Выделение букв внутри ячейки сохраняет обычную панель форматирования.

«Объединить ячейки» сохраняет содержимое верхней левой ячейки; подсказка объясняет
это до действия. Undo возвращает содержимое остальных ячеек. «Разделить ячейку»
сохраняет текст якоря и создаёт пустые покрытые ячейки. Таблица с rowspan может
содержать строки без собственных ячеек — они сохраняются при reload.

Enter создаёт отдельный абзац внутри ячейки. Tab переходит дальше, в последней
ячейке добавляет строку; добавление отделено в истории от следующего ввода.
Границы столбцов перетягиваются мышью, ширины сохраняются и отменяются Undo.
Минимальная ширина ячейки 96px; единственный горизонтальный scroll owner —
`.tableWrapper`. Таблица может быть шире него, общий текстовый rail не растёт.
Обычные ячейки остаются 18/28/400, заголовки — 18/28/600 на muted-поверхности.
Сетка таблицы не является рамкой inline-редактора: его border/outline/shadow
по-прежнему отсутствуют.

GFM сохраняется для представимых без потерь таблиц. `inline-table-markdown.js`
выбирает читаемый `<table data-inline-table="true">` при spans, ширинах,
нестандартных заголовках/выравнивании, нескольких/вложенных блоках и буквальном
whitespace. Это остаётся Markdown API; новая колонка БД не нужна. Кодек без DOM
сохраняет marks, списки, toggle, код и вложенные таблицы; проверяет vocabulary,
атрибуты, прямоугольную сетку и границы spans. Нераспознанный или повреждённый
канонический HTML остаётся буквальным текстом и не исполняется.

Resize-плагин устанавливается и при первоначальном read-only, но его события
проверяют editable. При отключении редактирования активный drag сбрасывается
вместе с меню, поэтому mouseup не записывает незавершённую ширину. Повторное
включение доступа возвращает действия без пересоздания документа.

Отдельный полный smoke: `npm run test:text-edit -- --tables-only`. Он входит в
обычный прогон и проверяет восемь размеров, native selection/resize, меню на
коротком VisualViewport, save/reload/draft/retry, публичное чтение, четыре ответа
и отзыв доступа во время drag. Отдельные hover-ручки строк/столбцов, их drag/
дублирование, рост сетки за угол, фон целой ячейки, произвольный табличный clipboard
и реальные touch/IME ещё требуют работы и не считаются завершёнными.


## Выбор и действия с блоками

Escape переводит курсор или текстовое выделение в выбор целых блоков. Повторный
Escape снимает этот выбор. ↑/↓ переходят к соседнему блоку, Shift+↑/↓ расширяют
или сокращают диапазон, Shift+клик выбирает диапазон от исходного блока.
Enter возвращает курсор в последний выбранный блок. Выбор обозначен только
мягкой заливкой; рамок, колец, теней и панели inline-форматирования нет. Буквы
сохраняют основной цвет, даже когда браузер скрывает нативное выделение.
Нативный NodeSelection после drag/Undo также не открывает панель форматирования
текста. Ручка скрывается, если плагин после изменения привязал её к защищённой
структурной секции; новое наведение на абзац снова показывает её у абзаца.


Ctrl/Cmd+A сначала выбирает текст текущего абзаца; повторное нажатие — документ.
В пустом абзаце первое нажатие выбирает сам блок. В режиме выбора блоков
Ctrl/Cmd+A расширяет выбор на все блоки документа.

Ctrl/Cmd+Shift+↑/↓ перемещают весь диапазон, Ctrl/Cmd+D дублирует его,
Backspace/Delete удаляют. Ctrl/Cmd+/ открывает общее меню действий с диапазоном;
добавление выше/ниже вставляет блок за пределами всей группы. На desktop ручка
выбранного блока переносит группу целиком. Копирование и вырезание сохраняют
структуру и marks. В списках и чек-листах Tab/Shift+Tab вкладывают/поднимают
выбранные пункты вместе с дочерними блоками. Структурные действия отделены в
истории: Undo восстанавливает текст и выбор блоков, в том числе после удаления
всего документа. Перемещение абзаца с курсором сохраняет позицию и stored marks.

Перед командами, копированием и вырезанием редактор сверяет нативный текстовый диапазон с состоянием,
чтобы быстрый Escape после клика и accessibility-выделение работали с нужным
абзацем. IME-композиция и структурные/cell selections этим не заменяются.
Выделение не вызывает запись; обычное изменение текста проходит через прежнюю
очередь автосохранения. Выбор несоседних блоков описан ниже; перенос группы
через границы структурных ответов остаётся отдельным незавершённым сценарием.

## Несоседние блоки

Cmd+Shift+клик на Mac и Alt+Shift+клик на Windows/Linux добавляют или снимают
целый блок. Вне режима выбора первое такое нажатие выбирает только нажатый блок.
На широкой странице то же сочетание на ручке не открывает меню. Обычный
Shift+клик выбирает непрерывный промежуток от исходного anchor, в том числе
через фиксированные секции ответов. `blockSelectionBetween` сохраняет прежнюю
группу соседей, а через защищённые обёртки собирает точные целые блоки ответов:
промежуточная проза включается, вопросы — нет. Native text range также доступен.
Escape переводит нативный диапазон в блочный выбор в обе стороны; конец ровно
в начале нетронутого ответа исключает этот ответ. Копирование блочной группы
не добавляет фиксированные вопросы; удаление/замена не сливают нетронутые хвосты.
Частичный endpoint списка проверен unit-тестом; отдельный чистый diagnostic
прошёл все 32 комбинации пустых ответов/направления. Полный mixed-table/toggle аудит остаётся
незавершённым.
Это соответствует [командам Notion](https://www.notion.com/help/keyboard-shortcuts).

`BlockSelection.positions` хранит отсортированные начала выбранных узлов;
`ranges` объединяет только соседей одного родителя. Выбор родителя включает
дочерние блоки, поэтому перекрывающиеся parent/child записи удаляются.
`createSelectionBetween` сохраняет BlockSelection при задержанной нормализации
его DOM-проекции из границ узлов в первые/последние текстовые позиции. Иначе
браузер мог превращать точный набор в TextSelection, включать пропуски/вопросы
и показывать чужую панель после отрисовки. Флаг обычного mouse/touch pointer
сохраняет возможность явно выбрать текст или поставить курсор, включая пустой
абзац; новая явная блочная команда сбрасывает этот флаг. Частичный native range
не перехватывается. Устойчивость проверяется каждый кадр 650 мс для сквозной и
несоседней группы, а пустой блок после обычного клика сразу принимает текст.

JSON/bookmark сохраняют точный набор и направление; mapping удалённого узла
не должен выбирать занявшего его место соседа. Поля from/to описывают главный
диапазон, поэтому проверки принадлежности используют containsSelectedBlock.

Copy/cut, удаление, замена текстом, HTML/Markdown paste, цвета и смена типа
затрагивают только выбранные блоки. Дублирование вставляет копии рядом с каждой
выбранной последовательностью. Перемещение вверх/вниз сдвигает каждую выбранную
последовательность на одного соседа внутри её родителя; упёршаяся в край
последовательность остаётся на месте. Drag переносит выбранное содержимое
вместе, без пропущенных блоков. Групповые изменения имеют один Undo.
Удаления при замене выполняются с конца и заканчиваются в месте ввода, чтобы
последующий набор слова оставался в одной истории с заменой. Подготовка IME
создаёт свой пустой абзац, не присоединяя ввод к пропущенному соседу;
отмена композиции восстанавливает текст и выбор без публикации временного удаления.
Реальный IME всё ещё требует проверки на устройстве.

При смене типа несоседние пункты исходного списка изолируются разбиениями,
сохраняющими mapping пропущенных пунктов. Сохраняются checked state, исходные
номера пропущенного ordered-list сегмента, rich marks и наследуемые цвета детей.
Если новый тип не допускает вложенных блоков, дочерние блоки сохраняются после
него и входят в выбор. Code block получает обычный текст, Undo возвращает marks.
При перекраске quote/item/toggle собственный первый paragraph/summary
не должен перекрывать новый blockColor: его старый blockColor сбрасывается,
inline marks и независимые дочерние стили сохраняются. Цвет целого list
container применяется также к его прямым пунктам и маркерам, включая reset.
Bookmark хранит обе границы выбранного узла: wrapper replacements сохраняют
интервал, настоящее удаление схлопывает его. После wrapping первый paragraph
пункта нормализуется в item; вложенные item остаются отдельными.
Это сохранение существующего содержимого; произвольное Notion-вложение прозы
ещё не реализовано. Tab/Shift+Tab для несоседнего набора пока не выполняется.

В четырёх ответах можно выбрать блоки разных секций, не выбирая вопрос или
промежуточный ответ. Copy/cut, цвет, тип, удаление и замена сохраняют фиксированные
вопросы и нетронутые хвосты ответов; Enter редактирует head вместо удаления группы.
Полный аудит сложных таблиц/toggle и drag через границы секций остаётся открытым.

## Четыре вопроса как один документ

`FourQuestionRichEditor` создаёт один contenteditable и одну историю Undo для
всех ответов. `four-question-document.js` задаёт четыре упорядоченных секции:
формулировки вопросов остаются фиксированными по действующему серверному
контракту, содержимое ответов редактируется напрямую. Заголовки вопросов
находятся вне editable contentDOM; их нельзя удалить или переставить действием
над абзацем. Обычные абзацы внутри ответа поддерживают выбор блока,
перемещение, дублирование и перетаскивание.

Нативное выделение может начинаться в одном ответе и заканчиваться в другом,
в обе стороны. Форматирование использует один диапазон; замена, Backspace,
Delete, Enter и вырезание удаляют выбранный текст внутри каждого ответа,
сохраняя фиксированные вопросы и оставшиеся части ответов на своих местах.
Действие отменяется одним Undo. Ctrl/Cmd+A может выбрать весь документ;
стрелка возвращает курсор в начало или конец редактируемого текста и скрывает
панель. Копирование включает только вопросы, попавшие в диапазон; HTML
содержит обычные заголовки и блоки, пригодные для вставки в другой документ.
Отмена композиции восстанавливает временно удалённый диапазон без сохранения
промежуточной пустоты. Реальные iOS/Telegram IME ещё требуют отдельной проверки.

API и сохранённая структура не меняются: `{ questions: [{ title, paragraphs }] }`.
Адаптер сериализует изменённые ответы в прежний Markdown; неизменённые массивы
абзацев сохраняет в исходном виде, включая legacy whitespace. Одна очередь
автосохранения подтверждает снимки, не заменяя новый ввод старым ответом сервера.
Ошибка сохраняет полный черновик четырёх ответов для восстановления и retry.
Открытие, выделение и read-only не вызывают запись. Смешанный clipboard через
ответы проверяется на таблицах, списках, закрытых toggle, колонках, nested tasks,
marks и code; частичные endpoints и merged-cell rectangles сравниваются с обычным
редактором. Произвольные составы и внешние приложения требуют дальнейшего аудита.

`npm run test:text-edit -- --four-document-only` запускает отдельную полную
матрицу этого документа: 320/390/768/820/1024/1440/1920px и 390×400.
Она также включена в обычный `npm run test:text-edit` и отклоняет API-запросы.

## Компоненты

- `EditableTextBlock`: Tiptap, семантические заголовки, списки/чек-листы, цитаты,
  ссылки, таблицы, изображения и код. Markdown остаётся форматом API; чтение
  само по себе не записывает преобразованную версию. `:::label`/`:::statement`
  имеют собственный парсер и сериализатор. Регрессионные тесты проверяют
  существующие документы, текст, структуру и форматирование после round trip.
- `InlineDocument`: общие действия страницы, редактор и `InlineSaveStatus`.
  «Добавить» вставляет новый блок в текущий документ. Текст можно удалить
  обычным выделением/Backspace; отмена и повтор поддерживаются редактором.
- `InlineTextField`: plaintext-поле для структурированных данных.
  Названия и отдельные пункты однострочные по модели данных, визуально
  переносятся; Enter завершает поле. Описания допускают несколько строк.
- `useInlineAutosave`: одна очередь на документ. Все четыре ответа используют
  общую очередь, поэтому сохранение одного ответа не затирает соседний.

## Ввод и навигация

Enter создаёт абзац, Shift+Enter — перенос строки; стандартные горячие клавиши
отвечают за жирный, курсив, undo/redo. `/` в начале строки или после пробела
открывает команды и в существующем тексте: фильтр по названию/alias, стрелки,
Enter, Escape. Доступны типы блоков, `/duplicate` и `/delete` с русскими aliases.
Удаление имеет destructive variant. Tab переводит фокус на активную команду;
Enter выбирает её, стрелки/Home/End перемещают фокус между кнопками.
В search input Home/End сохраняют обычную работу с текстом. Escape возвращает
фокус документу. Пустой результат не перехватывает Tab; Enter выбирает
подсвеченную команду и после смешанного pointer/keyboard ввода.

Меню привязано к конкретному набранному `/`: Escape, уход курсора из query,
Undo/Redo, paste/drop или загрузка не открывают его заново. Перемещение внутри
query сохраняет полный диапазон команды. Выбор удаляет только этот диапазон,
сохраняя текст по обе стороны, marks и соседние блоки. Удаление query и смена
структуры выполняются одной транзакцией; один Undo возвращает набранную команду
и исходный блок, дальнейший ввод имеет отдельную историю. Дублирование сохраняет
вложенное содержимое; действие в ячейке обращается к её блоку текста. Четыре
фиксированных вопроса защищены прежним контрактом.

Пути/URL без пробела перед slash, ссылки и code не запускают команды; IME
не выполняет выбор по Enter. Read-only/отзыв доступа закрывают меню. Slash-цвета
с фоном целого блока и полный каталог действий Notion ещё не реализованы.
VisualViewport resize/scroll обновляют положение slash и link после shared CSS
layout; vertical shift сохраняет поля 16px даже при panning клавиатуры.

Выделение показывает компактную панель
форматирования. Ссылка открывается обычным нажатием при чтении, Ctrl/Cmd+нажатием
при редактировании; обычное нажатие позволяет редактировать её текст. Ctrl/Cmd+K
открывает ввод ссылки возле выделения. Escape закрывает его и возвращает фокус.
Вставка текстового Markdown распознаёт заголовки, списки и чек-листы; вставка
HTML сохраняет поддерживаемое форматирование. Внутри блока кода текст остаётся
буквальным. Если буфер содержит `text/plain`, вставка в активный строчный code
использует его даже при наличии HTML: сохраняются символы, LF, табы, пробелы
и marks назначения.
Это правило действует для текстового выделения внутри одного блока; выбор
целых блоков сохраняет обычную структурную вставку, включая группу code-абзацев.
CRLF/CR нормализуются в LF; вставка не создаёт другие блоки и не запускает
повторные paste rules. Она имеет отдельный шаг Undo/Redo и сохраняет соседний
текст. Slash не открывает меню внутри строчного или блочного кода.
Панели используют стабильные настройки, чтобы их обновления не
перезаписывали нативное положение курсора.

Редактор остаётся в document flow. Нет scroll lock, отдельного вертикального
скроллера или фиксированных Save/Back. Контекстная панель помещается на экране
от 320px без горизонтальной прокрутки. Текст остаётся 18/28, высоты контролов — 48px. Вокруг редактируемого текста никогда нет рамки, outline, ring или тени, включая hover/focus/focus-visible/active. Клавиатурный фокус кнопок панели остаётся видимым.
Публичные страницы, ожидание загрузки и ошибки доступа не допускают записи.

## Форматирование символами

Преобразование происходит при обычном наборе в документе, без режима
редактирования. Блоковые префиксы работают в начале абзаца после пробела;
парное форматирование — после закрывающих символов.

| Набор | Результат |
| --- | --- |
| `# ` … `###### ` | Заголовки 1–6 |
| `- `, `* `, `+ ` | Маркированный список |
| `1. `, `3. ` и другие номера | Нумерованный список с указанного номера |
| `a. `, `i. ` | Буквенный или римский список; тип сохраняется после загрузки |
| `[] `, `[ ] ` | Невыполненная задача |
| `[x] `, `[X] ` | Выполненная задача |
| `- [ ] `, `- [x] ` | Пункт обычного списка превращается в задачу |
| `> ` | Раскрывающийся блок |
| `" `, `“ ` | Цитата |
| `---` | Разделитель сразу после третьего дефиса |
| `*** `, `___ ` | Разделитель после пробела |
| Три обратные кавычки или `~~~`, затем Enter | Блок кода; можно указать язык, например `js` |
| `**текст**`, `__текст__` | Жирный |
| `*текст*`, `_текст_` | Курсив |
| `~текст~`, `~~текст~~` | Зачёркнутый |
| Обратная кавычка с каждой стороны текста | Код внутри строки |
| `[текст](https://example.org)` | Ссылка |

Backspace сразу после автоматического преобразования возвращает последние
введённые символы. Создание блока кода через Enter имеет отдельный шаг Undo.
Соседние пункты, номера и вложенное содержимое сохраняются при преобразовании
пункта списка в задачу. Форматирование сериализуется обычной очередью автосохранения;
одинарная тильда сохраняется каноническим Markdown с двойной тильдой.

Внутри кода правила форматирования отключены. Незавершённые пары, имена вроде
`file_name_value` и обычные арифметические выражения остаются текстом. Небезопасная
Markdown-ссылка не превращается в активную ссылку. IME-композиция не преобразуется
до завершения; Enter при активной композиции не создаёт блок кода.
При наборе используются префиксы Notion. Чтение и вставка Markdown сохраняют
стандартные значения: сохранённое `> Цитата` по-прежнему является цитатой.
Toggle сериализуется в существующие `:::details`-директивы. Его название сохраняет
исходные текст, marks и мягкие переносы; вложенные списки становятся содержимым,
соседние пункты и их номера остаются на месте. Backspace сразу после `> `
возвращает исходные символы. Enter в пустое содержимое открытого toggle переводит
курсор в существующий абзац, не добавляя ещё один пустой блок.
`InlineTextField` остаётся plaintext-полем структурированных данных.

## Перемещение блоков

Выбор блоков, NodeSelection и ячеек рисует полупрозрачный синий слой через
background-image (`--inline-selection-tint`, 18% существующего ink-blue).
Авторский background-color остаётся под ним, glyphs — над ним. Выбор не создаёт
border, outline, ring или box-shadow у прозы. Скрытое нативное `::selection`
использует currentColor и прозрачный фон, сохраняя разные цвета inline marks,
а не заменяя их `--foreground` всего блока. Обычное текстовое выделение сохраняет
общий продуктовый стиль: правило ограничено ProseMirror-hideselection.
Проверка реальных пикселей важнее computedStyle(::selection): в наблюдённом
Chromium currentColor мог возвращать первый highlight RGB для всех фрагментов,
хотя glyphs рисовались правильно.


На широком экране от 1024px ручка из шести точек и «+» появляются в левом
поле документа при наведении на блок. Перетаскивание меняет порядок через
ProseMirror, сохраняет форматирование и показывает позицию вставки. Вложенные
пункты списка переносятся вместе со своими дочерними пунктами. Нажатие на ручку открывает меню блока.

На любой ширине кнопка «Действия блока» в меню выделения и Ctrl/Cmd+/ открывают то же
меню для блока у курсора: вверх/вниз, вставить выше/ниже, дублировать, удалить.
Верхнее поле «Поиск действий блока» сразу получает фокус. Название действия,
типа или цвета на русском/английском фильтрует общий каталог; ↑/↓ выбирают
результат, Enter применяет его, Escape закрывает меню с восстановлением позиции
в документе. Пустой поиск оставляет обычные действия и инструменты таблицы.
Запрос не попадает в текст или историю. Смена типа, цвет, дублирование и удаление
имеют отдельный Undo; группа блоков сохраняет область выбора при фокусе в поиске.
Меню ручки адресует наведённый блок, а не прежнее положение курсора. Изменение
документа после открытия делает снимок меню недействительным; read-only и IME
не выполняют команду. Палитра и вставка по-прежнему открываются вместо меню.
Ctrl/Cmd+Shift+↑/↓ перемещают текущий блок среди соседей. На телефоне и узком
экране используется это меню: наружные hover-контролы не перекрывают текст и не
выходят за экран. Первый/последний блок не перемещается за границы родителя.
Все операции входят в обычную историю Undo/Redo и очередь автосохранения.
Read-only/loading не отображают контролы перемещения. Рамок вокруг блоков нет.

## Создание блоков

«+» возле блока открывает выбор типа для вставки ниже. Alt/Option+нажатие
открывает вставку выше. На любой ширине те же действия доступны в меню блока
(кнопка в меню выделения или Ctrl/Cmd+/). Блок появляется только после выбора типа:
открытие, поиск, отсутствие результатов и Escape не меняют документ.

Общий каталог для «+», кнопки «Тип блока» и `/`: текст, заголовки 1–4,
маркированный и нумерованный списки, чек-лист, раскрывающийся список, цитата,
код, разделитель и таблица. Разделитель создаёт собственный следующий абзац для
ввода; таблица — сетку 3×3 с заголовками и курсором в первой ячейке. Tab переходит
к следующей ячейке. Структурные блоки вставляются после существующего текста,
а пустой абзац slash-команды заменяется без лишнего пустого блока.
Поиск понимает русские названия и английские text/heading/toggle; стрелки
меняют выбор, Enter применяет, Escape возвращает курсор. На широком экране
показывается пример блока, на телефоне — компактный список. Меню имеет один
вертикальный скроллер и ограничено доступной высотой VisualViewport.
Кнопка «Тип блока» меняет тип текущего блока, сохраняя текст. Превращение
списка в текст снимает маркеры; превращение раскрывающегося блока в текст
сохраняет его название и содержимое обычными блоками. Undo возвращает структуру.
Прокрутка списка стрелками не меняет выбор из-за неподвижного указателя мыши.

Новый блок сразу получает текстовый курсор. Создание и следующий ввод имеют
отдельные шаги Undo. Удаление slash-команды и создание выбранного блока — один
шаг Undo, который восстанавливает введённую команду. Обычный текст внутри списка создаёт соседний пункт;
для других типов выбирается ближайший родитель, допускающий этот тип,
чтобы не нарушать структуру списков и таблиц. Открытый выбор не применяется
к документу, который успел измениться извне.

Раскрывающийся блок содержит редактируемое название и вложенный документ;
стрелка сворачивает/раскрывает его, Enter из открытого названия переходит
в содержимое. Структура и состояние сохраняются Markdown-директивами
`:::details`, `:::detailsSummary`, `:::detailsContent`. Пустое содержимое
восстанавливается с абзацем для ввода. Read-only позволяет раскрывать текст,
но не записывает изменение состояния.

## Сохранение

После паузы 800 мс, потери фокуса или Ctrl/Cmd+S отправляется текущая версия.
Запросы последовательны. Ввод во время запроса остаётся доступным; ответ старого
запроса не заменяет новый черновик. Состояния: есть изменения, сохраняем,
сохранено, ошибка с повтором. IME-композиция передаётся после её завершения.

При доступном sessionStorage черновик хранится в текущей вкладке по владельцу и
разделу, удаляется после успешного сохранения. Восстановленный черновик требует
повторного сохранения; при отличии серверной версии показывается предупреждение.
Переход между страницами отправляет оставшиеся изменения; закрытие/перезагрузка
вкладки с незавершённым сохранением вызывает браузерное предупреждение. Ошибку
нельзя выдавать за успешное сохранение. Отказ sessionStorage не блокирует ввод,
но восстановление после закрытия вкладки тогда недоступно.

Это не совместное редактирование: серверные API пока не поддерживают слияние
параллельных изменений из разных вкладок/устройств. SessionStorage не является
бессрочной историей версий. Автотесты не записывают данные в production.

## Вложенность обычных блоков

Tab вкладывает текущий блок или выбранные блоки под предыдущий, Shift+Tab
поднимает на один уровень. Поддерживаются обычный текст, несоседние группы,
пункты трёх видов списков и их дети. Родитель перемещается, дублируется и
удаляется вместе с детьми. Курсор сохраняет смещение и ожидающие marks;
блочное выделение сохраняет направление и точный набор блоков. Каждая команда
образует отдельный шаг Undo. Backspace в начале первого обычного ребёнка
поднимает его вместо склеивания с родителем. Нативные Tab в code/table,
read-only и IME guards остаются у своих обработчиков.

Логический `nestedBlock` создаётся только при появлении обычных детей: первый
блок — собственное содержимое родителя, остальные — дети. Пустая прозрачная
обёртка нормализуется обратно. Хранение использует существующий безопасный
канонический HTML внутри Markdown; родительские list/quote/toggle с такими
детьми также сериализуются целиком. Старый Markdown продолжает загружаться.
Новая версия читателя нужна для новых вложенных документов. До создания дерева
проверяется существующий предел HTML reader в 100 уровней тегов, включая marks.

В «4 вопросах» форма API прежняя: фиксированные заголовки и `paragraphs`.
Лимит одного ответа остаётся суммарно 600000 символов и до 30 частей; один
rich-фрагмент может использовать этот бюджет целиком. Это проверка валидатора,
а не увеличение HTTP body limit (он остаётся 256KB). Изменения БД не нужны.

`scripts/text-nesting-checks.mjs` включён в полный `test:text-edit`;
`--nesting-only` запускает диагностическую матрицу 320, 390 (включая высоту 400),
768, 820, 1024, 1440 и 1920. Проверяет реальные клавиши, детей при drag родителя,
Undo/дублирование/удаление, точный save/reload/public read, ритм заголовков,
12 уровней на узком экране и отсутствие рамок/API. Реальные мобильные клавиатуры,
вложенные clipboard/color boundaries и жесты изменения глубины требуют дальнейшей
проверки. В меню блока доступны «Вложить блок» и «Поднять на уровень выше»,
включая поиск действий. Они используют ту же транзакцию, что Tab/Shift+Tab,
сохраняют caret/выбор и отдельный Undo; для grip применяется наведённый блок.

Глубоко вложенные нативные bullet/ordered/task списки сохраняют доступную ширину
на узком экране: shared typeset уменьшает горизонтальный отступ на глубине,
а checkbox занимает собственную строку grid без повторного вычитания своей ширины
из каждого потомка. Публичный MarkdownDocument направляет документы со списками
в тот же read-only parser, что редактор. Коллапсируемые и явно интерактивные
legacy-checklists сохраняют свою композицию. `--deep-lists-only` проверяет три
типа списков на 12 уровнях: реальный ввод, точный save/reload, публичную иерархию,
checked state, body 18/28/400, все borders/outline/shadow и descendant overflow.

У многоабзацной legacy-цитаты при групповом преобразовании сохраняется выбор
отдельных абзацев. Одноабзацная цитата и цитата в собственном первом блоке
явного nested-родителя выбираются как родитель с детьми. Нормализация не должна
превращать выбор четырёх цитируемых абзацев в один контейнер и менять дальнейшие
цвет/тип/Undo-команды.

Горизонтальная стрелка без модификаторов снимает обычный текстовый диапазон через
нативное visual caret movement и сразу синхронизирует DOM/model. Это исключает
восстановление старого диапазона при быстром возврате из portalled палитры:
панель скрывается вслед за реальным курсором. IME, расширение Shift, shortcuts,
Block/Node/Cell/AllSelection и read-only сохраняют собственные обработчики;
при отсутствии platform movement API используется прежний нативный путь.
`text-native-caret-checks.mjs` сравнивает команду с отдельным unmanaged editing host
на тех же тексте/marks/направлении и проверяет 650ms стабильности для LTR/RTL/bidi/
emoji. Это проверка текущего Chromium, а не доказательство работы реальных iOS/Windows/IME.

Контекстные Bubble/Floating меню используют `position: fixed` уже при первом
измерении, до применения координат библиотекой. Tiptap React первоначально
выставляет inline `absolute`; локальное правило в `inline-editor.css` согласует
computed position с fixed strategy. Без этого первое скрытое выделение за
viewport, затем прокрутка и новый выбор добавляли scrollY к координатам панели.
`text-first-selection-checks.mjs` проверяет эту последовательность, первое окно
ссылки и 650ms frame stability на девяти размерах, включая 1280×720 живого дефекта.
В живом приложении при scroll432 панель теперь имеет bottom302 для selectionTop310:
ровно 8px, без изменения текста или сохранений.

30 элементов `questions[].paragraphs` — прежняя форма хранения, а не ограничение
числа блоков в ответе. Адаптер сохраняет исходный массив нетронутого ответа точно;
изменённый Markdown с более чем 30 storage chunks сохраняется одной строкой,
включая все разделители и пустые строки внутри кода. Текущий общий character
budget и HTTP body limit остаются прежними. Fixture проверяет объекты настоящей
чистой `identityFourQuestionsSchema`; zod оптимизируется до загрузки страницы.
`text-long-answer-checks.mjs` проверяет native Enter в 31-й/32-й абзац, API shape,
соседей, точный reload, draft/retry и read-only на всей восьмиразмерной матрице.

Непосредственные блоки ответа могут перемещаться через фиксированные вопросы
клавиатурой и через меню. Перемещаются узлы с детьми, marks и собственным цветом;
сами вопросы остаются на месте. Несоседние группы сохраняют порядок и направление,
пустой источник получает реальный paragraph, канонический пустой приёмник
заменяется. Курсор/Node/Cell/Block bookmarks и один Undo сохраняются.
`text-question-move-checks.mjs` проверяет клавиши, меню, оба направления sparse
выбора, 650ms stability и save/reload на восьми размерах.

Перемещение использует общую модель логических соседей (`inline-block-move.js`):
native list wrapper определяет маркеры, а каждый listItem/taskItem является
самостоятельным блоком на текстовом rail. Поэтому пункт может перейти за край
списка, а обычный абзац — переместиться мимо одного пункта. Родитель переносит
всех детей. Восстанавливаются исходные marker attrs, ordered segments, цвет
контейнера и checked state. Новые совместимые стыки списков соединяются;
нетронутые исходные wrappers, разные цвета и custom ordered starts сохраняются.
Собственный первый текст nested/list родителя не меняется местами с его детьми.

Внутренний drag переносит исходные узлы той же модели, не пропуская их через
HTML fitting. Верхняя/нижняя половина собственной строки определяет before/after;
линия 2px на общем текстовом rail показывает реальную позицию вставки, а возле
края viewport доступна прокрутка документа. Перенос сохраняет BlockSelection и
один Undo; перед dispatch снимается нативная drag ownership. Сохранённый
BlockSelection не выдаётся ProseMirror за NodeSelection. Внешние HTML/text drops
сохраняют обычный путь. Escape, изменение исходного doc и отзыв доступа отменяют
внутренний перенос без fallback-копии старого HTML или DOM residue.
`text-list-block-move-checks.mjs` проверяет три списка/два направления на восьми
размерах, native drag на 1024×844 и 1440×400, а также реальные жесты отмены,
изменения документа и доступа с видимой линией вставки. Итоговая общая регрессия
текущей объединённой версии проверяется отдельно от этих целевых матриц.


Cmd/Ctrl+Enter меняет текущее checked/open у taskItem/details, сохраняя текст,
attributes, descendants, Text/Node/Block selection и pending marks. Undo/Redo
отделены от ввода. Одиночный block mode поддерживается; read-only, IME и
multi-block text ranges не запускают эту команду. `text-mod-enter-checks.mjs`
проверяет native shortcuts, tasks/toggles, caret, save/reload и guards на8размерах.

Общий `canReloadNestedBlocks` защищает Tab, keyboard moves и relocation от
канонического HTML глубже существующего reader limit100tags (включая marks).
Неприемлемый перенос целиком отменяется до transaction; guide не обещает такую
позицию. `text-relocation-depth-checks.mjs` проверяет настоящий held mouse drag
55-level группы внутрь другой55-level группы без HTML fallback/мутаций/записей.

У таблиц есть hover-ручки строки и первого ряда столбцов на desktop от1024px с
hover pointer. Их48px/20px геометрию задаёт ControlBar; общий block grip временно
скрывается без transition visibility у его дочерних кнопок, чтобы не дублировать
действия поверх ячеек. При вводе ручки исчезают. На всех размерах те же команды
перестановки доступны в существующем меню Ctrl/Cmd+/. Menu close синхронно
возвращает focus редактору; следующий Undo сразу действует на документ.

`inline-table-axis.js` использует установленные ProseMirror row/column commands
и связанный spans band. Он сохраняет cell attrs/marks/children, позиционные
header roles, соседей и fixed question sections; имеет отдельный Undo и точный
Markdown reload. Перенос произвольной группы несвязанных выбранных строк пока
не реализован; такие menu actions отключены вместо частичного переноса.
Pointer drag показывает2pxguide, поддерживает edge scroll и отменяется при
Escape/doc/access change, capture loss и window blur. Window blur в fixture
синтетический; настоящее touch/IME и широкий horizontal edge scroll ещё нужны.
`text-table-handles-checks.mjs` проверяет9 viewport cases и2 guard cases с5modes;
табличная сетка сохраняется, рамка у editable prose по-прежнему отсутствует.


Табличные ручки учитывают нижнюю границу настоящей `.global-app-chrome` при
прокрутке: reserved slot не оказывается под переключателем разделов. Если места
над header row нет, column handle получает отдельный slot в gutter; высокий
первый ряд размещает этот slot выше row handle, когда ниже не хватает места.
Геометрия не меняет body/font/page inset и сохраняет прежнюю границу gutter8px.
Реальная композиция — внешний app-page и вложенный sphere-text-page с reading role,
а не эти два класса на одном элементе.
`text-table-chrome-checks.mjs` использует реальные GlobalAppChrome/contexts,
проверяет native hit-testing, непересечение контролов и DOM Range текста,
menu cancel, root overflow и отсутствие save/API на10размерах. На1024×400 таблица
содержит только header row; на1440×400 header
cell намеренно высокий. Это новая проверка композиции; источник605 её не имел.
`text-table-wide-checks.mjs` проверяет pointer edge-scroll широкой таблицы к
невидимому столбцу на1024×844 и1440×400: exact attrs/widths/children, Undo/Redo,
reload и один горизонтальный owner. Произвольные selected row groups,
duplication/grow/media и actual device ввод остаются отдельной работой.

Курсор после native keyboard/input события остаётся между реальными app chrome/navigation bounds. Reveal меняет только scroll через два кадра; manual scroll и посторонние programmatic selection не вызывают reveal. На время focus inline prose html использует auto scrolling и native scroll-padding по общим chrome/navigation tokens. Table axis меню теперь также дублируют строки/столбцы целыми connected merged bands, сохраняют attrs/widths/children и один Undo. Исторические проверки source611 описаны в датированном отчёте; актуальная матрица указана в docs/verification.md.

Общий caret observer обслуживает rich prose и plaintext InlineTextField. Он читает нативный Range, использует PM fallback для пустого rich paragraph и Range fallback для plaintext blank line, не меняет selection/history/string; pending reveal отменяется по wheel/touch intent и composition. Scoped root auto/padding действует только на focus редактируемого host. Grid growth доступен через hover-plus и corner handle: preview transient, Enter/Space/pointerup — один Undo, Escape/blur/access/doc/capture-loss — отмена. Shrink имеет destructive variant. Независимые header flags переживают1cell shrink/reload; strict canonical table marker принимается public reader. Focus предшествует resize transaction, чтобы новая дальняя ячейка вошла в свой horizontal scroller. Native Four Questions/wide/nested scenarios проверяются отдельными сценариями; общий результат текущей версии фиксируется полным прогоном из docs/verification.md.

После явного роста таблицы `requestInlineCaretReveal` сначала раскрывает всю новую ячейку через её собственные scroll owners, затем общий observer оставляет нативный курсор между app chrome/navigation. Undo/Redo через keyboard или history beforeinput используют тот же путь. Команда проверяет текущий фокус, доступ, IME и пустое текстовое выделение; обычный selectionchange и ручная прокрутка её не вызывают. Это сохраняет курсор при offscreen первой строке и после отмены роста. `text-table-insert-caret-checks.mjs` проверяет 1024×844 и 1440×400 после 650ms, DOM/model parity, немедленный ввод, отдельный Undo и оба Redo shortcut. Точный отчёт: `notion-table-caret-intent-verification-2026-10-18.md`.

Текущие document columns используют semantic columns/column в одном editing host и общей истории. Боковой drag создаёт соседнюю колонку; перемещение последнего блока в обычный поток и удаление целой колонки разворачивают единственную оставшуюся колонку. Общий picker и /columns создают две колонки с немедленным вводом. Ширины — относительные атрибуты: pointer preview не меняет JSON, commit имеет один Undo, keyboard arrows/Home/End меняют пару пропорций; Escape/access/source/IME отменяют устаревший preview. До768px колонки идут последовательно. Gutter и table axis controls проверяют реальные glyph rects, не перекрывая соседний текст.

После sync native selection история закрывается перед native paste; низкоприоритетный InlinePasteHistory закрывает его после appended paste rules. Следующая печать отменяется отдельно; обычная непрерывная печать группируется по-прежнему. Column draft/retry/native HTML clipboard сохраняют width ratios, marks, literal whitespace и nested task/toggle. Structural insertion проверяет canonical reload depth до dispatch: отказ сохраняет исходный документ/историю. Остальные операции на границе глубины требуют отдельного аудита.

Bare Home/End на macOS сохраняют native selection и используют те же document endpoints мгновенно. Это предотвращает keyboard-scroll анимацию, которая продолжала действовать поверх следующего Shift+Up. Modified keys остаются native. ## Явное нативное выделение после фокуса

`InlineNativeSelection` читает явный native TextSelection активного editable host
в capture phase document selectionchange, до recent-focus reset core observer.
Подписка снимается при destroy; IME, read-only и кастомные selections сохраняют
владельца. Нельзя сопоставлять range с устаревшим документом: read-only адаптер
к DOMObserver prosemirror-view1.42.6 откладывает sync при pending DOM mutations,
scheduled parse или подавленном selection update. Очередь сохраняется, forceFlush
и изменение внутренних focus timestamps не используются. При отсутствии API
адаптер отказывается от раннего sync; обновления библиотеки требуют native smoke.
Native-caret матрица дополнительно проверяет explicit start, возврат owned range
через focus и queued append/middle/delete/markup с точным caret/marks/соседями.
Движение Shift+стрелок остаётся браузерным; keyboard reference и650ms stability
сохранены. См. `notion-native-selection-capture-verification-2026-10-18.md`.


## Создание блока и окончательные метрики курсора

Успешная вставка возвращает native focus перед dispatch и отправляет общий
explicit authoring caret intent после commit. Scoped slash/action commands только
строят одну транзакцию: их facade не меняет DOM, а реальный владелец управляет
focus и раскрытием уже выбранного нового курсора. Отказ schema/depth/source/access
не должен менять документ или историю. Создание и следующая печать отменяются
отдельно. Новая строка видна до первого символа между реальными app controls.

Shared rich/plain observer сначала раскрывает native caret, округляя fractional
scroll delta наружу, чтобы сохранить полный8px зазор. Если новое начертание ещё
загружается, он сверяет окончательные метрики только для прежнего native range и
generation. Wheel/touch, другой selection, доступ, IME и lifecycle отменяют старый
callback; шрифт не меняет selection/history/content.
`text-insert-ownership-checks.mjs` проверяет8 размеров,64 создания в code/table,
columns/nesting/toggle и четырёх ответах, точный ввод/Undo/save/reload и8 настоящих
delayed-font settlement/cancel scenarios. Это не проверка физической мобильной IME.

## Native clipboard и история диапазона ячеек

Внутри одного ответа text/plain использует реальные selection.ranges в порядке
документа, включая отдельные диапазоны ячеек. Сквозной clipboard сериализует
flattened slice только между его openStart/openEnd: структурные предки не
создают пустых строк перед первым выбранным символом. Не применять trim:
пробелы, табы и переносы, написанные в коде, остаются буквальными. HTML сохраняет
marks/цвета, merged spans, colwidth, вложенные списки, toggle и колонки; вопросы
попадают в обычный документ только при фактическом пересечении диапазона.

Нативный paste ограничивает отдельное событие истории до запуска clipboard
handlers. Это распространяется на upstream table paste, у которого нет uiEvent
metadata. Граница после синхронного doc change включает appended clipboard rules;
следующая печать отменяется отдельно, как и вырезание до вставки. Непринятый
paste intent снимается в microtask и не меняет группировку следующей обычной
печати. Read-only не создаёт историю и не dispatch-ит транзакции.

`scripts/text-cross-clipboard-checks.mjs` включён в полный test:text-edit:
8 mixed cross-answer cases (оба направления, Copy/Cut/Paste/Undo/Redo/save/reload),
8 partial cases (48 сравнений table/list/task/code endpoints с ordinary native
editor), 8 cell cases (merged rectangle, native text/HTML parity, отдельные
Cut/Paste/typing Undo/Redo и exact reload). Все API fixture-запросы отклоняются.
Диагностика `--cross-clipboard-only`, `--partial-cross-clipboard-only`,
`--cell-clipboard-only` не заменяет полный editor/comprehensive.

Native editor focus preserves a newly placed DOM caret or forward/backward range while selectionchange is delayed. The pinned late-priority ProseMirror focus adapter runs after Tiptap public FocusEvents, retaining focus/blur callbacks, isFocused and focus class lifecycle; unsupported adapter shape falls back to upstream behavior. Explicit EditorView.focus() still restores model-owned selections. `--selection-only` tests all eight viewports with a simulated delayed native event, exact offsets/direction, one anchored toolbar, public callbacks, no document/save/API writes. This does not substitute for actual-device IME verification.

Column-width separators own the narrow inter-column gutter before hover state renders. The first native pointer must hit the separator and be captured by that same control; revoking access or changing the document during preview cancels without a native prose drag or document mutation. `--column-contexts-only` includes first-hit/capture checks and exact changed-source cancellation at short desktop and mobile widths.

Native focus restoration is synchronous for model-owned image/cell/block selections; it must not schedule a later reset over a newly placed text range. Image resize controls carry their own editor instance owner, not shared-portal ownership; hovering another image retires previously focused image chrome, and returning native editor focus restores only its selected image guides. Native resize tests cover focus/hover/portal handoff with both editors simultaneously visible.

Inline Markdown storage preserves marks on every character, including selected edge spaces and adjacent differently styled runs. Explicitly removed links and literal ++ delimiters stay literal after reload; normal Markdown imports keep their existing syntax. Rich list-item child blocks (extra paragraphs, dividers, headings, code and media) retain their own structure through canonical HTML instead of compact continuation lines. Native style checks include actual formatting/unlink/typing, independent Undo/Redo, exact editor reload/public reading at eight viewports. Model tests compare whitespace marks rather than discarding them.

Ctrl/Cmd+S from portalled editor controls prevents the browser Save Page action and flushes only the owning document queue. React capture keeps portal ownership local to each InlineRichTextEditor; key events inside the editable DOM retain ProseMirror native input/mutation handling. Saving a document does not apply or close an unconfirmed link form. The native style matrix checks two simultaneously dirty editors and pending metadata on all eight viewports.
