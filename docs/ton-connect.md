# TON Connect в РОЛЛАПП

На `/app/rolls` есть отдельный блок подключения TON-кошелька. Поддерживаются
Tonkeeper, MyTonWallet (в реестре — My Wallet) и Wallet в Telegram. Используется
официальный `@tonconnect/sdk`, а окно выбора и QR-код собраны из компонентов
РОЛЛАПП. SDK загружается отдельным чанком вместе с блоком кошелька.

Пользователь выбирает кошелёк, открывает приложение по ссылке или сканирует QR
и подтверждает подключение. Установленное расширение/встроенный кошелёк использует
JS bridge. После подтверждения показываются полный адрес и сеть; адрес можно
скопировать, кошелёк — отключить. Запрос отменяется при закрытии окна или выборе
другого кошелька. Подключение восстанавливается на этом устройстве; ключи хранения
разделены по ID пользователя РОЛЛАПП. При уходе со страницы транспорт останавливается.
Телеметрия SDK отключена. Приватные ключи криптокошелька и seed-фразы не запрашиваются.

Это подключение на устройстве, а не доказанная сервером привязка адреса к профилю.
Вход через TON и авторизация по адресу не реализованы: для них нужен отдельный
одноразовый challenge и серверная проверка `ton_proof`. Баланс криптовалют,
отправка транзакций, обмен роллов и криптопополнение в эту интеграцию не входят.
Существующие операции с роллами и Telegram Stars не меняются.

## Публичный манифест

`GET /tonconnect-manifest.json` доступен без авторизации, отдаёт JSON с
`Access-Control-Allow-Origin: *` и кешем 5 минут. Иконка — публичный `/favicon.png`.
`GET /api/ton-connect/config` возвращает только URL манифеста.

Перед выдачей конфигурации сервер проверяет публичный HTTPS-манифест: статус,
JSON вместо HTML страницы, CORS, поля приложения и доступность PNG/ICO-иконки.
Проверка ограничена 6 секундами; успешный результат кешируется на 30 секунд,
ошибка — на 5 секунд, одновременные проверки объединяются. Маршрут самого
манифеста остаётся доступным независимо от этой проверки. Браузер ограничивает
ожидание конфигурации 8 секундами и повторяет проверку перед созданием QR/ссылки.
При ошибке показывается сообщение с повтором, запрос в кошелёк не создаётся.

Настройте `TON_CONNECT_PUBLIC_URL` на публичный HTTPS origin приложения. Если
переменная не указана, используется первый HTTPS origin из `PUBLIC_APP_URL`,
`TELEGRAM_WEB_APP_URL`, `APP_ORIGIN`. Невалидное явное значение приводит к 503,
без подмены конфигурации. Адреса не формируются из заголовков запроса.

Манифест и иконка должны быть опубликованы на этом origin **до реального подключения**.
Локальная разработка может использовать манифест уже опубликованного приложения
или доступный извне HTTPS preview с соответствующей конфигурацией. Телефон не
может загрузить манифест с localhost компьютера. Vite проксирует путь манифеста
на backend; статическая сборка сама по себе не обслуживает динамический манифест.

Список кошельков в `public/tonconnect-wallets.json` взят из официального реестра
`https://config.ton.org/wallets-v2.json` 12 сентября 2026 года. При обновлении списка
синхронно обновляйте `TON_CONNECT_BRIDGE_ORIGINS` в `server/ton-connect.js`:
production CSP разрешает соединения только с перечисленными мостами и своим origin.
Добавление произвольных кошельков требует проверки их bridge origin.

## Проверка

`node --test server/ton-connect.test.js src/lib/ton-connect.test.js` проверяет
изолированное хранение сессий, выбор транспорта, конфигурацию, публичный манифест,
CORS и соответствие реестра CSP. Эти проверки не используют базу данных.

Для проверки в интерфейсе используйте только настроенную production PostgreSQL.
На desktop и mobile проверьте окно выбора, QR, отмену, повторный выбор, ошибки
сети; для полного протокольного цикла требуется пользовательский кошелёк:
подтверждение → адрес/сеть → перезагрузка → копирование → отключение.

Источники: [SDK](https://docs.ton.org/applications/ton-connect/api-reference/sdk),
[манифест](https://docs.ton.org/applications/ton-connect/core-concepts),
[правила Telegram](https://core.telegram.org/bots/blockchain-guidelines).

  для подключения внешний кошелёк должен получить новый манифест с публичного домена.

### Исправление зависания

После сообщения о зависшем Wallet добавлена проверка готовности публичного
манифеста. Подтверждено, что из среды разработки HTTPS-запрос к публичному
домену закрывается без ответа (curl и браузер), а новый серверный probe возвращает
`TON_PUBLIC_UNAVAILABLE`. Это препятствует подключению, но не доказывает, что
загрузка интерфейса Telegram Wallet зависла исключительно из-за манифеста.
Последняя публикация `34688563897` также завершилась ошибкой проверки production.
VM запущена; SSH с настроенным ключом отклонён (`Permission denied (publickey)`).
Защита от HTML вместо манифеста, отсутствующего CORS, сетевого тайм-аута,
недоступной иконки и повторной проверки покрыта тестами. Всего 11 проверок TON/Vite.

### Восстановление production

После разрешённых пользователем исправлений metadata и SSH обнаружен
заполненный диск VM. Освобождение кэша старых Docker-образов позволило
запустить ожидаемую версию `fe4ecc…`; публичный HTTPS и проверка базы через
`/api/healthz` снова отвечают 200. Подробности — в `ton-production-recovery.md`.
Манифест пока возвращает HTML старого приложения. Отдельная сборка только
с TON Connect подготовлена и проверена (Vite, shadcn, 11 тестов).
Полный цикл с подтверждением в пользовательском кошельке
остаётся непроверенным.
