# Проверка поиска предложений в карточке товара, 13 ноября 2026

Проверка проведена в отдельном worktree от `6613188b4022a849531c57b47ea21f43ed5d9ef9` (`origin/main`, чистый до правки). Основной checkout `f55cce47` содержал незавершённые изменения других задач. Проверки ниже выполнялись с рабочим diff этой задачи.

- В авторизованном Comet на production `6b02ea31d7a5d66d4e87091f1f6555d0d112e59c` кнопка «Найти лучшие» в карточке Ulanzi L024 показала начало поиска, затем «Не удалось найти новые прямые карточки товара». На момент проверки снимка выдачи для карточки в базе не было.
- Импортированное название содержало общие слова после разделителя. Их учитывали при расчёте доли совпадений, из-за чего короткое название той же модели могло не пройти порог. Поставщик мог выбрать одну карточку площадки до проверки поисковых цитат или дубликата исходной карточки.
- Сервер и клиент используют одну проверку соответствия товара. Для названия с кодом модели допускается совпадение по части до разделителя с сохранением проверок модели, цвета и аксессуаров. Кандидаты проходят проверку до отбора предложения по магазину.
- Поиск по индексу Яндекса подключён как резерв для обычных товаров, если каталоги ещё не нашли новую прямую карточку. Резерв отправляет название и список магазинов, использует действующую сервисную роль и проверяет, что результат ведёт на подходящую карточку. Цены и наличие по поисковому сниппету не выставляются. Первый пригодный набор показывается во время поиска. На мобильном результат раскрывается выше фиксированной панели.
- Отдельный запрос к действующему Yandex Search API с production runtime SA вернул шесть альтернативных карточек Ulanzi L024. После отбора были прямые ссылки Ozon и Wildberries. Прямой каталог Яндекс Маркета вернул другую карточку той же модели. Эти пробы не сохраняли данные в БД. [Документация Web Search API](https://aistudio.yandex.ru/ru/docs/search-api/api-ref/WebSearch/search)
- Настроенная production PostgreSQL проверена через `initializeRuntimeDatabase` в `verify` с прямым TLS. Managed dev service после проверки здоров и оставлен включённым.
- Целевые unit-тесты: 58 прошли. `npm test`: 1001 прошёл, один пропущен. `npm run test:ui` и `npm run build` прошли, сохранилось предупреждение о размере сборочных chunks. Целевой браузерный прогон на 320×844, 390×844, 390×400 и 1440×844 подтвердил получение результата из потока, его видимость, обработку задержанного чтения и повторный поиск.
