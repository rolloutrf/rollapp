# Проверка консистентности UI — 21 сентября 2026

Проверка выполнена в локальном интерфейсе `127.0.0.1:5174` с существующей авторизованной сессией и настроенным production API. Данные не создавались, не сохранялись и не удалялись.

## Исправления

- Общая панель действий: одна строка, контролы не сжимаются, длинные подписи не выходят из кнопок. При нехватке места доступна горизонтальная прокрутка с доступным первым элементом.
- На ширине до 390 px центральный переключатель разделов ограничен своей колонкой. На 320 px больше нет пересечения с соседними кнопками; до 360 px декоративная иконка скрыта, название и стрелка остаются.
- Статусы курсов, конференций, коучинга, тренировок и препаратов расположены под названием; меню карточек — справа.
- Заголовки и кнопки секций CV выровнены по вертикали; контролы секций остаются у правого края. В CV и ИПР используется существующий контракт вложенного документа для отступов заголовков.
- Группы препаратов используют общий компонент названия и счётчика списка.
- Плитки дат анализов используют одинаковый размер, отступы и выравнивание; строка центрируется, когда помещается. Длинные заголовки групп анализов переносятся, а не обрезаются.
- У форм создания и просмотра контакта добавлены доступные названия диалогов.
- Read-only проверки компоновки распознают намеренно прокручиваемые списки и проверяют размер, пересечения и доступность первого элемента панелей действий.

## Ограничения

- «Характер» в текущем окружении возвращает «Раздел не найден»: запущенный API из прежнего checkout не поддерживает этот раздел. Проверена страница ошибки, но живой выбор и сохранение черт не проверены. Клиентская реализация и схема данных проверены тестами.
- `/app/business/access` перенаправляет текущую сессию в желания; административные состояния не проверены.
- Вход без авторизации, все возможные состояния данных, загрузка файлов, оплата и операции сохранения/удаления не входят в этот read-only проход.
- Полный `test:visual` не запускался, поскольку существующий сценарий изменяет данные. Вместо него использованы проверки DOM и визуальный просмотр в существующей сессии.
