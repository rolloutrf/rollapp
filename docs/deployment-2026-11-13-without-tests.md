# Деплой Rollapp без тестов 13 ноября 2026 года

В production развёрнут коммит `e87514f04bfcffcc9b9b7f842e2f603037de286a`. На момент запуска `HEAD` совпадал с `origin/main`, рабочее дерево было чистым.

## Запуск и проверки

- `npm ci --ignore-scripts --no-audit` установила зависимости для проверки схемы. По запросу пользователя тестовые наборы пропущены.
- Штатная проверка схемы через `initializeRuntimeDatabase` успешно прошла на настроенном production PostgreSQL через прямое TLS-подключение в транзакции `READ ONLY` с откатом. Отдельно прочитана схема календарного бронирования, публикаций и дневника настроения. Миграции не запускались. Приложение сохранило режим `ROLLAPP_DATABASE_INITIALIZATION=verify`.
- Команда `gh workflow run deploy-yandex-cloud.yml --ref main -f verification=none` запустила сборку и публикацию Docker-образа без тестов. Шаг проверки production завершился успешно. [Запуск GitHub Actions](https://github.com/rolloutrf/rollapp/actions/runs/43420053563)
- Публичный `GET /api/healthz` вернул `ok: true` и точный SHA релиза, `GET /` вернул `200`, а `GET /mcp` без авторизации вернул `401`. Вызов инструментов MCP с пользовательским ключом в рамках этого деплоя не проверялся.
- GitHub Actions завершился ошибкой на настройке Telegram из-за тайм-аута Bot API после успешной проверки production. Штатный скрипт `scripts/configure-telegram-bot.mjs` затем успешно выполнен с рабочей машины. Он подтвердил аккаунт `@rollappRFbot`, кнопку меню с production-адресом, активный Main Mini App и режим long polling.
