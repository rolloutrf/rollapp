# Личные заметки на Яндекс Диске

В режиме пилота в разделе «Yandex ID» настроек профиля появляется ссылка
«Личные заметки на Диске». После запуска синхронизации полной копии ссылка
«Открыть личные заметки» доступна в карточке синхронизации владельцам с
сохранёнными заметками. Их текущий текст включается в общий архив.
Это отдельный приватный раздел с текстовым редактором и автосохранением.
После паузы в наборе Rollapp сохраняет Markdown в папку приложения на Диске.
Редактор показывает «Все изменения сохранены» после подтверждения записи.
Прежние разделы и существующие документы продолжают пользоваться своими хранилищами.

PostgreSQL хранит идентификаторы подключения, зашифрованные токены OAuth,
идентификатор папки и номер текущей версии. Текст и история версий находятся
в файлах .md на Диске. Сервер Rollapp читает и записывает текст через API.
Каждая подтверждённая запись создаёт новый файл без перезаписи прежнего.
Пилот сохраняет все версии. Это расходует место на Диске пользователя.
Папку и текущий файл следует оставить на месте для доступа из Rollapp.

Во время сохранения сервер сравнивает версию из редактора с актуальной
версией под блокировкой строки подключения. Он переводит указатель на новый
файл после проверки его содержимого чтением с Диска. Если загрузка прошла,
а ответ или транзакция потерялись, повтор запроса с уже подтверждённым
текстом безопасен. При прерванной загрузке на Диске может остаться файл,
который Rollapp не выбрал текущей версией.

При потере связи или конфликте черновик остаётся в редакторе и в хранилище
вкладки. Перезагрузка этой вкладки сохраняет исходную версию черновика.
Его можно скачать как Markdown даже при ошибке загрузки заметок. После
конфликта откройте свежую версию в отдельной вкладке и перенесите нужный
текст вручную. Закрытие вкладки может удалить локальный черновик.
Пилот поддерживает форматированный текст, таблицы и списки. Загрузка
изображений отключена. Доступ к папке можно отозвать в Яндекс ID.
Для повторного подключения выберите тот же аккаунт Яндекса.

## Включение

1. Зарегистрировать отдельное OAuth-приложение для пользователей. Запросить
   только `cloud_api:disk.app_folder` и зарегистрировать точный адрес
   `https://xn--80avakiab.xn--p1ai/api/private-notes/connection/callback`
   для production. Для изолированной локальной проверки использовать
   `http://127.0.0.1:5172/api/private-notes/connection/callback` и отдельное
   OAuth-приложение. Папки и подключения разделены по OAuth client ID.
   Сохранять действующий client ID после запуска пилота.
2. С отдельно подтверждённым изменением схемы применить
   [SQL для пилота](../scripts/sql/yandex-disk-notes.sql) к проверенной целевой
   базе. Настройка и запуск с `ROLLAPP_DATABASE_INITIALIZATION=verify`
   проверяют таблицу чтением. Обычный релиз схему не меняет.
3. Задать `YANDEX_DISK_OAUTH_REDIRECT_URI` и добавить `client_id` и
   `client_secret` в секрет Lockbox для runtime. Передать его идентификатор
   в переменную репозитория `YC_YANDEX_DISK_OAUTH_LOCKBOX_SECRET_ID`.
   CI передаст идентификатор в Compose и проверит `capabilities.privateNotes`
   после выпуска. Для локальной проверки можно
   задать `YANDEX_DISK_OAUTH_CLIENT_ID` и `YANDEX_DISK_OAUTH_CLIENT_SECRET`
   через защищённое окружение. Для токенов пользователей используется
   действующий `USER_CREDENTIALS_SECRET`.
4. До широкого включения проверить на выделенном аккаунте настоящий OAuth,
   права на папку, сохранение и чтение на втором устройстве, конкурентную
   правку, отзыв разрешения и повторное подключение к исходному Диску.
   Убедиться в появлении .md на Диске и в отсутствии текста в PostgreSQL.
   Если проверка не проходит, отключить конфигурацию OAuth пилота. Файлы
   пользователя остаются на его Диске.

## Проверки

`npm test` включает проверку разрешений OAuth, точной записи и чтения байтов,
ограничения размера и отказа от небезопасных ссылок на передачу файлов.
`npm run test:private-notes` проверяет состояния подключения и редактирования,
конфликт двух браузерных сессий, перезагрузку черновика, обрыв связи, повтор
сохранения и скачивание черновика на восьми размерах. Сценарий использует
изолированные данные и блокирует сетевые вызовы к API приложения.
