# Восстановление сайтов в Яндекс Клауде, 13 ноября 2026

Проверка прошла около 13:55–14:02 МСК. Рабочее дерево Rollapp было чистым на коммите `f55cce47e5718bc411f39cfc9436930deb152f23`. Версия в production по `/api/healthz` — `6b02ea31d7a5d66d4e87091f1f6555d0d112e59c`. Выкладки кода не было.

На момент восстановления Billing API показал активный платёжный аккаунт и положительный баланс. На четырёх публичных адресах исходная проверка обнаружила ошибку TLS или отсутствие ответа. Три домена возвращали 403 с сообщением об остановленном API Gateway, если пропустить проверку TLS. Виртуальная машина Студии была остановлена.

Состояние ресурсов подтверждено через `yc serverless api-gateway get` и `yc compute instance get`. Привязки доменов, сертификаты и записи DNS сверены через `yc` и `dig`. После возобновления шлюзов некоторое время встречались ответы 403 об остановленном шлюзе. В трёх последних сериях HTTPS-запросов с проверкой сертификатов все 90 запросов дали HTTP 200, по пять на домен в каждой серии.

Chrome через Playwright открыл все шесть страниц при ширине 1440 и 390 px. После ожидания данных Колосков.рф показал публикации на обеих ширинах. В финальном проходе браузер не зарегистрировал ошибок загрузки ресурсов с того же origin или исключений JavaScript. `curl` подтвердил HTTP 301 на канонический адрес Rollapp с www и служебного домена. `npm run dev:keepalive:status` из основного checkout подтвердил, что локальный Rollapp API, frontend и автовосстановление работают. В checkout аудита команда не запустилась из-за отсутствующей зависимости `dotenv`.

Проверка охватывала публичные страницы и формы входа. Авторизованные сценарии, содержимое защищённых лекций и генерация озвучки не проверялись. Схема и данные БД, DNS и конфигурация сайтов не менялись.
