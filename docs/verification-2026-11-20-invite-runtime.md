Рабочая версия при первой проверке `08dd7cb7bccb1f0674c839f2bb2bdef4a0f1ccb9`.
Локальная база исходников `a93a78b63321753e6ec23bbabc62c7eeeb7e38e9`;
рабочее дерево уже содержало правки панели «Инвайты».

- В рабочем Rollapp и Вишлисте `/api/auth/yandex/config` подтвердил включённый Яндекс ID. Локальное превью вернуло `enabled: false`.
- Настроенная production PostgreSQL проверена через READ ONLY. Найдены два действующих приглашения и два ранее принятых. Для последнего действующего приглашения рабочий сервер вернул HTTP 200 на проверке ссылки. Chromium показал «Создать с Яндекс ID» в окнах 390×844 и 1440×900. Последняя проверенная ссылка действовала до 30 ноября, 02:28 МСК.
- В WebKit и Chromium запрос из формы на `POST /api/auth/yandex/start` с синтетическим несуществующим токеном дошёл до рабочего сервера. Получены HTTP 403, `INVITE_INVALID` и соответствующее сообщение на форме. Этот сценарий проверяет доставку запроса и отображение ответа.
- На приложенном снимке из 02:03 МСК форма показывает ошибку транспорта `API_UNAVAILABLE`, которую клиент выводит при отклонённом `fetch`. Строки консоли на снимке касаются загрузки карт исходников. Публичный callback без состояния вернул ожидаемый `YANDEX_STATE_INVALID`.
- Callback с реальным согласием получателя и создание аккаунта остаются непроверенными. Получить журнал работающего контейнера не удалось: SSH разорвал соединение, Cloud Logging ответил `Unavailable`. Диагностика не отправляла письма, не создавала попыток OAuth и не расходовала приглашения.

## Повторная проверка после обновления рабочей версии

Корневой домен и Вишлист вернули один SHA `85317dee67df43f3cae2a4ce464befceca900dd1`. Серверные и браузерные проверки выполнены на чистой выгрузке этого SHA. Незакоммиченные правки панели в локальной ветке в проверку не вошли.

- Действующее рабочее приглашение открыло опубликованную форму «Создать с Яндекс ID» в WebKit на 390×844 и Chromium на 1440×900.
- Схема настроенной production PostgreSQL прошла штатный `verify` в READ ONLY. Поднятые на loopback обработчики рабочего SHA проверили существование и срок ссылки, PKCE и cookie попытки, отклонение callback без cookie и повторного state, сохранение приглашения при отсутствии email, создание личного аккаунта с другим адресом Яндекс ID, создание аккаунта продавца, вишлист, кошелёк, сессию, повторный вход и отказ при повторном использовании принятого инвайта.
- Обработчики использовали одно соединение PostgreSQL под внешним `BEGIN` → `ROLLBACK`, внутренние транзакции использовали `SAVEPOINT`. Фоновые службы и очистка истории входа были отключены в проверочном процессе. Ответы Яндекса при обмене кода и запросе профиля были тестовыми. После отката отдельный READ ONLY запрос подтвердил отсутствие тестовых аккаунтов, привязок, приглашений, сессий и OAuth-попыток.
- Все 18 целевых unit-тестов и 67 сценариев `npm run test:member-invites` прошли. Общий `test:ui` остановился на правиле текстовой кнопки с иконкой в `notification-drawer.jsx:99`.
- `npm audit` сообщил о 7 moderate и 2 high, `npm audit --omit=dev` о двух high через `@ton/ton` и Zod. npm не предложил совместимого исправления для этой ветки зависимости.
- Живой callback с согласием получателя остаётся непроверенным. Получить OAuth-конфигурацию из Lockbox для отдельной проверки страницы входа не удалось. Настроенный постоянный dev-сервис работает.
