# Страницы продавцов и предложения Wishlist

Для нового бизнес-аккаунта категории seller обязателен один sellerSpace:
products / places / events / media / food / transport. Категория и пространство
проверяются на сервере. Личные/другие бизнес-аккаунты не могут передать sellerSpace.
Существующие продавцы с NULL не получают backfill; они могут работать с каждым
пространством отдельно. Неизвестные значения не открывают доступ.

У продавца в Вишлисте и «Клиентах» есть «Моя страница»:
`/app/wishes/business?tab=<space>`. Владелец задаёт название, описание, публикацию
и добавляет товары и другие позиции. В редакторе отдельно показаны обложка,
основная информация и видимость. Обязательное поле — название. Доступны описание
до 4000 символов, бренд, цена с валютой и HTTP(S)-ссылка.
Поддерживается одна обложка JPG, PNG или WebP до 8 МБ. Выбор, замена, удаление и
предпросмотр происходят в форме. Загрузка в существующий image API начинается
при сохранении, сервер проверяет владение фото. Общий image-usage guard
удерживает используемые изображения.
Сохранение карточки оставляет несохранённые настройки страницы в форме. При
ошибке товар можно отправить повторно с теми же полями и обложкой. Повторный POST
с тем же requestId возвращает сохранённую карточку этого продавца в этом
пространстве. Правки к уже сохранённой карточке идут отдельным PATCH.
Выход с несохранёнными изменениями требует подтверждения.
Скрытый айтем и неопубликованная страница не попадают к покупателям.

Пункт «Объявления о продаже» в переключателе разделов открывает «Доску объявлений»
(`/app/classifieds`) в личном аккаунте и у бизнес-продавца. Она показывает все активные позиции владельца из
доступных ему пространств. В личном аккаунте это объявления из исполненных
желаний, отмеченные для публикации. Бизнес-продавец также видит активные
позиции ещё неопубликованной витрины с пометкой о её статусе. Скрытие позиции
убирает её с доски при следующем открытии. Из карточки можно перейти в нужный
раздел «Мои продажи» или в редактор витрины.
`GET /api/wishlist-business/classifieds` использует владельца из текущей
сессии и не кэшируется. Доска не меняет правила публикации и не требует миграции.

«Бренды» (`/app/wishes/catalog?source=brands&tab=<space>`) показывает аккаунты
продавцов выбранного пространства. Продавец с заданным `sellerSpace` появляется
в списке и меню сразу. Для прежнего продавца без `sellerSpace` принадлежность к
пространству определяет опубликованная витрина. Список ведёт в соответствующий
раздел публичного профиля. Авторизованный `GET /api/wishlist-business/:space/accounts`
возвращает имя, username, аватар и название опубликованной витрины при наличии.

Опубликованные страницы и активные позиции появляются в «Объявлениях продавцов»
(`/app/wishes/listings?tab=<space>`) и на публичной
витрине продавца. Фильтр бренда использует опубликованные позиции пространства.
Магазин `/app/store?tab=<space>` показывает только собственные товары роллаут.рф:
котов за роллы в products. Он не запрашивает ленту продавцов, в том числе по
устаревшим ссылкам с `business`; в остальных пространствах есть пустое состояние.
Цены авторских айтемов информационные; переход ведёт по ссылке продавца, автоматических
списаний/заказов эта функция не создаёт.

## Мои продажи

В «Моих продажах» (`/app/wishes/sales?tab=<space>`) кнопка «Добавить товар»
или «Добавить позицию» открывает редактор объявления в выбранном разделе.
Можно указать название, цену, описание, бренд, ссылку и загрузить обложку.
Новая карточка скрыта до явной публикации. Повтор сохранения после потери ответа
возвращает ту же карточку по ключу запроса, привязанному к владельцу и разделу.

### Продажа из исполненного желания

Владелец личного аккаунта или продавец с доступом к этому пространству открывает
меню исполненного желания и выбирает «Выставить на продажу». Редактор подставляет
название, описание и собственное загруженное фото, если оно есть. Цену и ссылку
на продажу владелец указывает в форме. По умолчанию карточка скрыта. Отмена
формы оставляет желание и продажи без изменений.

После включения «Опубликовать объявление» объявление личного аккаунта появляется
в объявлениях своего пространства. Покупатель может открыть переписку с продавцом
в Rollapp. У бизнес-продавца также нужна опубликованная витрина. Скрытие карточки
убирает её из списка объявлений. Исходное желание сохраняет статус «Исполнено» и свои
настройки видимости.

API продаж проверяет владельца и пространство. При создании из желания он также
проверяет его статус. Из одного желания создаётся одна карточка, в том числе при
повторной отправке после потери ответа. Дальнейшие изменения относятся к
объявлению. Существующие таблицы и image-usage guard обслуживают эти карточки
без миграции. Личные объявления не входят в список бизнес-аккаунтов.

Браузерный сценарий входит в `test:business-accounts`; откатная проверка маршрутов
на production PostgreSQL запускается через
`ROLLAPP_TEST_WISH_SALES=1 node --test server/wish-sales.integration.test.js`.

## Публичная витрина продавца

Публичный профиль бизнеса `/:username` и `/:username/:space` — витрина, а не личный
вишлист. Он показывает статус бизнес-аккаунта, опубликованные товары продавца и
существующие предложения за роллы. Пустой каталог продавца содержит текст «Товаров
пока нет»; второй пустой магазин и личные списки/желания под ним не выводятся.
Владелец видит «Управлять товарами» с переходом в существующий редактор своего
sellerSpace и «Клиенты». Без явного раздела профиль использует sellerSpace продавца;
явный раздел адреса сохраняется при чтении витрины. Прямые ссылки на прежние списки,
желания и shared-ссылки сохраняют прежние правила чтения и редактирования.
Обычный вход бизнеса в `/app/wishes` переводит на собственную публичную витрину;
допустимый `tab` сохраняется, без него используется sellerSpace или products.
Личный аккаунт продолжает открывать обычный Вишлист.

`GET /api/wishlist-business/:space/profiles/:username` доступен гостю и возвращает
только опубликованную страницу и активные товары конкретного seller-аккаунта в
разрешённом ему пространстве. Ответ не кэшируется. Он не открывает API управления,
списки покупателей, приватные желания или предложения. Публикация страницы и
товаров остаётся явным действием владельца в редакторе.

`npm run test:business-accounts` дополнительно проверяет настоящую композицию
публичного профиля: владелец, покупатель, гость, личный профиль, пустое состояние,
ошибка/повтор, переход в редактор, отмена без записи, обложка и предпросмотр,
скрытое сохранение, повтор при сбое загрузки и потере ответа, редактирование
и сохранение черновика настроек витрины. Та же проверка покрывает переход
на доску объявлений через переключатель, ошибку с повтором, длинные названия,
детали с возвратом, переход к нужной витрине и пустое состояние. Матрица:
320, 390, 768, 820, 1024, 1440, 1920 px и 390×400; реальные API запрещены.

Личный аккаунт покупателя открывает бизнесу конкретное пространство своего Вишлиста; наличие доступа к другим частным сферам для этого не требуется. Запросы отображаются и подтверждаются в выбранном пространстве. Права других сфер остаются прежними. Новые широкие разрешения
wishlist/wishlist запрещены; существующие сохранены без переноса. В выборе бизнеса
старое широкое разрешение явно подписано и может быть отозвано. Категория/раздел
проверяются при запросе, одобрении, прямом предоставлении, чтении частного профиля
и деталей; публичная видимость сохраняет прежние правила. При частичном разрешении
приватные желания из других пространств в API-ответ не попадают.

Продавец открывает собственный опубликованный айтем → выбирает покупателя из
аккаунтов, предоставивших соответствующее разрешение → «Предложить». Сервер в
транзакции повторно проверяет владение, публикацию, активность, личный тип покупателя
и действующее согласие. Строки согласия блокируются FOR SHARE до фиксации.
UNIQUE(item_id,buyer_user_id) предотвращает дубликаты и повторное появление после
отклонения. Нельзя подставить чужой айтем или покупателя без разрешения.

Покупатель видит айтем в «Предложениях» соответствующего пространства:
`/app/wishes/offers?tab=<space>`; кнопка рядом с магазином. На странице предложений
нет отдельной кнопки «Назад» и видимого заголовка «Предложения · Пространство»;
контекст сохраняется в общей шапке и доступном имени секции. Это отдельный список
рекомендаций, без автоматической записи в подтверждённые желания. Покупатель
открывает детали/страницу продавца/внешнюю ссылку либо отклоняет предложение.
Чтение предложений каждый раз проверяет действующее согласие, категорию продавца,
публикацию и активность. Отзыв доступа скрывает предложение при следующей загрузке.
Отклонение ограничено текущим покупателем и пространством; продавец не может его сбросить.
API/ошибки не заменяются демо-данными. Частные API отвечают no-store.

## Схема и выпуск

Отдельная разрешённая миграция:
`node scripts/migrate-wishlist-business.mjs --apply`.
Без --apply команда только проверяет настроенную production БД, роль, наличие
users.seller_space и трёх таблиц. Добавляются nullable поле с CHECK и пустые
wishlist_business_pages / wishlist_business_items / wishlist_business_offers,
FK, UNIQUE и индексы. Не выполняются backfill/удаление/публикация чужих данных.
lock_timeout 5s, statement_timeout 20s, одна транзакция, pool1.
Обычный startup/release использует verify: LIMIT0 в READ ONLY, без миграций.
Production Compose сохраняет pool2; preview pool1/TLS.

Кнопки/формы составлены из существующих PageActionButton, ControlBar, Drawer,
MobileFormScreen/MobileFormFooter, Field, Select и общих layout/grid ролей.
Шапка остаётся прозрачной; новые CSS-размеры/типографика не вводятся.
