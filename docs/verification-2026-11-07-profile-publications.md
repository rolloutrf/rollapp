# Календарь записи и доска объявлений профиля

Проверка 7 ноября 2026 года. Ветка `codex/profile-session-publications` перенесена с исторической базы `f55cce47` на `origin/main` (`ed696ed6eb13cdee6442d153d13601f8e8e7bd57`). При проверке рабочее дерево содержало изменения функции. Node 22.22.3.

## Поведение

- В профиле доступны `/:username/calendar` и `/:username/announcements`. Владелец может открыть их также со своего вишлиста.
- В календаре публикуются отдельные интервалы записи. Время отображается в часовом поясе посетителя. Для записи требуется вход в Rollapp. Свободные слоты видны посетителям профиля, занятый слот доступен владельцу и записавшемуся участнику. Только владелец получает имя записавшегося участника.
- Публикация проверяет пересечения интервалов под блокировкой владельца. Запись сериализуется блокировкой слота и защищена уникальностью `slot_id`. Отмена привязана к идентификатору конкретной записи, чтобы повтор старого запроса не затронул новую запись.
- Владелец публикует, редактирует и удаляет объявления. Посетители читают опубликованный текст. Управление товарными карточками витрины продавца остаётся отдельным сценарием.

## Production

Текущий production health подтверждает базовый SHA `ed696ed6eb13cdee6442d153d13601f8e8e7bd57`. Полная проверка, сборка и развёртывание этой базы прошли в [GitHub Actions](https://github.com/rolloutrf/rollapp/actions/runs/42376464466). Этот результат относится к базе до изменений календаря записи и доски.

`node scripts/profile-publications-schema.mjs` по TLS проверил базу `rollapp`, роль `rollapp_app` и схему `public`. Все три таблицы отсутствуют. Скрипт по умолчанию проверяет схему в транзакции READ ONLY. У роли есть права на создание таблиц и ссылку на `users.id`. Dev-сервис ветки оставлен запущенным в режиме `verify`.

Через production API в локальном превью проверены обе ссылки и возврат с клавиатуры на восьми размерах. Существующий профиль загружается, а оба новых раздела возвращают 503 с сообщением «Раздел пока недоступен» до создания таблиц. Живая проверка выполнялась чтением.

После отдельного согласия запустить `node scripts/profile-publications-schema.mjs --apply`. Миграция создаёт `profile_session_slots`, `profile_session_bookings`, `profile_announcements` и индексы. Затем повторить скрипт без `--apply` и выполнить `npm run test:profile-publications:production`. Интеграционный тест использует реальные обработчики и настроенный production PostgreSQL. Проверяет повтор записи, отказ для занятого слота, изоляцию прав, отмену и доску в одной транзакции с откатом. Полный auth-flow и конкуренция двух отдельных DB-сессий выходят за рамки этого теста.

После проверок выпустить из актуальной основной ветки и сверить SHA production health и живые экраны. Миграция и развёртывание пока ожидают.
