# Подарочные карты бизнеса

Профиль бизнеса открывается по обычному публичному адресу `/:username`, в том числе из имени и аватара продавца в карточке предложения. Непосредственно под аватаром профиля находится круглый значок подарка в `ControlBar`. Гостя он ведёт на вход с возвратом в профиль. Публичный профиль показывает активные предложения этого бизнеса.

Карта выпускается с нулевым балансом. Владелец пополняет её целыми роллами со своего обычного кошелька, затем выбирает получателя поиском по имени или username. Получателю нужен аккаунт Rollapp. Отправленная карта целиком переходит получателю, появляется в разделе «Подарочные карты» его кошелька и исчезает у отправителя. Текущий владелец может пополнить или передарить карту. Из кошелька открывается именно выбранная карта; если она больше недоступна, другая карта автоматически не подставляется. Банковская карта, платёжный шлюз и покупка валюты в этом сценарии не используются.

Баланс карты хранится отдельно и не становится обычными роллами получателя. В подтверждении покупки можно выбрать обычный баланс или одну из собственных карт именно этого бизнеса; недостаточно пополненные карты недоступны для выбора. Доплата из другого источника не выполняется. Возврат восстанавливает баланс исходной карты, даже если её уже передали дальше. Обналичивание, перевод с карты в обычный кошелёк и срок действия не предусмотрены.

Пополнение списывает кошелёк и зачисляет карту в одной серверной транзакции; покупка списывает карту и записывает заказ в одной транзакции. Все изменения имеют журнал `business_gift_card_events`. Оплаты картой хранят неизменяемый снимок заказа в этом журнале, а возвраты ссылаются на оплату через `purchase_id`; уникальный индекс разрешает только один возврат. Эти заказы не записываются в `roll_store_purchases`, поэтому прежняя версия сайта, которая возвращает обычные заказы на обычный кошелёк, не может обойти ограничение карты. Новый `/rolls/orders` объединяет обычные заказы и собственные оплаты картами без раскрытия заказов следующему владельцу карты. Пополнения также видны в обычной истории роллов. Блокировки берутся в порядке «кошелёк → карта»; покупка после кошелька блокирует предложение. Сервер проверяет владельца, бизнес, положительную целую сумму, достаточный баланс и лимит карты 1 000 000 000 роллов. Передача не начисляет обычные роллы получателю.

Клиент сохраняет запрос с UUID в sessionStorage перед отправкой. При неизвестном результате блокирует изменение операции и повторяет тот же запрос. Сервер сравнивает его параметры и не списывает повторно. Повтор отправки работает после смены владельца, повтор покупки — после изменения цены или снятия предложения. Данные запросов разделены по аккаунтам. Ошибка загрузки не подменяется нулевым балансом или демонстрационными картами.

Мобильная форма использует `form-surface` / `MobileFormPages`, один скроллер документа и общий нижний ряд Back + primary. Настольная форма открывается справа; заголовок и `DrawerFooter` находятся вне прокручиваемого тела. Выпуск ещё одной карты и повтор загрузки находятся в содержимом, чтобы не перегружать нижний ряд. Размер и скругление действий принадлежат `ControlBar`.

## Отдельное обновление схемы

`server/gift-cards-schema.js` добавляет только две таблицы и их индексы (включая снимок оплаты и ссылку возврата внутри нового журнала). Production startup и обычный релиз сохраняют `ROLLAPP_DATABASE_INITIALIZATION=verify`: новая схема не создаётся при перезапуске приложения. Если таблиц нет, API карт отвечает 503 с `GIFT_CARDS_UNAVAILABLE`; обычный кошелёк продолжает работать без выдуманной истории карт.

Проверка настроенной production-базы без изменений:

```sh
node scripts/gift-cards-schema.mjs
```

Только после отдельного явного разрешения пользователя и сверки целевой базы/роли:

```sh
node scripts/gift-cards-schema.mjs --apply --database=rollapp --role=rollapp_app
npm run test:gifts:production
```

Миграция работает в транзакции с ограничениями ожидания блокировок и времени запроса, не изменяет пользователей, остатки или старые операции. Production-тест не инициализирует схему; все временные пользователи, предложения и операции выполняются внутри BEGIN → ROLLBACK. Он проверяет полный цикл, ограничения бизнеса и владельца, повтор после снятия предложения, возврат после передаривания и отсутствие второго списания. Он также проверяет обычную покупку/возврат и сохранение общей суммы обычных и карточных остатков на каждом этапе. Это не проверка параллельных запросов с разных соединений.

`node scripts/grant-welcome-rolls.mjs` без `--apply` выполняет сверку без записи: учитывает обычные и карточные остатки, пополнения карт, оплаты/возвраты и оплаченные Stars/TON-начисления в роллах. Проверяет как общую сумму, так и соответствие каждого карточного остатка журналу.

## Проверки

`npm test` включает тесты валидации, владельца, баланса, повторов, ограничения бизнеса и возврата в исходный источник. `npm run test:gifts` входит в `check:release` и использует реальные компоненты с явным UI transport, блокируя сетевые API. Проверяет восемь размеров формы, настоящую композицию публичного бизнес-профиля на семи ширинах, гостевой вход, ошибки, выпуск, пополнение, потерянный ответ, отправку, способ оплаты, геометрию футера и отсутствие горизонтального переполнения.
