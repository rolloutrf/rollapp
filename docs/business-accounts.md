# Категории бизнес-аккаунтов

Количество бизнес-аккаунтов при регистрации не ограничено. Номера участника
доступны личным аккаунтам.

Для регистрации нового личного или бизнес-аккаунта нужна ссылка, отправленная
владельцем `@koloskof` из раздела «Инвайты» на конкретный email. Ссылка
действует 10 дней и даёт создать один аккаунт через Яндекс ID с этим адресом.

При регистрации выбор «Бизнес» показывает обязательное поле «Категория бизнеса». Категория не выбрана заранее. Переключение на личный аккаунт очищает её. Сервер отклоняет бизнес-регистрацию без известной категории и личную регистрацию с категорией. Выбранный тип аккаунта и параметры бизнеса сохраняются при завершении регистрации через Яндекс ID.

| Категория | Ключ | Сфера клиента |
| --- | --- | --- |
| Психолог / Коуч | `psychologist-coach` | Идентичность |
| Доктор | `doctor` | Здоровье |
| Продавец | `seller` | Вишлист |
| Преподаватель | `teacher` | Образование |
| Карьерный консультант | `career-consultant` | Карьера |

Источник соответствий — `shared/modules/catalog-marketplace/business-accounts.js`. Сфера «Карьера» включает существующее пространство контактов с совместимым storage scope. Категория хранится в nullable `users.business_category`. API входа и чтения сессии возвращает её в `user.businessCategory`.

Продавец выбирает раздел Вишлиста при регистрации. Значение сохраняется в
`users.seller_space`. Категория и раздел определяют, в каком каталоге появляется
бренд и какие предложения он может отправить. Продавец с прежним значением NULL
может работать в нескольких разделах.

На карточке бренда кнопка «Открыть потребности» разрешает этому бренду
читать активные потребности покупателя и присылать ему предложения.
«Закрыть потребности» отзывает оба разрешения. Обычный клик по карточке
открывает профиль, Ctrl+клик переводит фокус на кнопку. Согласие хранится
отдельно от подписок и прав личных разделов.

Новые права чтения личных сфер и запросы на них прекращены. Устаревшие
эндпоинты создания отвечают HTTP 410. В меню бренда можно отозвать ранее
выданные права текущего раздела. Старое право на весь Вишлист отзывается
отдельным действием. В «Клиентах» остаются предложения и ссылки на ранее
открытые разделы. Публичный Вишлист использует правила публичного чтения.

Страницы продавцов и карточки покупателя описаны в [документе Вишлиста](wishlist-business.md).

## Отдельная операция схемы перед выпуском

Обычный startup/release остаётся в `ROLLAPP_DATABASE_INITIALIZATION=verify`. Он проверяет `users.account_type,business_category` в READ ONLY транзакции; отсутствие столбца останавливает запуск без миграции или demo fallback.

`npm run business:categories:migrate` использует настроенный production PostgreSQL, проверяет совпадение database/role/таблицы `users` и наличие столбца без изменений. TLS используется по умолчанию; SSH-туннель — только при `ROLLAPP_DATABASE_CONNECTION=tunnel`.

Только после отдельного явного разрешения выполнить `npm run business:categories:migrate -- --apply`. Команда в одной транзакции с `lock_timeout=5s` и `statement_timeout=15s` добавляет nullable столбец с ограничением известных категорий и типа аккаунта. Она не запускает общую инициализацию, не меняет существующие аккаунты/разрешения и не делает backfill. Затем повторить проверку существующей схемы и проверить новую регистрацию/вход в согласованном режиме перед rollout.

## Проверки

`npm test` проверяет обязательность категории, тип аккаунта, все соответствия сфер/разделов, legacy-аккаунты и отказ для неизвестных значений.

После отдельно разрешённой миграции `npm run test:business:production` проверяет на точной настроенной production-БД сохранение пяти категорий и ограничения столбца внутри `BEGIN` → `ROLLBACK`. Сценарий не инициализирует схему, не создаёт сессии/кошельки/запросы и проверяет отсутствие временных аккаунтов после отката. Он дополняет, но не заменяет реальную проверку регистрации/входа.

`npm run test:business-accounts` проверяет реальные компоненты выбора типа/категории и пространства на 320, 390, 768, 820, 1024, 1440, 1920 px и 390×400: обязательность, сброс категории, сохранение остальных полей, keyboard/cancel, пять категорий, прямую кнопку, Ctrl+клик, согласие и отзыв, геометрию, прокрутку и отображение прежних прав. Это presentation-проверка без API/БД: все API-запросы запрещены. Сохранение категории в production требует отдельной проверки после разрешённой операции схемы. Проверка входит в `check:release` и `check:comprehensive`.
