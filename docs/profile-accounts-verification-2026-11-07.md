# Проверка переключения аккаунтов — 7 ноября 2026

База проверки: `f55cce47e5718bc411f39cfc9436930deb152f23`. Рабочая копия
при старте была чистой; проверка выполнялась с незакоммиченными изменениями
функции. Версия в production не менялась.

- `npm run test:accounts` — пройдено. Chrome: 320×568, 390×844, 390×400,
  768×900, 820×900, 1024×768, 1440×900, 1920×1080. Проверены видимый активный
  аккаунт, длинные имена, геометрия, возврат из формы, ошибка списка и повтор,
  неверный пароль, успешное добавление, переключение обратно, отказ устаревшей
  записи, защита черновика профиля, удаление сохранённого входа и выход.
  Скриншоты 390×844 и 1440×900 просмотрены. Тест не обращался к реальному API.
- `npm run test:accounts:production` — пройдено на настроенной PostgreSQL.
  Тест проверил чужую и истёкшую сессии, cookie с прежним сроком, смену активного
  аккаунта, отказ запроса от старого аккаунта, отзыв сохранённого входа и выход.
  Все тестовые строки откатились; миграции и очистка данных не выполнялись.
- `npm run test:unit` — 792 пройдено, 1 штатно пропущен (интеграция TON).
  `npm run test:ui`, `npm run test:navigation`, `npm run test:form-pages`
  и `npm run build` — пройдены.
- `npm run check:comprehensive` запущен; на момент отчёта прошли unit,
  UI, controls, details, dates, calendar и form actions. Матрица редактора
  и последующие этапы ещё не завершились. Результат команды пишется в
  `/tmp/rollapp-eb09-account-check.json`. Новый профильный тест выполнен
  отдельно, поскольку общий прогон запущен до включения этого теста в матрицу.
- `npm run dev:keepalive:status` — при живой проверке API и Vite были готовы на отдельных портах,
  PostgreSQL подключена напрямую по TLS; startup подтвердил схему без записи.
  В реальном браузере на 390×400 и 1440×900 неавторизованный посетитель возвращается
  с добавления аккаунта к обычному входу. Анонимные запросы списка и переключения
  возвращают 401. При последующем перезапуске были повторные отказы Yandex CLI
  Lockbox; автозапуск оставлен включённым. Прямой тест БД прошёл.
- `npm audit` — 11 advisories (2 low, 5 moderate, 4 high);
  `npm audit --omit=dev` — 3 high (body-parser, Vite, Zod).
  Это результаты для неизменённого lockfile. Замена зависимостей в эту задачу
  не входила.

Найдена и исправлена ошибка мобильного профиля: его форма находилась вне
`MobileFormPages`. Смена аккаунта перезагружает страницу, а старый клиент
указывает ожидаемый аккаунт в API-запросе, чтобы сервер не применил его
правку к новому аккаунту.

Реальные входы двух пользовательских аккаунтов, доставка SMS, полный переход
через Яндекс OAuth и Telegram WebView не проверялись. Браузерный тест проверяет
ссылку добавления через Яндекс; unit проверяет состояние OAuth и выбор аккаунта.
