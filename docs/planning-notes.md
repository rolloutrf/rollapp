# Заметки

«Заметки» — четвёртый пункт общего меню планирования. Адрес списка:
`/app/planning?tab=notes`, документа — `?tab=notes&note=<id>`.
Из открытой заметки нижняя стрелка в общем ControlBar возвращает к сетке.
Из сетки эта стрелка возвращает в приложение. Сетка и документ используют один
нативный document scroller, общие page/container/типографические токены и нижний
резерв для навигации. Заметки не используют ограниченный по высоте board layout.
До 768 px сетка и открытая заметка начинаются у верхней безопасной границы
экрана с общим зазором 8 px. На широком экране начало определяется общей шапкой.

Создание с чистого листа добавляет пустую заметку «Без названия». Документ открывается
после успешного ответа сервера. Заметки упорядочены по последнему изменению.
Название редактируется через InlineTextField (до 200 символов), текст — через
общий EditableTextBlock / InlineRichTextEditor (до 200 000 символов). Все текущие
возможности общего редактора доступны без отдельной реализации форматирования,
блоков, таблиц, столбцов и изображений. Его ограничения также сохраняются.

Название и canonical Markdown образуют один snapshot и одну очередь
useDocumentDraft/useInlineAutosave. Подтверждение сервером не заменяет более
новый ввод. Черновик хранится по владельцу и id заметки; ошибка записи оставляет
текст и явный повтор. Blur, Ctrl/Cmd+S и уход со страницы вызывают общую очередь.
Пустое название на сервере нормализуется в «Без названия». Ошибка загрузки не
создаёт пустой редактор, есть повтор. Ответ старого загрузчика не меняет новый
документ. Позднее создание не перенаправляет пользователя после ухода из раздела.
Новая навигация необратимо отменяет право позднего создания открыть документ,
включая возврат browser Back к исходной history entry. Уже подтверждённое
удаление завершается на сервере, но не меняет текущий маршрут после ухода из
его редактора. Ошибки старой операции также не появляются в новом документе.

Кнопка удаления расположена справа от заголовка в общей строке ControlBar.
Удаление требует подтверждения и дожидается очереди сохранения. Ошибка оставляет документ
доступным. Существующие изображения после удаления заметки не удаляются из
хранилища: они могут использоваться другими документами. Защита удаления медиа
проверяет owner-scoped ссылки в planning_notes и при ошибке запроса fail closed.

## Хранение и ввод в эксплуатацию

API `/api/planning/notes` и `/:id`: список, создание, чтение, полное обновление
 title/content и удаление. Все операции требуют сессию и используют только
`req.user.id`; query owner не открывает чужие заметки. Список не отдаёт содержимое
всех документов. Ответы чтения/сохранения имеют private/no-store. Для заметок
JSON body limit 2 MiB допускает Unicode и JSON-экранирование полного документа;
общий лимит остальных JSON API остаётся 256 KiB.

Отдельная таблица planning_notes содержит id, user_id (FK users ON DELETE CASCADE),
title, content, created_at и updated_at. Индекс: user_id/created_at/id.
Она не переиспользует задачи, профиль или чужие текстовые разделы.

Обычный startup/release с initialization=verify проверяет существующие колонки
в READ ONLY транзакции; не создаёт таблицу. **Перед первым запуском новой версии
необходимо отдельно разрешить и применить additive migration.**

`node scripts/migrate-planning-notes.mjs` проверяет точную настроенную production
базу и роль и только читает наличие таблицы. После отдельного разрешения:
`node scripts/migrate-planning-notes.mjs --apply`. Эта команда создаёт только
таблицу/индекс, проверяет колонки в той же транзакции; не меняет существующие
пользовательские записи. Lock timeout 5s, statement timeout 15s. Полный schema
initializer и backfill запускать ради заметок не требуется.

## Проверка

`npm run test:notes` входит в check:release. Восемь размеров: 320×740, 390×844,
768×1024, 820×414, 1024×768, 1440×900, 1920×1080 и 390×400. Реальные компоненты
и CSS получают несохранённые presentation props; любые реальные API запросы
запрещены. Проверяются меню/переходы, ввод/название/автосохранение/переоткрытие,
ошибка и повтор, задержанная очередь, удаление/отмена, empty/create/load-error,
48px controls, отсутствие рамки редактора и доступность конца страницы.
Это UI fixture, не замена production БД и не доказательство live persistence.
Модельные route tests проверяют auth/owner predicates, validation, whitespace,
ошибки хранилища и защиту media references. Общая регрессия редактора:
`npm run test:text-edit`; настоящие iOS/Telegram IME остаются отдельной проверкой.

После первоначальной отдельно разрешённой миграции выполнить
`npm run test:notes:production`: реальные HTTP CRUD и PostgreSQL в одной
rollback-only транзакции. До любых тестовых INSERT проверяются существующие
колонки planning_notes. Тест не содержит DDL и не инициализирует схему.
Созданные пользователи, сессии и заметки откатываются; после ROLLBACK отдельно
проверяется отсутствие тестовых записей. Проверяются anonymous 401, чужие
GET/PATCH/DELETE 404 (включая owner query), canonical text без trim, список без
полного содержимого, empty title, валидация, 200 000 кириллических символов через
реальный JSON parser и owner-scoped media guards. Отсутствующая таблица — FAIL
без перехода на demo/mock/local БД.

`npm run test:notes:production:ui` добавляет native Chrome проход по настоящему
dev приложению на тех же восьми размерах (включая 390×400). Сессия и notes API
перенаправляются в тот же HTTP сервер с настоящей production транзакцией;
никакой подмены client/ответов данных нет. Все прочие API запрещены. Проверяются
реальный PlanningSpace/AppShell/навигация, создание, native текст/жирный стиль/
чек-лист, autosave, browser reload, переоткрытие и delete/cancel. Нужен готовый
keepalive; по умолчанию используется ROLLAPP_DEV_FRONTEND_PORT, при необходимости
NOTES_TEST_BASE_URL. Тестовые пользователи/сессии/заметки остаются внутри общей
rollback-only транзакции; схема не создаётся. Снимки:
`/tmp/rollapp-notes-production-<width>-<height>.png`.

## Сетка заметок

Страница начинается с сетки, в которой есть плитка «Пустой документ» и сохранённые заметки.
На телефоне две колонки, на более
широких экранах число колонок зависит от доступной ширины. Сетка переносит
плитки на следующую строку и прокручивается вместе со страницей.

Сетка использует общий page-width, открытый документ — document-width.
Плитка заметки — ссылка, плитка создания — кнопка. Длинное название заметки
занимает до двух строк; полное название остаётся в accessible name и title.
Даты берутся из API. В пустой библиотеке остаётся плитка создания. При
загрузке или её ошибке она недоступна.

`test:notes` дополнительно проверяет порядок и геометрию единой сетки,
создание пустой заметки, отложенную загрузку, блокировку создания и 14 заметок
с длинными названиями. Последняя плитка прокручивается выше нижней навигации.
