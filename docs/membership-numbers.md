# Номера Rollapp и TON

В «Настройки профиля → Инвайты» авторизованный пользователь создаёт ссылку,
копирует её или открывает системное меню «Поделиться». Инвайт даёт право
создать один аккаунт в течение 10 × 24 часов. Ранее выданные ссылки сохраняют
свой срок, указанный при выпуске. Действующая ссылка сама по себе не занимает место.

При регистрации пользователь запускает барабан. Номер приходит с сервера после
создания аккаунта; на экране меняются только цифры анимации. Первый вход через
Яндекс ID использует тот же пул и показывает результат после возвращения от
провайдера. Внутренний UUID и существующие ссылки профиля сохраняются.

База один раз случайно перемешивает 30 000 мест. Транзакция создания аккаунта
забирает первое свободное место в этом порядке. Все уже существующие аккаунты
учитываются. После удаления аккаунта номер остаётся занятым, а использованная
ссылка не открывается повторно. Полный пул возвращает `MEMBERSHIP_FULL`.
Нумерация и создание квитанции откатываются вместе с регистрацией.

Новый аккаунт сразу получает запись в очереди TON. Внешний запрос идёт из
отдельного кошелька Rollapp Wallet V4R2 в основной сети TON. Тело внутреннего
сообщения на этот же адрес содержит 32-битный тег `0x524c4d31` (RLM1) и
SHA-256 сохранённой квитанции. Номер, имя, email, токен и UUID в сеть не уходят.
Квитанция доступна владельцу в «Инвайтах». Для проверки можно сравнить
SHA-256 скачанного файла с последними 32 байтами тела сообщения. Квитанция
содержит случайный nonce и хеш, связывающий её с внутренним ID.

Статус меняется на «подтверждена» только после чтения успешной транзакции с
тем же подписанным запросом и нужным исходящим сообщением. До этого показывается
ожидание. Регистрация не ждёт сеть TON. При сбое отправки очередь повторяет
тот же подписанный запрос. Если seqno увеличился, а провайдер не показывает
исходную транзакцию, новые подписи приостанавливаются до сверки истории
кошелька. Храните рабочий ключ доступным для разбора этой очереди и не
используйте кошелёк для других операций.

## Активация

1. Проверить цель через `npm run membership:migrate`. Эта команда работает в
   режиме чтения. После отдельного разрешения выполнить
   `npm run membership:migrate -- --apply` на проверенной базе Rollapp.
   Миграция транзакционная; она блокирует запись в таблицу пользователей на
   время назначения номеров и установки триггера. Обычный запуск её не выполняет.
2. Подготовить отдельный, уже развёрнутый и инициализированный кошелёк V4R2
   основной сети с seqno ≥ 1 и балансом на комиссии. Хранить 24 слова только
   в Yandex Lockbox, в поле `mnemonic`. Сервисной учётной записи VM нужен
   доступ к этому секрету. Не использовать платёжный кошелёк Rollapp.
3. Включить переменную выпуска `ROLLAPP_MEMBERSHIP_ENABLED=true` и задать
   `ROLLAPP_MEMBERSHIP_TON_ADDRESS`, `YC_MEMBERSHIP_TON_LOCKBOX_SECRET_ID`.
   Контейнер проверяет схему, совпадение адреса и подписывающего ключа.
   Деплой проверяет версию и `capabilities.membershipNumbers`.
4. После миграции запустить `npm run test:membership:production` на
   настроенной базе. Он проверяет нумерацию, неудачную вставку, повтор инвайта
   после удаления и целостность квитанции в откатываемой транзакции.
   Отдельно проверить получение первой реальной транзакции TON.

Локальные проверки: `npm run test:membership` (браузер), `npm run test:profile`
(инвайты), `npm run test:business-accounts`, `npm run test:unit` (подписи и
обработка ответов TON). Для отката приложения сохранить таблицы и триггер:
удаление реестра нарушит уникальность ранее выданных номеров.
