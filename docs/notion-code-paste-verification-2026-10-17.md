## Исправленные находки

- Текст с Markdown-префиксом внутри inline code мог создавать другие блоки.
  Теперь текстовое выделение в одном текстовом блоке со строчным code получает буквальный
  `text/plain`, включая случай, когда буфер также содержит HTML. LF, табы,
  пробелы, marks назначения и соседний текст сохраняются; CRLF/CR становятся LF.
- Дополнительные Tiptap paste rules повторно превращали `**…**` в жирный текст
  уже после буквальной вставки. Эта вставка больше не запускает второй Markdown
  проход и имеет собственный шаг Undo/Redo, отдельно от предшествующего набора.
- Обычный codespan serializer превращал `line1\nline2` в `line1 line2`, терял
  whitespace-only code и выносил крайние пробелы/табы за пределы marks.
  Для таких случаев используется существующий безопасный rich-inline HTML.
  Добавлено 48 точных round trips: восемь строк в paragraph, heading,
  typography block, list, table cell и toggle title.
- В опубликованном чтении inline code использует `white-space: pre-wrap`.
  Проверяются текст, вычисленный стиль и реальная высота переносов; формат
  не восстанавливается только номинально в JSON при визуально слитых строках.
- Slash внутри code больше не открывает команды. Выбор целых блоков отделён
  от текстового выделения: вставка группы code-абзацев не склеивает их.
- Сохранены обычные Markdown/HTML paste и буквальная вставка в code block.
  Ввод по-прежнему происходит на странице; рамки вокруг прозы не добавлялись.
