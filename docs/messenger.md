# Личные сообщения Rollapp

`/app/messenger` и `/app/messenger/:conversationId` открывают штору
со списком или выбранным разговором поверх домашней страницы. Кнопка над
планированием открывает ту же штору поверх текущей страницы. На компьютере
она выезжает справа, на телефоне — снизу. Список и чат показываются по очереди.
Стрелка в чате возвращает к списку. Крестик, Escape, жест и клик по фону
закрывают штору. Иконка над планированием использует общий 48px ControlBar
и промежуток 8px.

Список при открытии показывает существующие диалоги, затем все подписки,
с которыми ещё нет диалога. Контакты с диалогом представлены в списке один раз.
Поиск охватывает всех зарегистрированных участников по имени или username.
Открытие контакта создаёт диалог по требованию.

## Ассистент Rollapp

Круглая кнопка над «Сообщениями» открывает ассистента в той же шторке поверх
текущего раздела. Крестик, Escape, жест и клик по фону закрывают шторку.
Фокус возвращается на кнопку ассистента. Прямой адрес `/app/assistant`
открывает шторку поверх домашней страницы аккаунта.
В пустом чате все доступные пресеты идут подряд в области сообщений и переносятся по ширине окна.
Список прокручивается вместе с чатом. Меню «Пресеты запросов» рядом с «Новым чатом»
доступно и в начатой беседе. Выбранный пресет
вставляет текст в поле ввода, добавляя отдельный абзац к существующему черновику. Пресет разбора открытой заметки доступен при пустом поле ввода.
Пользователь может изменить текст перед отправкой. См. [каталог сценариев UI SDK](assistant-ui-sdk-scenarios.md).
В меню есть сценарии для вишлиста, планирования и заметок. Для аккаунтов с
доступом также видны «Идентичность», «Здоровье», «Образование» и «Карьера».
Один запрос может подготовить до трёх отдельных черновиков, например заметку
с итогами и две задачи. Каждый черновик проверяется в штатной форме.
Без личного ключа используется Alice AI LLM Flash
в Yandex AI Studio, оплачиваемая Rollapp. Личные ключ и модель OpenRouter из настроек
профиля получают приоритет. При нехватке средств или пустом ответе OpenRouter ассистент один раз
повторяет запрос через Yandex, если он настроен. Если Yandex отключён, поддерживаются прежние
серверные настройки OpenRouter. Подключённая модель должна
поддерживать вызов функций. При ошибке черновик остаётся в поле ввода.

При каждом открытии ассистента показывается список чатов с теми же строками
и переходами, что в «Сообщениях». Первая строка «Новый чат» открывает отдельную
беседу. Пустая беседа без черновика не появляется в списке. После первого
запроса её имя берётся из текста сообщения. Под именем показываются последнее
сообщение, черновик или состояние запроса, включая новый ответ и ошибку.
Стрелка «Все диалоги» возвращает к списку. У каждого чата своя история и черновик.
Пока ассистент отвечает в одном чате, можно отправить
запрос из другого, закрыть шторку или перейти в другой раздел Rollapp. Ответ приходит в беседу,
из которой был отправлен запрос. В одной беседе одновременно выполняется один
запрос.

Чаты и черновики остаются в памяти текущей вкладки при переходах по страницам.
При перезагрузке или смене аккаунта они очищаются, а незавершённые запросы отменяются.

Поле ассистента использует общую конструкцию To Do. Текст находится сверху
в единой скруглённой панели, внизу слева расположен микрофон, справа — стрелка
отправки. Панель остаётся под прокручиваемой историей. При открытой клавиатуре
на телефоне текстовая область занимает 48 px, а длинный черновик прокручивается внутри неё.

Кнопка микрофона и пробел вне поля ввода и других интерактивных контролов
включают и останавливают диктовку на русском. Готовые фразы добавляются в конец
черновика. Отправка доступна после завершения диктовки и требует отдельного
действия. При переключении чата или закрытии шторки микрофон останавливается. Распознавание
обеспечивает браузер, который может обрабатывать аудио через собственный
сервис. При отсутствии поддержки или разрешения доступен ручной ввод.
[Спецификация Web Speech API](https://webaudio.github.io/web-speech-api/).

В пустом поле нового чата серым показан пример сообщения. Tab вставляет его как
редактируемый черновик. Shift+Tab и последующий Tab продолжают перемещать фокус.
В поле ввода ассистента работают Ctrl/Cmd+Enter и ограничение в 4000 символов.
Под кнопками появляются только состояния диктовки, включая ошибку и отсутствие
поддержки браузером.

Ассистент предлагает открыть доступные разделы Rollapp и готовит черновики задач
To Do, событий календаря и заметок. Ссылка открывает нужный экран, а черновик
заполняет обычную форму, где можно изменить поля, сохранить или отменить.
Создание записей выполняют обычные формы по подтверждению пользователя.
При отмене черновик остаётся доступен из чата. Задача без заданной даты
открывается на текущем дне с пустым временем. В событии сохраняются предложенные
местные дата, время и длительность.

В чате ассистента кнопка «Добавить желание» вставляет пример запроса.
После отправки модель может вернуть действие `draft_wish`. Карточка ответа
показывает предложенные название, цену и список. Кнопка «Проверить желание»
вызывает `openDraft` через Vercel UI SDK и открывает обычную форму вишлиста.
Черновик также может передать HTTP(S)-ссылку из сообщения пользователя. Форма
подставляет доступные данные товара и сохраняет переданные в черновике значения
названия, описания и цены. Идентификатор списка определяет Rollapp
по точному имени среди списков текущего аккаунта. Если совпадений нет или их
несколько, форма показывает это и позволяет выбрать список вручную. Отмена
возвращает к тому же чату. Создание записи выполняет обычная кнопка формы
«Загадать желание».

Запрос «Найди кофемолку на Ozon до 4500 ₽ в „Кухню“» запускает поиск после отправки.
Можно указать Яндекс Маркет, Ozon, Wildberries, Мегамаркет, DNS или домен другого магазина.
Ассистент выбирает прямую карточку с указанной площадки по совпадению товара, наличию
и цене в заданном бюджете. Черновик содержит ссылку, название и доступные данные товара.
Если цену подтвердить не удалось, поле остаётся пустым и чат сообщает об этом.
«Проверить желание» открывает форму с выбранным списком и автоматически запускает
«Заполнить по ссылке». Данные со страницы дополняют черновик. Кнопкой можно
повторить заполнение вручную.

Пресет «Разобрать „Не отсортированные“» предлагает списки для первых десяти
активных товаров без тематического списка в порядке вишлиста. Он работает и как
обычный запрос к ассистенту. Провайдер подбора получает текст запроса,
пронумерованные названия этих товаров и до 100 названий списков. Идентификаторы,
цены, ссылки и настройки видимости остаются в Rollapp. При недоступном подборе
можно выбрать списки вручную.

«Проверить распределение» открывает панель в чате через действие
`stageSuggestions` Vercel UI SDK. Пользователь может поменять список и
снять отметку с любой строки. Правки сохраняются при переключении чатов.
«Перенести выбранные» проверяет принадлежность и актуальность всего набора,
в одной транзакции добавляет связи со списками и обновляет вишлист.
Товары без выбранного списка остаются в «Не отсортированных».
При конфликте панель сохраняет введённые значения. Новый запрос строит актуальный
предпросмотр. Если осталось больше десяти товаров, разбор можно запросить снова
после переноса.

Обычный запрос из чата передаёт выбранному провайдеру последние реплики этой
беседы и до 30 невыполненных задач и событий на семь дней, начиная с сегодняшнего
дня в местном часовом поясе. Снимок учитывает повторения и содержит названия,
даты, указанное время и длительность. Описания, ID и контакты в снимок не входят.
Клиент явно передаёт `includePlanning: true` при каждой отправке. Точный текст пресета разбора сразу запускает подбор списков без снимка планирования.
API сохраняет поддержку запросов без контекста для прежних клиентов.
Отдельных таблиц, миграции и серверного хранения переписки нет.

Текстовые сообщения до 4000 символов, переносы строк, Ctrl/Cmd+Enter для отправки.
Обновление открытого чата каждые 5 секунд, списка каждые 10 секунд.
История — страницы по 50 сообщений, новые страницы читаются последовательно,
без пропусков при большом числе новых сообщений. Список содержит непрочитанный
счётчик; read-cursor продвигается только при фокусе/видимости и прокрутке вниз.
Серверный read-cursor не может ссылаться на сообщение из другого диалога.

Черновики остаются в памяти текущего экрана при переходах между диалогами;
закрытие шторы мессенджера, перезагрузка/закрытие страницы их очищают. Ошибка отправки сохраняет текст и
client UUID: повтор после неоднозначного сетевого отказа возвращает уже
сохранённое сообщение. Изменение текста создаёт новую отправку.
Нет вложений, групповых чатов, push-уведомлений или статуса присутствия.

### Задачи из открытой заметки

Кнопка «Сделать задачи из заметки» сохраняет текущие правки и открывает чат
с запросом на разбор. В пустом чате поверх открытой заметки есть пресет
«Задачи из заметки». Сервер передаёт провайдеру текст только этой заметки,
до 18 000 символов, и локальную дату. Предпросмотр включает до восьми задач
и показывает дословные выдержки, если они нашлись в исходнике.

В панели можно поменять названия, описания и сроки и снять отметки с лишних задач.
Команда в поле «Что изменить в черновике?» передаёт провайдеру текущие строки.
UI SDK применяет только разрешённые правки к указанным строкам. Сохранение
требует нажатия «Сохранить выбранные». Оно создаёт задачи в основном To Do-листе
одной транзакцией и связывает каждую с заметкой. Повтор с тем же запросом
возвращает результат без дублей. Если заметка изменилась до сохранения,
ассистенту нужно заново подготовить задачи.

## Доступ и хранение

Сессионная авторизация и существующий CSRF-guard приложения обязательны.
Участник читает/пишет/подтверждает прочтение только собственных диалогов;
чужие и несуществующие UUID дают одинаковый 404. Поиск возвращает только
публичные id, имя, username, avatarUrl, без email/телефона/private sphere data.
Список подписок использует существующие связи `follows` текущего пользователя
и тот же набор публичных полей. Текст отображается как текст React, без
HTML/Markdown исполнения.
Поиск и отправка ограничены по пользователю. Ответы API — `Cache-Control: no-store`.

Хранение в настроенном production PostgreSQL, без fallback.
`messenger_conversations` — уникальная упорядоченная пара пользователей;
`messenger_messages` — тело, автор, глобальная последовательность, UUID попытки;
`messenger_reads` — монотонный курсор прочтения участника.
Сервер сериализует отправки в пределах диалога блокировкой его строки, чтобы
курсоры последовательности не опережали commit соседнего сообщения.

## Отдельная миграция

Схема подготовлена в `server/messenger-schema.js`; она не включена в startup.
До установки API возвращает явный 503 `MESSENGER_SCHEMA_REQUIRED`.

1. `node scripts/migrate-messenger.mjs` — read-only target/schema preflight.
2. Получить явное разрешение на создание трёх таблиц в указанной production БД.
3. `node scripts/migrate-messenger.mjs --apply --database=rollapp` — проверить
   target повторно, создать только таблицы и индексы в одной транзакции;
   lock timeout 5s, statement timeout 30s. Без backfill/cleanup пользовательских данных.
4. Повторить read-only preflight и проверку UI с production API.

`npm run test:messenger:production` проверяет реальный PostgreSQL отдельным
локальным API harness: временные участники/сообщения существуют только внутри
BEGIN → ROLLBACK, после завершения проверяется отсутствие временных пользователей.
Схема не инициализируется.

Не отправлять реальные сообщения ради проверки. Для проверки записи нужен
отдельный rollback-only тест после установки схемы. Обычный UI deployment
остаётся в `ROLLAPP_DATABASE_INITIALIZATION=verify` и не устанавливает схему.

Настройка базовой модели, IAM, ограничения и проверка: [Yandex AI](yandex-ai-setup.md).
