# Личные сообщения Rollapp

`/app/messenger` и `/app/messenger/:conversationId` открывают штору
со списком или выбранным разговором поверх домашней страницы. Кнопка над
планированием открывает ту же штору поверх текущей страницы. На компьютере
она выезжает справа, на телефоне — снизу. Список и чат показываются по очереди.
Стрелка в чате возвращает к списку. Крестик, Escape, жест и клик по фону
закрывают штору. Иконка над планированием использует общий 48px ControlBar
и промежуток 8px.

Список при открытии показывает «Ассистент Rollapp», существующие диалоги, затем все подписки,
с которыми ещё нет диалога. Контакты с диалогом представлены в списке один раз.
Поиск охватывает всех зарегистрированных участников по имени или username.
Открытие контакта создаёт диалог по требованию.

## Ассистент Rollapp

Первая строка доступна даже пока загружаются диалоги или их загрузка не удалась.
В пустом чате примеры запросов заполняют поле ввода. Пользователь может изменить
текст перед отправкой и отдельно выбрать, учитывать ли своё планирование.
Ассистент отвечает в отдельном чате. Без личного ключа используется Alice AI LLM Flash
в Yandex AI Studio, оплачиваемая Rollapp. Личные ключ и модель OpenRouter из настроек
профиля получают приоритет; ошибка личного провайдера не переключает запрос на
баланс Rollapp. Если Yandex отключён, поддерживаются прежние серверные настройки
OpenRouter. Подключённая модель должна
поддерживать вызов функций. При ошибке черновик остаётся в поле ввода.
История чата остаётся в памяти текущей вкладки после закрытия шторы и при
переходах по страницам. При перезагрузке или выходе из аккаунта история очищается.

Ассистент предлагает открыть доступные разделы Rollapp и готовит черновики задач
To Do, событий календаря и заметок. Ссылка открывает нужный экран, а черновик
заполняет обычную форму, где можно изменить поля, сохранить или отменить.
Ответ модели сам не запускает действия и не записывает данные.
При отмене черновик остаётся доступен из чата. Задача без заданной даты
открывается на текущем дне с пустым временем. В событии сохраняются предложенные
местные дата, время и длительность.

Чат отправляет выбранному провайдеру только последние реплики этой беседы. Если пользователь
включил «Учесть моё планирование», к этому запросу добавляется до 30
невыполненных задач и событий на семь дней в местном часовом поясе, с учётом
повторений. Передаются названия, даты и явное время; описания, ID, контакты и
другие личные разделы не передаются. После успешного ответа флажок сбрасывается;
реплики, созданные при включённом флажке, не переотправляются без нового согласия.
Отдельных таблиц, миграции и серверного хранения переписки нет.

Текстовые сообщения до 4000 символов, переносы строк, Ctrl/Cmd+Enter для отправки.
Обновление открытого чата каждые 5 секунд, списка каждые 10 секунд.
История — страницы по 50 сообщений, новые страницы читаются последовательно,
без пропусков при большом числе новых сообщений. Список содержит непрочитанный
счётчик; read-cursor продвигается только при фокусе/видимости и прокрутке вниз.
Серверный read-cursor не может ссылаться на сообщение из другого диалога.

Черновики остаются в памяти текущего экрана при переходах между диалогами;
закрытие шторы мессенджера, перезагрузка/закрытие страницы их очищают. Ошибка отправки сохраняет текст и
client UUID: повтор после неоднозначного сетевого отказа возвращает уже
сохранённое сообщение. Изменение текста создаёт новую отправку.
Нет вложений, групповых чатов, push-уведомлений или статуса присутствия.

## Доступ и хранение

Сессионная авторизация и существующий CSRF-guard приложения обязательны.
Участник читает/пишет/подтверждает прочтение только собственных диалогов;
чужие и несуществующие UUID дают одинаковый 404. Поиск возвращает только
публичные id, имя, username, avatarUrl, без email/телефона/private sphere data.
Список подписок использует существующие связи `follows` текущего пользователя
и тот же набор публичных полей. Текст отображается как текст React, без
HTML/Markdown исполнения.
Поиск и отправка ограничены по пользователю. Ответы API — `Cache-Control: no-store`.

Хранение в настроенном production PostgreSQL, без fallback.
`messenger_conversations` — уникальная упорядоченная пара пользователей;
`messenger_messages` — тело, автор, глобальная последовательность, UUID попытки;
`messenger_reads` — монотонный курсор прочтения участника.
Сервер сериализует отправки в пределах диалога блокировкой его строки, чтобы
курсоры последовательности не опережали commit соседнего сообщения.

## Отдельная миграция

Схема подготовлена в `server/messenger-schema.js`; она не включена в startup.
До установки API возвращает явный 503 `MESSENGER_SCHEMA_REQUIRED`.

1. `node scripts/migrate-messenger.mjs` — read-only target/schema preflight.
2. Получить явное разрешение на создание трёх таблиц в указанной production БД.
3. `node scripts/migrate-messenger.mjs --apply --database=rollapp` — проверить
   target повторно, создать только таблицы и индексы в одной транзакции;
   lock timeout 5s, statement timeout 30s. Без backfill/cleanup пользовательских данных.
4. Повторить read-only preflight и проверку UI с production API.

`npm run test:messenger:production` проверяет реальный PostgreSQL отдельным
локальным API harness: временные участники/сообщения существуют только внутри
BEGIN → ROLLBACK, после завершения проверяется отсутствие временных пользователей.
Схема не инициализируется.

Не отправлять реальные сообщения ради проверки. Для проверки записи нужен
отдельный rollback-only тест после установки схемы. Обычный UI deployment
остаётся в `ROLLAPP_DATABASE_INITIALIZATION=verify` и не устанавливает схему.

Настройка базовой модели, IAM, ограничения и проверка: [Yandex AI](yandex-ai-setup.md).
