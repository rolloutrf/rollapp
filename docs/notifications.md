# Оповещения и eve

Колокольчик находится над ассистентом в правом ряду действий. Точка на кнопке показывает, что среди последних 30 оповещений есть непрочитанные. Панель использует ту же адаптивную штору, что и мессенджер, и разделяет содержимое на три режима:

- «Входящие» — уже сработавшие напоминания и события Rollapp. Непрочитанные карточки выделены, тип события подписан, а общее действие «Прочитать всё» находится в футере вне прокрутки.
- «Активные» — будущие разовые и ежедневные расписания. Каждая строка показывает тему, полный режим повтора, дату начала и время. Добавление находится в футере этого режима. Удаление расписания не удаляет уже доставленные события из «Входящих».
- «Настройки» — автоматические источники и каналы доставки. Напоминания о препаратах и утренний обзор отделены от email/push по записям на услуги; сохранённый часовой пояс показан рядом с настройками.

Настройки, расписания и отметки о прочтении принадлежат текущему аккаунту.

- Любой пользователь может создать своё напоминание. Редактор сначала явно предлагает выбрать «Один раз» или «Каждый день», затем дату и время. Для нового расписания подставляется ближайшее будущее время; перед сохранением показывается итоговая фраза с полным расписанием. Разовое время в прошлом блокируется на клиенте и повторно проверяется сервером. Из списка можно изменить или удалить напоминание; одновременно поддерживается до 50 активных расписаний.
- Напоминания о приёме включаются в оповещениях. Rollapp использует часовой пояс браузера при первом сохранении напоминания или настройки, часы приёма активных препаратов и даты курса из раздела «Здоровье». Для еженедельной схемы день недели определяется датой начала курса. Схемы «По необходимости» и «Другая схема» не создают оповещений.
- Утренний обзор появляется в 08:00 по сохранённому часовому поясу. В обзоре за текущий день показываются до трёх задач и встреч из планирования. Ссылка открывает To Do на дату обзора.
- Оповещения доступны внутри Rollapp. Когда панель закрыта, активная вкладка обновляет значок раз в минуту и при возвращении к вкладке.
- Запись на опубликованный слот сначала создаёт запрос. Владелец получает его во входящих и может подтвердить или отклонить прямо в оповещении либо в «Календаре для бронирования». До подтверждения участник видит состояние «Запрос отправлен»; отклонение освобождает слот, а повторный ответ не меняет уже принятое решение.
- Для запросов и ответов по записи доступны три канала: внутреннее оповещение включено всегда, письмо можно отключить, browser push включается отдельно на конкретном устройстве после системного разрешения. Письмо и push открывают тот же защищённый запрос; изменение статуса выполняет только аутентифицированный владелец слота. Ответ и отмена создают отдельное оповещение участнику.
- [Карта друзей](modules/32-friend-map.md) может создать оповещение с именем взаимного друга при новом входе в радиус 1 км. Передача координат и такие оповещения включаются отдельно; гистерезис 1,2 км и направленное состояние встречи не дают повторять сообщение при каждом обновлении GPS.

Обработчик `eve/agent/schedules/notifications.ts` раз в минуту вызывает защищённый endpoint Rollapp. Запрос не содержит данных пользователя. Rollapp определяет список получателей и время в PostgreSQL. Повторные вызовы не дублируют оповещения. После короткого сбоя доставляются оповещения за текущую и четыре предыдущие минуты. Схемы приёма, названия препаратов и содержимое планирования остаются в Rollapp. Обработчик работает без вызовов модели.

Резервная копия на Яндекс Диске включает настройки каналов, свои расписания и полученные оповещения только для владельца аккаунта. Ключ доставки находится в Lockbox. Push endpoint и ключи подписки считаются учётными данными устройства, а delivery outbox, попытки, lease, ошибки провайдера и `source_id` — внутренним состоянием доставки; они исключены из архива вместе с живыми координатами и служебным состоянием proximity.

## Подключение среды

1. Запустить `node scripts/migrate-notifications.mjs`. По умолчанию это read-only проверка настроенной production-БД. Применение `--apply --database=<проверенная БД>` выполняется отдельно после явного разрешения. Миграция создаёт основные таблицы, push-подписки и delivery outbox без заполнения данных. Статусы бронирований отдельно устанавливаются `node scripts/profile-publications-schema.mjs --apply --database=<проверенная БД>`.
2. В production сохранить случайный токен длиной не менее 32 символов под ключом `notification_token` в отдельном Lockbox. Дать runtime service account право чтения этого секрета. Передать его идентификатор в переменной репозитория `YC_EVE_NOTIFICATION_LOCKBOX_SECRET_ID`. Платформа и обработчик получают значение через runtime metadata. Вне production можно передать одинаковый `ROLLAPP_EVE_NOTIFICATION_TOKEN` в окружении обоих процессов.
3. Для browser push создать VAPID-пару и сохранить в том же Lockbox значения `web_push_public_key`, `web_push_private_key` и `web_push_subject` (`mailto:` или HTTPS). После этого включить `ROLLAPP_WEB_PUSH_ENABLED=true`. Приватный ключ загружается только сервером; клиент получает только публичный ключ. Без полной конфигурации push fail-closed и переключатель недоступен, внутренние оповещения и письма продолжают работать.
4. Сервер принимает адреса доставки Web Push от Google FCM, Mozilla Push Service, Apple Push Notification service и Microsoft WNS. Для нового push-сервиса проверьте его адреса и обновите список в `notification-delivery.js`.
5. Production workflow собирает один образ с приложением и Node.js 24 для eve. Compose запускает `rollapp-eve` без опубликованных портов. Он вызывает платформу по `http://rollapp:8080`. Обычный запуск Rollapp проверяет схему в режиме `ROLLAPP_DATABASE_INITIALIZATION=verify`. При самостоятельном запуске выполнить `npm ci`, `npm run build`, `npm start -- --host 127.0.0.1` в `eve/` на Node.js 24 или новее. Допустимый `ROLLAPP_EVE_APP_ORIGIN` — HTTPS либо HTTP к `rollapp`, `localhost` или `127.0.0.1` внутри локальной сети.

Production health подтверждает точный SHA, `capabilities.notifications` и `capabilities.notificationsWorker`. Последний флаг появляется после успешного запроса eve, выполненного Rollapp в пределах трёх минут. `GET /api/notifications` без сессии возвращает `401`. Проверки интерфейса выполняются через `npm run test:notifications` на всей матрице мессенджера. [Документация расписаний eve](https://eve.dev/docs/schedules)
