# Оповещения и eve

Колокольчик находится над ассистентом в правом ряду действий. Точка на кнопке показывает, что среди последних 30 оповещений есть непрочитанные. Панель использует ту же адаптивную штору, что и мессенджер. Создание, отметка о прочтении и повтор загрузки находятся в общем футере вне прокрутки. Настройки и отметки о прочтении принадлежат текущему аккаунту.

- Любой пользователь может создать своё напоминание. Укажите тему, дату и время. Включите ежедневный повтор, если напоминание нужно с выбранной даты и дальше. Из списка можно изменить или удалить напоминание. Сохранённые оповещения остаются во входящих после удаления расписания.
- Напоминания о приёме включаются в оповещениях. Rollapp использует часовой пояс браузера при первом сохранении напоминания или настройки, часы приёма активных препаратов и даты курса из раздела «Здоровье». Для еженедельной схемы день недели определяется датой начала курса. Схемы «По необходимости» и «Другая схема» не создают оповещений.
- Утренний обзор появляется в 08:00 по сохранённому часовому поясу. В обзоре за текущий день показываются до трёх задач и встреч из планирования. Ссылка открывает To Do на дату обзора.
- Оповещения доступны внутри Rollapp. Когда панель закрыта, активная вкладка обновляет значок раз в минуту и при возвращении к вкладке.

Обработчик `eve/agent/schedules/notifications.ts` раз в минуту вызывает защищённый endpoint Rollapp. Запрос не содержит данных пользователя. Rollapp определяет список получателей и время в PostgreSQL. Повторные вызовы не дублируют оповещения. После короткого сбоя доставляются оповещения за текущую и четыре предыдущие минуты. Схемы приёма, названия препаратов и содержимое планирования остаются в Rollapp. Обработчик работает без вызовов модели.

Резервная копия на Яндекс Диске включает настройки, свои расписания и полученные оповещения только для владельца аккаунта. Ключ доставки находится в Lockbox. Внутренние даты изменения расписаний, используемые при расчёте доставки, и `source_id` для дедупликации исключены из архива.

## Подключение среды

1. Запустить `node scripts/migrate-notifications.mjs`. По умолчанию это read-only проверка настроенной production-БД. Применение `--apply --database=<проверенная БД>` выполняется отдельно после явного разрешения. Миграция создаёт `notification_preferences`, `notification_reminders` и `user_notifications` без заполнения данных.
2. В production сохранить случайный токен длиной не менее 32 символов под ключом `notification_token` в отдельном Lockbox. Дать runtime service account право чтения этого секрета. Передать его идентификатор в переменной репозитория `YC_EVE_NOTIFICATION_LOCKBOX_SECRET_ID`. Платформа и обработчик получают значение через runtime metadata. Вне production можно передать одинаковый `ROLLAPP_EVE_NOTIFICATION_TOKEN` в окружении обоих процессов.
3. Production workflow собирает один образ с приложением и Node.js 24 для eve. Compose запускает `rollapp-eve` без опубликованных портов. Он вызывает платформу по `http://rollapp:8080`. Обычный запуск Rollapp проверяет схему в режиме `ROLLAPP_DATABASE_INITIALIZATION=verify`. При самостоятельном запуске выполнить `npm ci`, `npm run build`, `npm start -- --host 127.0.0.1` в `eve/` на Node.js 24 или новее. Допустимый `ROLLAPP_EVE_APP_ORIGIN` — HTTPS либо HTTP к `rollapp`, `localhost` или `127.0.0.1` внутри локальной сети.

Production health подтверждает точный SHA, `capabilities.notifications` и `capabilities.notificationsWorker`. Последний флаг появляется после успешного запроса eve, выполненного Rollapp в пределах трёх минут. `GET /api/notifications` без сессии возвращает `401`. Проверки интерфейса выполняются через `npm run test:notifications` на всей матрице мессенджера. [Документация расписаний eve](https://eve.dev/docs/schedules)
