# Базовая модель Rollapp в Yandex Cloud

Без личного ключа OpenRouter ассистент и поиск предложений используют
**Alice AI LLM Flash** через управляемый Yandex AI Studio. Отдельная GPU VM
не нужна. Личный ключ и выбранная модель OpenRouter имеют приоритет.
При отказе OpenRouter из-за нехватки средств (код 402) поиск предложений и
чат ассистента один раз повторяют запрос через настроенную базовую модель
Yandex AI в пределах исходного таймаута. Личный ключ и модель используются
для следующих запросов. После удаления личного ключа сразу используется
базовая модель.

## Выбор модели

На 2026-11-06 Alice AI LLM Flash поддерживает контекст 64k и совместимые
Chat Completions/Responses API. Тариф: 0,10 ₽ за 1000 входящих и 0,20 ₽ за
1000 исходящих токенов, с НДС. Веб-поиск и токены инструментов оплачиваются
отдельно. Это оплата потребления облачным аккаунтом Rollapp, не бесплатная модель.

Модель выбрана для короткого русскоязычного помощника и ограниченного поиска.
Живые проверки подтвердили текстовый ответ, вызов `open_section` и поиск
прямой карточки AirPods Pro 2 USB-C. Qwen3.6 35B также нашла карточки,
но потребовала больше токенов в этом единичном сравнении. DeepSeek V4.1 Flash
в проверенном сочетании схемы и поиска не вызвала инструмент. Это небольшая
функциональная проба, не универсальный бенчмарк качества моделей.
YandexGPT Lite 5 исключена из выбора: её отключение объявлено на 2026-11-15.

## Runtime и доступ

Каталог: `b1gebpfrhvkd43r38q98`.
Сервисный аккаунт существующей VM: `ajers2ngi708sf3i1t4g`.
Ему 2026-11-06 назначены только дополнительные роли `ai.languageModels.user`
и `search-api.webSearch.user` на этом каталоге. Долгоживущий API-ключ не создан.

Compose задаёт `YANDEX_AI_MODEL=aliceai-llm-flash` и
`YANDEX_AI_AUTH=metadata`. Backend получает краткоживущий IAM-токен из
metadata service с кешированием и обновлением до истечения срока.
Локально используются тот же каталог и `YANDEX_AI_AUTH=cli`, который вызывает
существующий `yc iam create-token`. `YC_IAM_TOKEN` позволяет передать временный
токен из защищённого окружения для диагностики; не сохраняйте его в репозитории.

Пустой `YANDEX_AI_MODEL` отключает этот провайдер. Тогда сохраняется прежнее
поведение с серверным OpenRouter, если его ключ настроен. Существующие личные
ключи, секрет шифрования и схема БД не меняются.

Запросы идут напрямую на `https://ai.api.cloud.yandex.net/v1`, без OpenRouter
и его прокси. Заголовок `x-data-logging-enabled: false` отключает логирование
содержимого у провайдера; Responses-запросы используют `store: false`.
Сырые upstream-ошибки, токены и текст пользователя не попадают в логи ошибок.

## Границы запросов

Ассистент сохраняет действующие auth/CSRF, 8 запросов в минуту на пользователя,
предел контекста и отдельное согласие на снимок планирования. Максимальный
ответ — 1200 токенов, таймаут — 45 секунд. Вызовы функций создают только
валидированные кнопки/черновики и сами не меняют данные пользователя.

Поиск использует Responses API с `web_search`, режим `low`, до пяти
разрешённых доменов, `max_tool_calls: 3` и `max_output_tokens: 2000`.
В живой пробе строгая `text.format` могла подавлять поиск, поэтому JSON-схема
передаётся в инструкции, ответ проверяется локально. Принимаются только
прямые карточки из цитируемых поисковых источников после завершённого поиска.
Страницы категорий/поиска и ссылки без источника отбрасываются. Отсутствующая
цена остаётся `null`; поисковый индекс не гарантирует актуальность наличия
или цены. Прямые каталоги магазинов остаются дополнительным источником.

Ограничения длины, таймаута и числа инструментов ограничивают один запрос,
но не задают месячный лимит бюджета и не заменяют контроль расходов в Billing.

## Проверка и выпуск

`node --test server/yandex-ai.test.js server/messenger-assistant.test.js`
проверяет приоритеты, переход на Yandex AI при коде 402, обработку других
ошибок провайдера, обновление IAM, отмену и фильтрацию источников без БД.
`npm run test:messenger` и `npm run test:profile` проверяют затронутые поверхности.
Полный выпуск проходит существующий `check:release`; общий аудит —
`check:comprehensive`. Production startup сохраняет read-only `verify`,
никаких миграций для этой интеграции нет.

`/api/healthz` сообщает `capabilities.defaultAiProvider: "yandex"` и
`marketplaceAi: true`, если конфигурация включена. Это не проверка доступности
upstream: дополнительно нужен реальный ответ с runtime-идентичностью и точный
SHA выпущенного образа. Выпуск завершён только после этих проверок и UI review.
