## Изменения

- Главная страница бизнеса показывает витрину вместо личных списков и желания.
  Владелец продавца получает ссылки «Управлять товарами» и «Клиенты».
- Реальный Safari показал, что на скриншоте открыт также `/app/wishes`. Добавлен
  переход бизнеса с обычного домашнего экрана на собственную витрину с сохранением
  выбранного пространства; этот путь включён во все восемь размеров smoke.
- Публичная витрина использует опубликованные товары конкретного seller-аккаунта
  в конкретном пространстве; новый гостевой GET не открывает управляющие API.
- Существующие предложения за роллы сохранены. Второе пустое состояние скрыто,
  если уже показан пустой каталог продавца; ошибки и незавершённые оплаты остаются.
- PageActionButton принимает `to`: нативная ссылка с теми же 48px/24px/pill
  контрактами вместо ссылки, объявленной кнопкой.
- В бизнес-регистрационном smoke исправлена гонка: Home/Enter отправляются после
  передачи настоящего фокуса опции меню, а не сразу после появления DOM.

## Production-данные и схема

Пользователь отдельно подтвердил «Продавец → Товары». В настроенной PostgreSQL
`rollapp` / `rollapp_app` через прямой TLS и штатную загрузку Lockbox проверена
точная запись `fintehnika-rf` / «ФИНТЕХНИКА РФ». UPDATE с проверками id, username,
business account_type и прежних NULL изменил только business_category на seller
и seller_space на products, ровно одну строку. COMMIT успешен; публичный API
подтвердил оба поля. Блокировки ограничены 5s, выполнение запросов 10s.

Реальная initializeRuntimeDatabase в режиме verify прошла существующую схему
в READ ONLY транзакции, включая reserved-username guard. Миграции/инициализация,
backfill, очистка разрешений и публикация товаров не выполнялись.

Новый публичный GET отдельно проверен с production-запросами в READ ONLY:
HTTP 200, опубликованных страниц и товаров для этого продавца — 0.
Восемь размеров реального UI с production-данными проверены локально через
read-only обработчик нового GET и production API: 320×844, 390×844, 768×900,
820×450, 1024×900, 1440×900, 1920×900, 390×400. Горизонтального root overflow
и ошибок JS нет; личного пустого вишлиста нет. Просмотрены mobile и desktop PNG
`/tmp/rollapp-business-live-*.png`. Тестовые данные не сохранялись.

Постоянный dev-сервис основной рабочей копии проверен командой
`npm run dev:keepalive:status`: включён, API/frontend готовы. Он не останавливался.
