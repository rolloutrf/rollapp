# Storybook РОЛЛАПП

Из корня проекта запустите `npm ci`, затем `npm run storybook`. Каталог откроется по адресу [127.0.0.1:6006](http://127.0.0.1:6006/). В папке «Модули» и на странице каталога все модули идут в порядке [карты модулей](modules/README.md).

Storybook использует карту модулей РОЛЛАПП и истории из `storybook/stories/`. Общие компоненты находятся внутри модуля «Оболочка приложения». Конфигурация находится в `storybook/.storybook/`.

- В боковом меню выбирайте отдельный сценарий. В панели **Controls** меняйте аргументы, которые поддерживает текущая история.
- В верхней панели выбирайте светлую и тёмную темы и восемь размеров от 320 до 1920 px. Размер 390 × 400 помогает посмотреть формы и шторы в низком окне.
- Ссылки «В приложении» открывают рабочий РОЛЛАПП с его обычной сессией и production API. OAuth, интеграции платёжных провайдеров, файловые хранилища и календарь устройства требуют отдельной проверки в приложении.

Карточки, поля, формы и меню используют компоненты приложения и общую типографику, shadcn, `ControlBar` и `WishlistSnippet`. В историях можно проверять загрузку, пустые списки, ошибки, доступ владельца и гостя, редактирование, откат и повтор. PFM содержит действующий экран сводки по роллам.

## Добавление истории

Используйте ближайший файл в `storybook/stories/` и точки входа из инструкции модуля. Дайте истории имя по наблюдаемому состоянию или действию. Поставляйте данные через props, а когда компонент владеет чтением, передавайте конкретные операции UI-стенду `Scenario`. Он разрешает только определённые в истории операции с данными примера и восстанавливает транспорт после закрытия. Storybook работает на loopback без прокси к API. Рабочее подключение Rollapp к production PostgreSQL обслуживает существующий keepalive.

## Проверка

- `npm run test:storybook:a11y` проверяет все истории в светлом настольном и тёмном мобильном режимах через axe-core. Переменная `ROLLAPP_A11Y_REPORT` задаёт путь к JSON с нарушениями и случаями для ручной оценки.
- `npm run test:storybook` сверяет разделы и ссылки в каталоге с картой модулей РОЛЛАПП, открывает каждую историю на восьми размерах, проверяет светлую тему в каждом модуле и выполняет ключевые действия пользователя.
- `npm run build-storybook` собирает автономное превью в `storybook-static/`. Для проверки этой папки укажите её HTTP-адрес в `ROLLAPP_STORYBOOK_URL`.
- `ROLLAPP_STORYBOOK_SCREENSHOTS=/absolute/path npm run test:storybook` сохраняет скриншоты адаптивных сценариев и ошибок.

## Публикация

[Публичный Storybook](https://сторибук.роллапп.рф/) обслуживает отдельный бакет Yandex Object Storage `xn--90anhnkehm.xn--80avakiab.xn--p1ai` в каталоге `b1gebpfrhvkd43r38q98`. DNS-запись поддомена указывает на сайт бакета. Certificate Manager продлевает TLS-сертификат через отдельную запись `_acme-challenge`.

GitHub Actions запускает [Verify Rollapp Storybook](https://github.com/rolloutrf/rollapp/actions/workflows/storybook-ci.yml) на каждом push. Проверка shadcn, браузерная матрица и axe выполняются для того же статического каталога, который CI сохраняет как `storybook-release-<SHA>`. Журналы, снимки и JSON с результатами axe сохраняются как `storybook-report-<SHA>`.

После успешной проверки скачайте артефакт `storybook-release-<SHA>` из этого запуска GitHub Actions. Из рабочего дерева с тем же коммитом выполните:

```sh
AWS_PROFILE=yandex node scripts/storybook-release.mjs publish /path/to/artifact <SHA>
```

Скрипт сверяет SHA и хеши файлов артефакта, сначала публикует ресурсы, затем входные файлы с `Cache-Control: no-cache`. Старые объекты остаются доступны вкладкам, открытым до публикации. Команда проверяет хеши публичных входных файлов. Следом запустите браузерный smoke на публичном HTTPS. В артефакт не входят карты исходников, архив расширения, манифесты кошельков и скрытые файлы.


`npm run test:storybook:a11y` проверяет каждую историю в светлой настольной и тёмной мобильной теме через axe-core (WCAG 2 A/AA и 2.1 A/AA). `ROLLAPP_A11Y_REPORT=/absolute/path.json` сохраняет нарушения и случаи для ручной проверки. Используйте `ROLLAPP_STORYBOOK_URL` для собранной версии. Проверка отклоняет запросы к API и ошибки циклического рендера; она дополняет полную восьмиразмерную матрицу, клавиатурные и визуальные проверки.

Проверки Storybook используют общий `scripts/storybook-readiness.mjs`: наличие оболочки не заменяет готовность лениво загружаемого редактора. Для историй документов, «Четырёх вопросов» и соответствующих разделов карьеры дождитесь реального `.ProseMirror`/содержимого, исчезновения статуса загрузки и шрифтов до измерений, снимка и axe. Это относится и к проверке публичной публикации.

Готовность включает фактический продуктовый CSS и Geist. `document.fonts.ready` может разрешиться до появления асинхронной таблицы стилей; не считайте такое состояние проверенным интерфейсом.
