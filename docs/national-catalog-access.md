# Доступ Rollapp к Национальному каталогу РФ

## Текущее решение — 6 ноября 2026

После выбора бесплатного варианта и команды «продолжай» реализованы подсказки
Wikidata в желаниях и объявлениях. Контракт и ограничения:
[product-suggestions.md](product-suggestions.md). Это международный справочник
известных моделей, не федеральная база всех товаров РФ. Исторические выводы
ниже описывают поиск федерального API, доступ к которому по-прежнему не получен.


## Последние требования пользователя

Пользователь запретил отправлять обращение оператору, попросил найти открытые
источники и затем уточнил способ подключения: базу не скачивать, отправлять
поисковые запросы источникам во время ввода. Эти требования заменяют ранее
предложенный план выгрузки/индексирования. Черновик письма ниже — только
история исследования, не поручение на отправку. Нельзя подменять внешний
поиск внутренним каталогом или скачанным набором данных.

Предполагаемый поток после подтверждения подходящего API: поле названия
в обеих формах → сервер Rollapp → внешний поиск → подсказки. Нужны задержка
после ввода, отмена/игнорирование устаревших ответов, лимиты запросов,
обработка недоступности; поиск не сохраняет и не публикует форму.

Повторная проверка источников 6 ноября 2026:

- [Open Food Facts API](https://openfoodfacts.github.io/openfoodfacts-server/api/)
  прямо просит не использовать `/api/v*/search` и `/cgi/search.pl` для
  search-as-you-type; лимит поиска 10 запросов/минуту/IP. Не подключать их
  к автоматическому вводу, рассчитывая только на debounce.
- [Icecat Product JSON](https://iceclog.com/manual-for-icecat-json-product-requests/)
  получает одну карточку по Icecat ID, GTIN или бренду и артикулу. Это
  не подтверждённый API подсказок по произвольной части названия. Рекомендация
  Icecat как готового источника автоподсказок была преждевременной.
- [Search-a-licious](https://openfoodfacts.github.io/search-a-licious/users/ref-openapi/)
  документирует текстовый поиск, но документация развёртываемого движка
  не подтверждает доступный для Rollapp общетоварный сервис с охватом РФ
  и подходящими условиями для запросов при вводе. Не выдавать поддержку
  движком поиска за проверенное подключение всех товарных категорий.

На этом этапе исследования подтверждённого внешнего API со всем охватом РФ
не было. Позднее реализован ограниченный бесплатный поиск Wikidata,
описанный в разделе «Текущее решение» выше.

## Исследование федерального источника

Федеральный источник на 6 ноября 2026: доступ не предоставлен;
интеграция именно с Национальным каталогом не реализована.
Пользователь подтвердил, что доступа к API пока нет, и уточнил, что нужен
именно федеральный источник, а не поиск по внутреннему каталогу Rollapp.
Пользователь также сообщил, что ИП/ООО и УКЭП у него нет. Возможность
подключения разработчика без них требует ответа оператора; стандартный
путь получения ключа через кабинет с УКЭП сейчас неприменим.

## Требуемый результат

В форме продажи товара Rollapp и при добавлении желания ввод названия должен
возвращать реальные подходящие товары из общероссийского источника.
Наличие внутреннего каталога, API-адаптера без доступа или тестовых подсказок
не означает выполнения задачи. Требование охвата всех товаров РФ остаётся
неподтверждённым и не должно заменяться обещанием полноты отдельного каталога.

Точки интеграции в ветке `codex/product-catalog-suggestions`:

- `src/components/wishlist-business-item-editor.jsx`: форма продажи,
  поле `title` (основа — ветка `codex/product-listing-editor`).
- `src/App.jsx`: `WishModal`, поле названия желания.
- Общий серверный поиск и общий компонент подсказок для обеих форм.

## Что подтверждено первоисточниками

1. Национальный каталог входит в систему «Честный знак»; оператор — ЦРПТ.
   Описание проекта формулирует полноту охвата как цель, а не проверенную
   гарантию наличия каждой модели товара в текущей базе.
   Источник: [О проекте](https://национальный-каталог.рф/page/about).
2. Официальная инструкция получения ключа указывает вход с УКЭП в продуктивный
   личный кабинет, далее «Национальный каталог → Профиль → Данные участника».
   Ключ виден руководителю организации или администратору. Актуальная
   документация API находится в личном кабинете: товарная группа → Помощь →
   API → API Национального каталога.
   Источник: [Получение API Key](https://markirovka.ru/knowledge/tovarnye-gruppy/obschie-voprosy-gis/kak-poluchit-party-id-api-key-klyuch-dostupa-v-natsionalnom-kataloge).
3. Инструкция экспорта описывает сведения о товарах участника, фильтры и
   опубликованные карточки. Она не подтверждает возможность скачать всю
   общероссийскую базу для стороннего приложения. Указанный в ней предел
   5000 карточек относится к описанному экспорту, а не к лимитам поискового API.
   Источник: [Экспорт карточек](https://markirovka.ru/knowledge/tovarnye-gruppy/obschie-voprosy-gis/kak-massovo-vygruzit-kartochki-s-natsionalnogo-kataloga).
4. На сайте каталога опубликованы контакты `support@national-catalog.ru`,
   `info@national-catalog.ru`, 8-800-777-7709.
   Источник: [Контакты проекта](https://национальный-каталог.рф/page/about).

Открыть корень публичного API `https://апи.национальный-каталог.рф/` через
web-инструмент не удалось. Это ограничение проверки, а не доказательство
отключённого API или обязательной авторизации на странице документации.

## Что требуется подтвердить у оператора

- Как подключить Rollapp как сервис объявлений и желаний; допустим ли доступ
  без статуса участника оборота маркированных товаров.
- Доступно ли чтение каталога других производителей и всех нужных категорий,
  а не только карточек организации, которой принадлежит ключ.
- Есть ли поиск по части названия, бренду, модели и GTIN, его актуальная
  спецификация, ограничения и примеры ответов.
- Можно ли показывать названия, характеристики и изображения пользователям
  Rollapp; каковы условия кеширования и построения собственного поискового
  индекса на данных этого источника.
- Реальный охват категорий, частота обновления, тарифы и лимиты запросов.
- Если прямых подсказок нет — предоставляется ли разрешённая полная выгрузка
  с обновлениями, на основе которой можно построить поиск.

Обычный API Key сам по себе не доказывает эти возможности. Не реализовывать
клиент по устаревшей или сторонней спецификации как будто доступ подтверждён.

## Условия возобновления реализации и приёмки

Нужны оформленный доступ, подтверждённый охват и актуальная документация
оператора. Секрет хранить на сервере через существующий механизм секретов;
не включать его в клиентский код, журнал или отслеживаемые файлы.

После подключения проверить реальные ответы на запросы по согласованным
категориям, затем обе формы: ввод, выбор мышью/касанием/клавиатурой,
задержавшиеся ответы, отсутствие результатов и ошибку источника. Выбор
подсказки не публикует объявление и не сохраняет желание сам по себе.
Проверить мобильные и настольные размеры по `AGENTS.md`, регламент
`docs/verification.md` и реальный production API без сохранения тестовых данных.
Изменение схемы и массовый импорт в production требуют отдельного разрешения.
